## 問題描述

**發現位置**：`Strategy.json` (v2.6) 與 `signalGenerator.mjs`
**問題摘要**：系統在強勢多頭市場的回檔中建倉過於遲鈍，導致錯失底部加碼機會。
**詳細描述**：
目前的計分矩陣（Scoring Matrix）要求 4.0 分才啟動戰術加碼，且進場閘門（Entry Gate）嚴格要求 RSI 必須低於特定閾值。在多頭市場中，回檔通常較淺（5-8%）且 RSI 不易跌破 50，導致評分難以達標。這導致使用者在 0050 底倉持續投入的同時，00675L 的戰術槓桿卻因「等待技術面確認」而完全踏空，降低了整體的資金效率。

## 根因分析

| 根因層級 | 代碼   | 分析說明                                                                         |
| -------- | ------ | -------------------------------------------------------------------------------- |
| 需求層   | `REQ`  | 原有需求過於強調「防禦」，忽略了多頭市場中「時間分散性」優於「技術擇時」的特性。 |
| 開發層   | `DEV`  | 評分邏輯為靜態門檻（固定 4 分），未根據長期趨勢（MA60 斜率）進行動態調整。       |
| 架構層   | `ARCH` | `entryGate` 具有一票否決權，在多頭環境下形成了過度的「右側交易」濾網。           |

## 建議修改對象與內容

### 1. 修改 Strategy.json (v3.0 升級)

**目標位置**：`scoringMatrix` 與 `buy` 章節
**建議內容**：

- **新增多頭門檻**：`thresholds.buyTacticalBullish: 3.0` (原 4.0)。
- **優化進場閘門**：在 `entryGate` 中加入 `bullMarketRelaxation: true`，定義當 MA60 斜率 > 0 時，10% 以內的跌幅不檢核 RSI。
- **調整跌幅權重**：調整 `priceDrop` 的映射係數，讓 5-10% 的回檔能獲得更高的基礎分數（前端加權）。

### 2. 修改 signalGenerator.mjs 邏輯

**修改位置**：`generateScoringMatrix` 函數
**建議內容**：

- 引入 `extraData.ma60Slope` 判定。
- 若 `ma60Slope > 0` 且 `PB PR < 90`，則將判定門檻切換為 `buyTacticalBullish`。
- **導入安全熔斷**：明確定義若 `PB PR >= 90`，則不論趨勢如何，一律維持最高門檻（4.0）或甚至暫停戰術加碼。

## 預期效果

1. **提升建倉敏感度**：在 5-10% 的多頭小回檔中，00675L 能夠更及時地介入，降低整體持有成本。
2. **兼顧安全性**：透過「高估值熔斷器」，在市場真正過熱時保持冷靜，避免在泡沫頂端瘋狂加槓桿。
3. **符合 LCI 精神**：讓戰術部位在「大部分時間」都更積極地參與市場，減少閒置資金的成本損失。
