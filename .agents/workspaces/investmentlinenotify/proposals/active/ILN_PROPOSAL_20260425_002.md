## 問題描述

**發現位置**：`src/modules/providers/marketData.mjs` — `fetchAllMacroData()` 函式

**問題摘要**：`rawFx`（匯率）每次必定發出 API 請求且無快取保護；其他 7 個 slot 的 STALE 資料在 Provider 失敗時靜默回退，但沒有任何「資料新鮮度標注」傳遞給下游 AI Coach，導致過期資料影響決策時無法被識別。

**詳細描述**：

### 問題一：`rawFx` 無快取保護（P5-4）

所有其他 slot（rawNdc、rawMargin、rawCnn 等）都實作了「先讀快取、條件觸發重抓」的邏輯，唯獨 `rawFx`（Yahoo Finance 匯率）無條件每次執行都發出 API 請求：

```js
// marketData.mjs — 判斷邏輯 F（第 167–185 行）
// rawFx：無任何快取條件判斷，每次 fetchAllMacroData() 都直接 push 到 fetchPromises
const fxProvider = getProviderForSlot("rawFx");
fetchPromises.push(
  fxProvider.fetch().then(...).catch((err) => {
    console.warn("⚠️ Yahoo API 失敗:", err.message);
    finalData.rawFx = cachedData.rawFx || null;  // ← 失敗才讀快取，但快取可能已過期幾天
  }),
);
```

Yahoo Finance 的非官方 API 端點穩定性較差，若每次 dailyCheck 都是單點 HTTP 請求，任何一次失敗都只能 fallback 到上次成功的快取，但「上次成功是幾天前」這個資訊完全沒有被記錄或傳遞。

---

### 問題二：7 個 slot 的 STALE 資料靜默影響決策

所有 slot 失敗時的 fallback 模式一致：

```js
// 以 rawCnn 為例（第 113–122 行）
.catch((err) => {
  console.warn("⚠️ CNN API 失敗:", err.message);
  finalData.rawCnn = cachedData.rawCnn || null;   // ← 直接回傳舊資料
  newMetaSources[cnnProviderKey] = {
    status: "FAILED",
    error: err.message,
    lastFetch: cachedMeta[cnnProviderKey]?.lastFetch || null,  // ← 舊的 lastFetch
  };
}),
```

`newMetaSources` 中有 `status: "FAILED"` 與 `lastFetch`，但：

1. 這些 metadata **只存在 `_meta.sources` 中**，不會被附加到 `finalData` 的各個 slot 資料物件上
2. `aiDataPreprocessor.mjs` 和 AI Coach 收到的是純 `finalData`，**完全看不到任何 slot 的新鮮度資訊**
3. AI Coach 在生成建議時，若 VIX 數據已是 3 天前的快取，它不會知道，仍會引用該數據做出「基於今日 VIX 58 的判斷」

---

### 問題三：`Promise.allSettled` 後沒有整體失敗評估

所有 API 請求透過 `Promise.allSettled(fetchPromises)` 並行執行，但執行後沒有任何邏輯統計「本次有幾個 slot 失敗」、「關鍵 slot 是否失敗」：

```js
// marketData.mjs 第 227 行
await Promise.allSettled(fetchPromises);
// ← 此後直接進入「存回 Cache」，無任何失敗統計或告警
```

若當天 rawValuation（PE/PB）、rawMargin（融資餘額）、rawUsMarket（FRED）三個關鍵 slot 同時失敗，系統仍會繼續執行，將 3 天前的資料送進 AI Coach，最終送出一則「看起來正常」但資料已嚴重過期的 LINE 通知。

### 建議修改一：為 `rawFx` 補上快取條件（對齊其他 slot 的模式）

```js
// 判斷邏輯 F — 修改後：rawFx 補上「30 分鐘內不重抓」的快取保護
const fxProviderKey = macroDataSlots.rawFx.providerId;
const fxLastTime = new Date(cachedMeta[fxProviderKey]?.lastFetch || 0);
const minutesSinceFxUpdate = (now - fxLastTime) / (1000 * 60);

// 30 分鐘內有成功抓取紀錄 → 使用快取（匯率日內變動幅度通常可接受）
if (cachedData.rawFx && minutesSinceFxUpdate < 30) {
  console.log("⚡ [Cache] 匯率使用快取資料（距上次更新 < 30 分鐘）");
  finalData.rawFx = cachedData.rawFx;
} else {
  const fxProvider = getProviderForSlot("rawFx");
  fetchPromises.push(
    fxProvider
      .fetch()
      .then((res) => {
        finalData.rawFx = res;
        newMetaSources[fxProviderKey] = {
          status: "SUCCESS",
          lastFetch: now.toISOString(),
        };
      })
      .catch((err) => {
        console.warn("⚠️ Yahoo API 失敗:", err.message);
        // 失敗時才讀快取，並附帶 STALE 標記
        finalData.rawFx = cachedData.rawFx || null;
        newMetaSources[fxProviderKey] = {
          status: "FAILED",
          error: err.message,
          lastFetch: cachedMeta[fxProviderKey]?.lastFetch || null,
        };
      }),
  );
}
```

### 建議修改二：`Promise.allSettled` 後補充失敗評估與關鍵 slot 告警

```js
// ── 定義 slot 重要性分級 ──────────────────────────────────────────────────────
// CRITICAL：此 slot 失敗且快取超過 STALE 容忍度時，應發出 LINE 系統告警
// IMPORTANT：失敗時記錄 warn log，但不中斷流程
const SLOT_CRITICALITY = {
  rawValuation: { level: "CRITICAL", staleHours: 48 }, // PE/PB：超過 2 天視為 STALE
  rawMargin: { level: "CRITICAL", staleHours: 48 }, // 融資餘額：超過 2 天
  rawUsMarket: { level: "CRITICAL", staleHours: 48 }, // FRED：超過 2 天
  rawFx: { level: "IMPORTANT", staleHours: 4 }, // 匯率：超過 4 小時
  rawCnn: { level: "IMPORTANT", staleHours: 24 }, // CNN 恐慌：超過 1 天
  rawMarketOverview: { level: "IMPORTANT", staleHours: 48 }, // 大盤量價：超過 2 天
  rawInstitutional: { level: "IMPORTANT", staleHours: 48 }, // 法人籌碼：超過 2 天
  rawStockMargin: { level: "IMPORTANT", staleHours: 48 }, // 個股融資：超過 2 天
  rawNdc: { level: "LOW", staleHours: 720 }, // 景氣燈號：超過 30 天
  rawBankRate: { level: "LOW", staleHours: 720 }, // 利率：超過 30 天
  rawCpi: { level: "LOW", staleHours: 720 }, // CPI：超過 30 天
};

// ── Promise.allSettled 後：失敗評估 ─────────────────────────────────────────
await Promise.allSettled(fetchPromises);

const staleSlots = [];
const criticalStaleSlots = [];

for (const [slotKey, cfg] of Object.entries(SLOT_CRITICALITY)) {
  const meta = newMetaSources[macroDataSlots[slotKey]?.providerId];
  if (!meta || meta.status === "SUCCESS") continue;

  // 計算快取資料的新鮮度
  const lastFetch = new Date(meta.lastFetch || 0);
  const hoursStale = (now - lastFetch) / (1000 * 60 * 60);

  if (hoursStale > cfg.staleHours) {
    const staleInfo = {
      slot: slotKey,
      hoursStale: hoursStale.toFixed(1),
      threshold: cfg.staleHours,
    };
    staleSlots.push(staleInfo);
    if (cfg.level === "CRITICAL") criticalStaleSlots.push(staleInfo);
  }
}

// CRITICAL STALE → 發出 LINE 系統告警（實作細節由 lineNotifier 負責）
if (criticalStaleSlots.length > 0) {
  const alertMsg = criticalStaleSlots
    .map((s) => `${s.slot}（${s.hoursStale}h 前，門檻 ${s.threshold}h）`)
    .join("、");
  console.error(`❌ [DataFreshness] CRITICAL STALE slots：${alertMsg}`);
  // TODO: 呼叫 lineNotifier 發送系統告警
  // await notifySystem(`⚠️ [系統] 關鍵資料已過期：${alertMsg}，本日分析可能不準確。`);
}
```

### 建議修改三：`finalData` 各 slot 附加 `_stale` 標記供下游識別

```js
// 在 return finalData 前，為每個 slot 附加新鮮度標記
// 使下游（aiDataPreprocessor、AI Coach）可識別資料是否過期
for (const [slotKey, cfg] of Object.entries(SLOT_CRITICALITY)) {
  if (!finalData[slotKey]) continue;
  const meta = newMetaSources[macroDataSlots[slotKey]?.providerId];
  const lastFetch = new Date(meta?.lastFetch || 0);
  const hoursStale = (now - lastFetch) / (1000 * 60 * 60);

  // 只有當資料超過容忍度時才標注，避免污染正常資料
  if (meta?.status !== "SUCCESS" && hoursStale > cfg.staleHours) {
    finalData[slotKey]._stale = {
      hoursOld: Math.round(hoursStale),
      lastFetch: meta?.lastFetch || null,
    };
  }
}

return finalData;
```

### 建議修改四：`docs/modules/providers.md` 補充 Slot 分級規範

```markdown
## Provider Slot 分級與 Staleness Policy

### Slot 重要性分級

| Slot                | 分級      | STALE 容忍度      | 說明                                              |
| ------------------- | --------- | ----------------- | ------------------------------------------------- |
| `rawValuation`      | CRITICAL  | 48 小時           | PE/PB 是核心估值錨點，過期直接影響加減碼判斷      |
| `rawMargin`         | CRITICAL  | 48 小時           | 融資餘額反映市場槓桿，過期影響風險評估            |
| `rawUsMarket`       | CRITICAL  | 48 小時           | FRED 數據影響宏觀分析基礎                         |
| `rawFx`             | IMPORTANT | 4 小時            | 匯率日內可接受 30 分鐘快取；超過 4 小時視為 STALE |
| `rawCnn`            | IMPORTANT | 24 小時           | 盤後讀取，1 天容忍度合理                          |
| `rawMarketOverview` | IMPORTANT | 48 小時           | 收盤後更新，2 天容忍度合理                        |
| `rawInstitutional`  | IMPORTANT | 48 小時           | 法人籌碼，收盤後更新                              |
| `rawStockMargin`    | IMPORTANT | 48 小時           | 個股融資，收盤後更新                              |
| `rawNdc`            | LOW       | 720 小時（30 天） | 月更資料，長期快取合理                            |
| `rawBankRate`       | LOW       | 720 小時          | 低頻指標                                          |
| `rawCpi`            | LOW       | 720 小時          | 低頻指標                                          |

### 規則

1. **CRITICAL slot 超過 STALE 容忍度時，必須觸發 LINE 系統告警**，通知使用者本日分析品質可能降低。
2. **所有 slot 失敗時必須讀快取，同時在 `_stale` 欄位標注資料年齡**，使下游 AI 可在 prompt 中知悉資料新鮮度。
3. **`rawFx` 快取更新頻率為 30 分鐘**（非每次 dailyCheck 都重抓），對齊其他 slot 的快取優先策略。
4. **新增 provider slot 時，必須在 `SLOT_CRITICALITY` 中同步登記分級與 STALE 容忍度**，否則 PR review 不得通過。
```

## 預期效果

套用此提案後：

1. **消除 `rawFx` 單點故障風險**：30 分鐘快取保護讓 Yahoo Finance 短暫不穩定時不影響每次執行，失敗時有明確的快取回退。
2. **STALE 資料不再靜默影響決策**：`_stale` 標記讓 AI Coach 在 prompt 中知悉資料年齡，可在輸出的 `key_risks` 中主動提示「部分資料可能過期」。
3. **CRITICAL slot 過期可見**：LINE 系統告警讓使用者在收到投資建議前先知道資料品質問題，避免基於過期 PE/PB 做出錯誤決策。
4. **可維護性提升**：`SLOT_CRITICALITY` 字典集中管理所有 slot 的分級與容忍度，新增 slot 時有明確的文件規範要求同步登記。
