## 問題描述

**發現位置**：`src/modules/ai/aiClient.mjs` — `resolveChatPrompt()` 函式（第 164–215 行）

**問題摘要**：Langfuse 無法連線時，`systemInstruction` 與 `userTemplate` 均退化為空字串，AI 在無任何指令的情況下裸跑。

**詳細描述**：

`resolveChatPrompt()` 函式負責從 Langfuse 拉取 chat prompt（system + user messages）。當 Langfuse 連線失敗（網路逾時、服務中斷、密鑰失效），catch 區塊僅印出一行 warn log，並回傳：

```js
// 實際行為（Langfuse 斷線時）
{
  systemInstruction: "",   // 空字串
  userTemplate: "",        // 空字串
  langfusePromptObj: null,
  langfuseConfig: {}
}
```

`callAI()` 收到此結果後，直接以空字串呼叫 AI API：

```js
// aiClient.mjs 第 284–285 行
contents: [{ role: "user", parts: [{ text: userTemplate }] }],   // ""
config: { systemInstruction, ... }                                // ""
```

這代表：
- **AI 沒有任何角色定義**（無 system prompt）
- **AI 沒有收到任何市場資料**（無 user prompt）
- AI 仍會回傳一個看似合理的 JSON，**通過 Schema Validation**，但內容毫無根據
- Langfuse trace 的 `promptSource` 欄位雖然會標記為 `"code-fallback"`，但下游模組（aiCoach、periodReportAgent 等）不讀取此欄位，**不會中斷流程**
- 使用者最終收到的 LINE 通知是「AI 裸跑」的輸出，**無法識別與正常輸出的差異**

## 根因分析

| 根因層級 | 代碼 | 分析說明 |
|---------|------|---------|
| 架構設計 | `ARCH` | `resolveChatPrompt()` 設計為「最優努力（best-effort）」取回，將空字串視為合法 fallback，但未區分「降級可接受」與「必須中斷」兩種情境 |
| 開發實作 | `DEV` | `callAI()` 收到 `systemInstruction = ""` 時沒有防衛性檢查，直接透傳至 AI API；`promptSource: "code-fallback"` 僅作為觀測標記，未接入任何阻斷或告警邏輯 |
| 需求定義 | `REQ` | 現行規則文件（`agent_prompts.md` 與 `architecture.md`）均未明確定義 Langfuse 不可用時的 Degradation Policy，導致實作端沒有對應的規格可依循 |

### 建議修改一：`resolveChatPrompt()` catch 區塊補充 hardcoded fallback

```js
// ── 各 prompt 的 hardcoded fallback（Langfuse 斷線時使用）
// 僅包含最基礎的角色定義，確保 AI 不裸跑
// 注意：fallback prompt 不含市場資料插值，AI 輸出品質會明顯降低
// callAI() 會透過 promptSource 標記此狀態，下游可依此決定是否採用輸出
const PROMPT_HARDCODED_FALLBACK = {
  InvestmentAdvice: {
    system: "你是一位穩健的台股投資教練，請根據使用者提供的市場資訊，給出具體可執行的投資建議，以 JSON 格式回覆。",
    user: "{{userPromptData}}",
  },
  FilterAndCategorizeNews: {
    system: "你是一位金融新聞分析師，請篩選並分類以下新聞，以 JSON 格式回覆。",
    user: "{{newsItems}}",
  },
  AnalyzeMacroNews: {
    system: "你是一位總經分析師，請分析以下新聞對市場的影響，以 JSON 格式回覆。",
    user: "{{newsAnalysisData}}",
  },
  GenerateSearchQueries: {
    system: "你是一位金融研究員，請根據主題生成搜尋關鍵字，以 JSON 格式回覆。",
    user: "{{topic}}",
  },
};

async function resolveChatPrompt(promptName, variables = {}) {
  let langfusePromptObj = null;
  let systemInstruction = "";
  let userTemplate = "";
  let langfuseConfig = {};
  let promptSource = "langfuse"; // 追蹤來源

  try {
    langfusePromptObj = await langfuse.getPrompt(promptName, undefined, {
      type: "chat",
    });
    // ... 現有解析邏輯不變 ...
  } catch (err) {
    console.warn(
      `⚠️ [Langfuse] getPrompt(${promptName}, chat) 失敗，嘗試 hardcoded fallback：${err.message}`,
    );

    // ── 新增：hardcoded fallback 補充 ──
    const promptKey = promptName.split("/").pop();
    const fallback = PROMPT_HARDCODED_FALLBACK[promptKey];

    if (fallback) {
      systemInstruction = fallback.system;
      // 對 user template 進行簡易插值（支援最基本的 {{key}} 替換）
      userTemplate = Object.entries(variables).reduce(
        (tmpl, [k, v]) => tmpl.replace(new RegExp(`{{${k}}}`, "g"), String(v ?? "")),
        fallback.user,
      );
      promptSource = "hardcoded-fallback";
      console.warn(
        `⚠️ [Langfuse] 使用 hardcoded fallback prompt for: ${promptKey}（輸出品質可能降低）`,
      );
    } else {
      // 完全沒有 fallback → 設 promptSource 為 "missing"，讓 callAI 阻斷
      promptSource = "missing";
      console.error(
        `❌ [Langfuse] 無可用 prompt for: ${promptName}，callAI 將阻斷本次呼叫。`,
      );
    }
  }

  return { systemInstruction, userTemplate, langfusePromptObj, langfuseConfig, promptSource };
}
```

### 建議修改二：`callAI()` Step 1 後補充防衛檢查

```js
// ── Step 1: 從 Langfuse 取得 chat prompt ─────────────────────────────────
const { systemInstruction, userTemplate, langfusePromptObj, langfuseConfig, promptSource } =
  await resolveChatPrompt(promptName, options.promptVariables ?? {});

// ── Step 1.5: Degradation Policy 防衛檢查 ────────────────────────────────
// promptSource = "missing" 表示 Langfuse 斷線且無 hardcoded fallback
// 此情況下 AI 會裸跑，直接拋錯阻斷，避免產出無意義通知
if (promptSource === "missing") {
  const degradationErr = new Error(
    `[callAI] Prompt 不可用（Langfuse 斷線且無 hardcoded fallback）：${promptName}。` +
    `本次 AI 呼叫已阻斷，請檢查 Langfuse 連線或補充 PROMPT_HARDCODED_FALLBACK。`
  );
  console.error(`❌ ${degradationErr.message}`);
  throw degradationErr;
}

// promptSource = "hardcoded-fallback" 時繼續執行，但在 trace metadata 標記降級狀態
// 下游呼叫端可依 traceId 在 Langfuse 查詢是否處於降級狀態
```

### 建議修改三：`docs/modules/ai_pipeline.md` 補充 Degradation Policy 章節

```markdown
## Langfuse Degradation Policy

### Prompt 可用性層級

| 層級 | 條件 | 行為 | `promptSource` 標記 |
|------|------|------|---------------------|
| **正常** | Langfuse 連線成功，prompt 拉取成功 | 使用 Langfuse prompt，完整插值 | `"langfuse"` |
| **降級** | Langfuse 斷線，但 `PROMPT_HARDCODED_FALLBACK` 有對應 prompt | 使用 hardcoded prompt，繼續執行，輸出品質可能降低 | `"hardcoded-fallback"` |
| **阻斷** | Langfuse 斷線，且無 hardcoded fallback | `callAI()` 拋錯，阻斷本次 pipeline，避免無意義通知送出 | `"missing"` |

### 規則

1. **所有生產環境使用的 promptName 必須在 `PROMPT_HARDCODED_FALLBACK` 中有對應條目**，新增 prompt 時需同步維護。
2. **hardcoded fallback 僅包含最基礎的角色定義**，不嵌入完整市場資料模板，以避免 fallback 版本過時後產生誤導。
3. **降級狀態需主動告警**：`promptSource = "hardcoded-fallback"` 時，除 console.warn 外，應觸發 LINE 系統通知（`[系統] Langfuse 斷線，本日分析使用降級 prompt，請確認輸出品質`）。
4. **`PROMPT_HARDCODED_FALLBACK` 版本管理**：每次更新 Langfuse 上的 system prompt 重大改版時，需同步評估是否要更新對應的 hardcoded fallback，並在 commit message 中標注 `[langfuse-fallback-sync]`。
```

## 預期效果

套用此提案後：

1. **消除「AI 裸跑」情境**：Langfuse 斷線時，AI 至少有最基礎的角色定義，不會在空白狀態下產生看似合理卻毫無依據的投資建議。
2. **明確的三層 Degradation Policy**：正常 / 降級 / 阻斷三種狀態在程式碼與文件中均有明確定義，不再依賴「開發者判斷」。
3. **可觀測的降級狀態**：`promptSource` 欄位值從二元（`"langfuse"` / `"code-fallback"`）改為三態（`"langfuse"` / `"hardcoded-fallback"` / `"missing"`），Langfuse Dashboard 可過濾降級發生頻率。
4. **防止此問題的後退規則**：文件規則要求「新增 promptName 時必須同步維護 hardcoded fallback」，從根源防止未來新增 prompt 時重複出現相同缺口。
