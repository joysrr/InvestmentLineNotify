## 問題描述

**發現位置**：`docs/TEST_MAPPING.md`、`src/test/` 目錄實際結構、`docs/DoD_AUDIT_LOG.md`

**問題摘要**：`TEST_MAPPING.md` 宣告的覆蓋範圍與 `src/modules/` 實際存在的模組目錄之間存在大量空白，其中 `snapshotCrypto.mjs`、`storage.mjs`、`notifications/`、`bot/` 等高風險模組完全無任何測試映射；`DoD_AUDIT_LOG.md` 自初始化後無任何實際執行紀錄，Audit 機制形同虛設。

**詳細描述**：

**落差一：TEST_MAPPING 宣告 6 條映射，但 `src/modules/` 有 10 個模組/目錄**

對照結果如下 ：

| 模組 | TEST_MAPPING 映射 | 實際重要性 |
|---|---|---|
| `src/modules/strategy/` | ✅ 有 `strategyEngine.test.mjs` | 高 |
| `src/modules/data/archiveManager.mjs` | ✅ 有 `archiveManager.test.mjs` | 中 |
| `src/modules/newsFetcher.mjs` | ✅ 有 `keywords.test.mjs` | 中 |
| `src/modules/providers/` | ✅ 有 `providers.test.mjs` | 高 |
| `src/modules/ai/` | ✅ 有 `aiPrompt.test.mjs` | 高 |
| `src/utils/coreUtils.mjs` | ✅ 有 `test/coreUtils.test.js` | 低 |
| `src/utils/snapshotCrypto.mjs` | ❌ **無** | **極高**（財務資料加解密） |
| `src/modules/storage.mjs` | ❌ **無** | **高**（檔案寫入/讀取是資料持久化核心） |
| `src/modules/notifications/` | ❌ **無** | 高（LINE / Telegram 通知送出邏輯） |
| `src/modules/bot/` | ❌ **無** | 高（Bot 指令處理） |
| `src/modules/news/` | ❌ **無** | 中（新聞去重、過濾邏輯） |
| `src/test/backtest.mjs` | ❌ 有檔案但未列入映射表 | 中（回測腳本，角色不明） |
| `src/test/newsTest.mjs` | ❌ 有檔案但未列入映射表 | 中（手動新聞測試，無 Vitest 格式） |
| `src/test/test-keywordConfig.mjs` | ❌ 有檔案但未列入映射表 | 中（獨立腳本，非 Vitest） |

**落差二：TEST_REPORT 是一次性快照，`DoD_AUDIT_LOG` 無後續紀錄**

`TEST_REPORT.md` 明確標注本身為「2026-04-19 Epic 1 Remediation 快照，非 ongoing 產出」，但後續並未有新的 TEST_REPORT 產出。`DoD_AUDIT_LOG.md` 自 2026-04-22 初始化後，除了 `INIT` 那一行外，**沒有任何 Ticket 的 Gate Check 紀錄** ——這代表 `@Lead` 的 DoD 審計習慣尚未建立，Audit 機制只有框架、沒有執行。

**落差三：`src/test/` 中有遊魂測試檔，但未整合進 Vitest 流程**

`backtest.mjs`、`newsTest.mjs`、`test-keywordConfig.mjs` 存在於 `src/test/` 下但：
- 未列入 `TEST_MAPPING.md`
- 未使用 Vitest `describe/it` 格式，無法被 `npm test` 自動執行
- 缺乏維護責任人定義

這些「遊魂腳本」在需要時才手動執行，平時不產生任何防護效果 。

## 根因分析

| 根因層級 | 代碼 | 分析說明 |
|---------|------|---------|
| 需求層（Requirements） | `REQ` | `TEST_MAPPING.md` 的設計規範只要求「新增模組時需更新此表」，但未定義現有未覆蓋模組的補測優先序，導致已知缺口沒有明確修補路徑 |
| 開發層（Development） | `DEV` | `DoD_AUDIT_LOG` 設計依賴 `@Lead` 主動 append，但沒有硬性觸發機制（如 PR merge checklist），落實率等同於自律約定 |

## 建議修改對象與內容

### 修改一：`TEST_MAPPING.md` — 補齊現有未覆蓋模組的映射列，並標注補測優先序

**目標 Agent**：`@QA`
**目標文件**：`docs/TEST_MAPPING.md`

**建議新增的補測待辦清單**：

```markdown
## 補測待辦（Coverage Debt）

以下模組目前無對應測試，依風險等級排序補測：

| 優先序 | 原始碼路徑 | 建議測試檔案 | 測試類型 | 原因 |
| :----: | :--------- | :----------- | :------- | :--- |
| P0 | `src/utils/snapshotCrypto.mjs` | `src/test/unit/snapshotCrypto.test.mjs` | 單元測試 | 財務資料加解密邏輯；key 長度錯誤、null key、加解密往返一致性 |
| P1 | `src/modules/storage.mjs` | `src/test/unit/storage.test.mjs` | 單元測試 | 資料持久化核心；讀寫失敗、格式異常行為 |
| P1 | `src/modules/notifications/` | `src/test/unit/notifications.test.mjs` | 單元測試 | 通知送出邏輯；格式化、錯誤處理 |
| P2 | `src/modules/news/` | `src/test/unit/newsDedup.test.mjs` | 單元測試 | 新聞去重（Jaccard）邊界值 |
| P2 | `src/modules/bot/` | `src/test/integration/botHandler.test.mjs` | 整合測試 | Bot 指令路由與回應 |

## 遊魂腳本清理待辦

以下腳本存在於 `src/test/` 但未整合進 Vitest，需在下次 Retro 決定去留：

| 檔案 | 現況 | 建議處置 |
```

### 修改二：`DoD_AUDIT_LOG.md` — 補充強制觸發規範，明確 `@Lead` 的最低執行義務

**目標 Agent**：`@Lead`
**目標文件**：`docs/DoD_AUDIT_LOG.md`
**修改位置**：「使用規範」區塊

**建議修改的規則原文**：

```markdown
## 使用規範

- **觸發時機（強制）**：每次 PR merge 至 `main` 時，`@Lead` 必須在 24 小時內 append 至少一行 Gate Check 紀錄；若 Gate Check 未通過，以 `BLOCKED` 標示並附原因
- 每列必須 append-only，不可修改歷史
- 若連續 **3 個自然日** 無任何 append，視為 DoD 機制中斷，需在下次 Retro 列為議題討論
- `@Auditor` 每週執行 DoD 達成率統計（通過 ✅ / 全部 Gate Check 次數），統計結果寫入 `docs/Reports/AUDIT_HISTORY.md` 作為維度 5.1 評分依據
```

***

### 修改三：`docs/TEST_MAPPING.md` — 補充「遊魂腳本」的定義與處置規範

**目標 Agent**：`@QA`
**目標文件**：`docs/TEST_MAPPING.md`
**修改位置**：「執行規範」區塊底部新增

**建議新增的規則原文**：

```markdown
## 腳本分類定義

本專案區分以下兩種測試腳本類型：

| 類型 | 規範 | 路徑 |
| :--- | :--- | :--- |
| **自動化測試**（Vitest） | 必須使用 `describe`/`it`/`expect` 格式，可被 `npm test` 執行，須列入映射表 | `src/test/unit/`、`src/test/integration/` |
| **手動工具腳本** | 供除錯或一次性驗證使用，不計入覆蓋率，**不得放置於 `src/test/`** | `scripts/` |

> ⚠️ 放置於 `src/test/` 但未使用 Vitest 格式的腳本，視為「遊魂腳本」，需在下次 Retro 決定重構或移出。
```

***

## 預期效果

套用此提案後：

1. **P0 補測路徑明確**：`snapshotCrypto.mjs` 的加解密邊界值測試有明確的建立目標，不再依賴人工記憶
2. **DoD 執行有最低頻率約束**：「3 天無 append = 機制中斷」觸發 Retro 討論，從「自律約定」升級為「可稽核的流程規範」
3. **遊魂腳本不再佔據 `src/test/`**：路徑分離讓 CI 不會誤把手動工具腳本當作測試套件
4. **Coverage Debt 可視化**：以優先序排列的補測待辦表，讓每次 Sprint 都能評估要還多少測試債
