## 問題描述

**發現位置**：`src/modules/ai/llmJudge.mjs` + `src/dailyCheck.mjs`

**問題摘要**：LLM Judge 採固定排程觸發，高風險日（VIX 飆升、市場極端訊號）不會強制啟動，導致最需要品質驗證的建議反而最可能跳過評估。

**詳細描述**：

根據 `llmJudge.mjs` 的 `shouldRunJudge()` 實作 ，目前支援三種模式：

| 模式 | 觸發邏輯 | 問題 |
|---|---|---|
| `weekly`（預設） | 僅指定星期幾 | 該星期五 VIX = 80 仍可能不觸發 |
| `random` | 固定機率抽樣 | 高風險日與低風險日觸發機率相同 |
| `always` | 每次都執行 | 浪費 API token，不可持續 |

再看 `dailyCheck.mjs` 的觸發判斷 ：

```javascript
if (shouldRunJudge() && adviceTraceId && typeof aiAdvice === "object") {
  // 執行 Judge
}
```

**關鍵盲區**：`shouldRunJudge()` 完全不接受任何上下文參數，無法感知當日風險狀況。而 `dailyCheck.mjs` 在呼叫點已經擁有完整的高風險資訊（`vixData`、`result.signals`、`macroMarketDirection`），卻完全沒有將這些資訊傳遞給 Judge 觸發判斷。

具體高風險情境舉例：
- VIX ≥ 30（恐慌警戒線）
- `macroMarketDirection === "BEARISH"` 且 RSI < 30（雙殺訊號）
- `latchActive` 剛變更（策略狀態轉換日）
- `result.signals.action` 為 `BUY` 或 `SELL`（非 HOLD 日）

這些日子正是 AI Coach 建議品質最需要被驗證的時機，卻因為 `shouldRunJudge()` 不感知風險而可能被跳過。

## 根因分析

| 根因層級 | 代碼 | 分析說明 |
|---------|------|---------|
| 設計層（Architecture） | `ARCH` | `shouldRunJudge()` 被設計為無狀態純函式，只讀 env var，不接收 context，架構上無法表達「條件觸發」的意圖 |
| 開發層（Development） | `DEV` | `dailyCheck.mjs` 呼叫點雖持有完整 signal context，但未將高風險條件傳入，導致 context 資訊孤島 |

## 建議修改對象與內容

### 修改一：`llmJudge.mjs` — `shouldRunJudge()` 接收 context 參數

**目標 Agent**：`@Backend`
**目標文件**：`src/modules/ai/llmJudge.mjs`

**建議修改的程式碼**：

```javascript
/**
 * 依 LLM_JUDGE_MODE 環境變數決定今天是否執行 Judge
 *
 * 新增 context 參數，支援高風險強制觸發：
 *   若 context.forceRun === true，無論模式為何，皆強制執行
 *
 * @param {{ forceRun?: boolean }} [context={}]
 * @returns {boolean}
 */
export function shouldRunJudge(context = {}) {
  // ── 高風險強制觸發 ─────────────────────────────────────────────────────────
  if (context.forceRun === true) {
    console.log("⚠️ [LLMJudge] 高風險日強制觸發 Judge（forceRun=true）");
    return true;
  }

  const mode = (process.env.LLM_JUDGE_MODE ?? "weekly").toLowerCase();
  if (mode === "always") return true;

  if (mode === "random") {
    const rate = parseFloat(process.env.LLM_JUDGE_SAMPLE_RATE ?? "0.2");
    return Math.random() < rate;
  }

  // 預設 weekly
  const targetDay = parseInt(process.env.LLM_JUDGE_WEEKDAY ?? "1", 10);
  const todayDay = new Date().getDay();
  return todayDay === targetDay;
}
```

### 修改二：`dailyCheck.mjs` — 建立高風險判斷並傳入 context

**目標 Agent**：`@Backend`
**目標文件**：`src/dailyCheck.mjs`
**修改位置**：LLM Judge 觸發段落（`// ── LLM Judge（背景評估，不阻塞主流程）`）

**建議修改的程式碼**：

```javascript
// ── LLM Judge（背景評估，不阻塞主流程）──────────────────────────────────────
const judgeTasks = [];

// ── 高風險日判斷 ──────────────────────────────────────────────────────────────
const vixValue = vixData?.value ?? 0;
const isHighRiskDay =
  vixValue >= 30 ||
  (result?.signals?.action && result.signals.action !== "HOLD") ||
  valuationGuardState.latchActive !== (result?.signals?.latchNowActive ?? false);
// 說明：
//   1. VIX ≥ 30  → 市場恐慌，AI 建議最需驗證
//   2. 非 HOLD 日 → 實際有買賣動作，建議品質攸關財務決策
//   3. latch 狀態轉換日 → 策略發生結構性變化，需確認建議方向正確

const judgeContext = { forceRun: isHighRiskDay };

if (isHighRiskDay) {
  console.log(
    `⚠️ [LLMJudge] 高風險日偵測：VIX=${vixValue}, action=${result?.signals?.action ?? "unknown"}, latchChanged=${valuationGuardState.latchActive !== (result?.signals?.latchNowActive ?? false)}`
  );
}

if (shouldRunJudge(judgeContext) && adviceTraceId && typeof aiAdvice === "object") {
  console.log("🔍 [LLMJudge] 今日觸發 Judge，排入背景任務...");
  judgeTasks.push(
    runJudge(adviceTraceId, aiAdvice, sessionId).catch((err) =>
      console.warn("⚠️ [LLMJudge] 背景任務發生例外:", err.message)
    )
  );
} else if (shouldRunJudge(judgeContext)) {
  console.log(
    "⚠️ [LLMJudge] 今日應觸發但 adviceTraceId 無效或 aiAdvice 非物件，跳過"
  );
} else {
  console.log("⏭️ [LLMJudge] 今日不執行 Judge");
}
```

### 修改三：`ai_pipeline.md` — 補充 Judge 觸發策略規範

**目標 Agent**：`@Architect`
**目標文件**：`docs/modules/ai_pipeline.md`
**修改位置**：LLMJudge 章節

**建議新增的規則原文**：

```markdown
### LLM Judge 觸發策略

Judge 採雙層觸發機制，確保品質監控資源集中在最高風險場景：

**Layer 1 — 排程觸發**（節省 token）
- 由 `LLM_JUDGE_MODE` env var 控制：`weekly`（預設）/ `random` / `always`
- 適用於日常品質抽樣

**Layer 2 — 高風險強制觸發**（保護財務決策）
滿足任一條件時，無視 Layer 1 排程，強制執行 Judge：
| 條件 | 說明 |
|---|---|
| `VIX ≥ 30` | 市場恐慌，AI 建議最需驗證 |
| `action ≠ HOLD` | 有實際買賣動作，品質攸關資金安全 |
| `latch 狀態轉換` | 策略結構性變化，須確認方向正確 |

**實作要求**：
- `shouldRunJudge(context)` 必須接受 `context.forceRun` 參數
- `dailyCheck.mjs` 必須在呼叫前評估高風險條件並傳入 context
- 高風險觸發時，console 須輸出觸發原因供事後追蹤
```

## 預期效果

套用此提案後：
1. **VIX ≥ 30 的恐慌日**，AI Coach 建議必然通過 Judge 品質驗證，不會因排程未到而跳過
2. **實際買賣動作日**，建議的 Actionability / Tone 分數一定被記錄進 Langfuse，可供回顧決策品質
3. **latch 轉換日**，策略方向正確性有 LLM 背書，降低人工疏漏風險
4. `shouldRunJudge()` 改為可測試的有參函式，便於後續單元測試補充
