## 問題描述

**發現位置**：`src/modules/ai/ruleOptimizerAgent.mjs`

**問題摘要**：Rule Optimizer 每日自動將 AI 建議的 Regex 寫入 `blacklist.json`，但缺乏單次新增上限保護與 rollback 可執行機制，導致異常批次可能一次污染大量規則卻無法快速復原。

**詳細描述**：

讀取 `ruleOptimizerAgent.mjs` 後，現有的四關卡 Sandbox（語法合法性 → 廣泛度 → 重複 → Golden Dataset）設計本身是合理的 ，但有以下三個防護缺口：

**缺口 1：無單次新增數量上限**

`appendToBlacklist()` 直接執行 `push(...accepted.map(...))`，完全無數量限制。若 AI 產出 20 條合法但語意錯誤的規則（例如：誤把財報新聞標題當成噪音），四個關卡全部通過後會一次全寫入。Golden Dataset 僅攔截對特定已知好文章的碰撞，無法防止「整體規則過激」的場景。

**缺口 2：rollback 欄位有記錄但無執行機制**

`optimizerHistory.json` 的每筆 history 都有 `rolledBack` 欄位 ，顯示設計者有考慮 rollback，但程式碼中完全沒有任何函式實作這個欄位的寫入或反向操作邏輯。目前若要復原，需要手動編輯 `blacklist.json`，高壓情境下（例如：新聞抓取出問題後的隔日）極易出錯。

**缺口 3：TW 與 US 兩 region 共用同一個 `blacklistData` 物件**

`runRuleOptimizer()` 中，TW 和 US 的 `accepted` 規則都 push 進同一個 `blacklistData`，最後才寫入檔案一次 。若 TW 正常、US 異常（例如：AI 產出語意問題規則），兩個 region 的結果無法獨立復原，必須整包一起 rollback。

### 修改一：`ruleOptimizerAgent.mjs` — 新增單次新增上限保護

**目標 Agent**：`@Backend`
**目標文件**：`src/modules/ai/ruleOptimizerAgent.mjs`
**修改位置**：`validateAndPrepare()` 函式結尾、`runRuleOptimizer()` 呼叫前

**建議新增的程式碼**：

```javascript
// ── 常數：單次安全上限 ────────────────────────────────────────────────────────
const MAX_RULES_PER_RUN_PER_REGION = 5; // 單一 region 每次最多新增 5 條

// 在 runRuleOptimizer() 的 for 迴圈中，appendToBlacklist 之前加入：
if (accepted.length > MAX_RULES_PER_RUN_PER_REGION) {
  console.warn(
    `[Optimizer] ⚠️  ${region} 單次通過規則數 (${accepted.length}) 超過安全上限 (${MAX_RULES_PER_RUN_PER_REGION})，` +
      `截斷至前 ${MAX_RULES_PER_RUN_PER_REGION} 條，其餘記錄為 capped`,
  );
  const capped = accepted.splice(MAX_RULES_PER_RUN_PER_REGION);
  rejected.push(...capped.map((r) => ({ ...r, rejectReason: "batch_cap" })));
}
```

### 修改二：`ruleOptimizerAgent.mjs` — 實作 rollback 執行函式

**目標 Agent**：`@Backend`
**目標文件**：`src/modules/ai/ruleOptimizerAgent.mjs`

**建議新增的程式碼**：

```javascript
/**
 * 依據 optimizerHistory.json 中的指定日期 + region 執行 rollback
 * 從 blacklist.json 中移除該批次新增的規則，並標記 history 中 rolledBack = true
 *
 * @param {string} date   - 欲 rollback 的日期（YYYY-MM-DD）
 * @param {"TW"|"US"|"ALL"} region - 指定 region，或 "ALL" 表示兩者一起
 */
export function rollbackOptimizerRules(date, region = "ALL") {
  const history = JSON.parse(readFileSync(HISTORY_PATH, "utf-8"));
  const blacklist = JSON.parse(readFileSync(BLACKLIST_PATH, "utf-8"));

  const targets = history.history.filter(
    (h) =>
      h.date === date &&
      (region === "ALL" || h.region === region) &&
      h.rolledBack === false,
  );

  if (targets.length === 0) {
    console.log(
      `[Rollback] 找不到可 rollback 的紀錄：date=${date}, region=${region}`,
    );
    return { removed: 0 };
  }

  let removed = 0;
  for (const entry of targets) {
    const rulesToRemove = new Set(entry.addedRules.map((r) => r.regexLiteral));
    const before = blacklist.titleBlackListPatterns.length;
    blacklist.titleBlackListPatterns = blacklist.titleBlackListPatterns.filter(
      (p) => !rulesToRemove.has(p),
    );
    const delta = before - blacklist.titleBlackListPatterns.length;
    removed += delta;
    entry.rolledBack = true;
    entry.rolledBackAt = new Date().toISOString();
    console.log(
      `[Rollback] ✅ ${entry.region} (${date})：移除 ${delta} 條規則`,
    );
  }

  blacklist.lastUpdated = new Date().toISOString();
  writeFileSync(BLACKLIST_PATH, JSON.stringify(blacklist, null, 2), "utf-8");
  history.lastUpdated = new Date().toISOString();
  writeFileSync(HISTORY_PATH, JSON.stringify(history, null, 2), "utf-8");

  console.log(`[Rollback] 🏁 完成，共移除 ${removed} 條規則`);
  return { removed };
}
```

### 修改三：新增 `src/scripts/rollbackOptimizer.mjs` — rollback 入口腳本

**目標 Agent**：`@Backend`
**目標文件**：`src/scripts/rollbackOptimizer.mjs`（新增檔案）

**建議新增的程式碼**：

```javascript
/**
 * 手動執行 Optimizer Rollback
 * 用法：node src/scripts/rollbackOptimizer.mjs <date> [region]
 * 範例：node src/scripts/rollbackOptimizer.mjs 2026-04-25 TW
 *        node src/scripts/rollbackOptimizer.mjs 2026-04-25 ALL
 */
import { rollbackOptimizerRules } from "../modules/ai/ruleOptimizerAgent.mjs";

const [, , date, region = "ALL"] = process.argv;

if (!date || !/^\d{4}-\d{2}-\d{2}$/.test(date)) {
  console.error("❌ 用法：node rollbackOptimizer.mjs <YYYY-MM-DD> [TW|US|ALL]");
  process.exit(1);
}

const result = rollbackOptimizerRules(date, region);
if (result.removed === 0) {
  console.warn("⚠️ 無規則被移除，請確認日期與 region 是否正確");
  process.exit(1);
}
process.exit(0);
```

```markdown
### Rule Optimizer 安全治理規範

除四關卡 Sandbox 外，Rule Optimizer 需遵守以下批次安全規範：

#### 單次新增上限

| 範圍                   | 上限 | 超出行為                                  |
| ---------------------- | ---- | ----------------------------------------- |
| 單一 region / 單次執行 | 5 條 | 超出部分以 `batch_cap` 拒絕，記入 history |

設計動機：四關卡只驗證個別規則的合法性，無法防止「AI 批次產出語意錯誤但合法的規則」場景。

#### Rollback 機制

- `optimizerHistory.json` 的每筆 history 必須完整記錄 `addedRules`（含 `regexLiteral`）
- 執行 rollback 時使用 `src/scripts/rollbackOptimizer.mjs <date> [region]`
- Rollback 完成後，history 中對應項目的 `rolledBack` 欄位應標記為 `true`，並記錄 `rolledBackAt` 時間戳
- TW / US 可獨立 rollback，不互相影響

#### 異常偵測建議

若某次執行的 `Optimizer_Accept_Rate` > 0.8（AI 建議幾乎全部通過），應人工複查 AI 輸出是否異常，不應視為正常結果。
```

## 預期效果

套用此提案後：

1. **批次污染上限**：AI 即使產出 15 條「合法但語意問題」的規則，最多只有 5 條寫入，大幅降低單次污染範圍
2. **rollback 可執行**：意外寫入後 30 秒內可透過腳本精確復原，不需手動編輯 JSON
3. **TW/US 獨立復原**：兩 region 的規則可分開 rollback，不需整包撤銷
4. `rolledBack` 欄位從「設計孤兒」升格為有程式碼支撐的可用功能
