## 問題描述

**發現位置**：`src/utils/envGuard.mjs`、`src/utils/snapshotCrypto.mjs`、`docs/SECURITY.md`、`src/api/` 目錄結構

**問題摘要**：架構文件與規劃文件中描述的 `adminGuard`、`initDataGuard` 安全機制在程式碼中完全不存在，而 `SNAPSHOT_ENCRYPT_KEY` 未被列入 `envGuard` 的必填清單，造成加密機制可靜默失效。

**詳細描述**：

透過全域程式碼搜尋，確認以下三個具體落差：

**落差 1：`adminGuard` / `initDataGuard` 僅存在文件，無程式碼實作**

搜尋整個 repo 的 `adminGuard`、`initDataGuard`、`validateWebAppData`，結果為零 。`src/api/` 目錄下目前只有 `utils/` 子目錄，沒有任何 route 檔案 。架構文件所描述的「Telegram `initData` 驗證防護」屬於**預規劃但未落地的功能**。

**落差 2：`SNAPSHOT_ENCRYPT_KEY` 未列入 `envGuard` 必填清單**

`envGuard.mjs` 的 `REQUIRED_VARS` 列出 10 個必填變數，其中不包含 `SNAPSHOT_ENCRYPT_KEY` 。`snapshotCrypto.mjs` 的設計是「金鑰不存在時靜默略過加密、回傳 null」。這兩個行為組合起來意味著：若 GitHub Secret 設定失誤、`SNAPSHOT_ENCRYPT_KEY` 遺漏，系統不會報錯，財務快照將以明文寫入 `daily_report_*.json`，且整個流程繼續正常執行，不留任何告警。

**落差 3：`SECURITY.md` 宣稱「敏感欄位已加密」但缺乏防護前提的明確標注**

`SECURITY.md` 明確寫道「snapshot 類財務資料已加密儲存」，但未提及此保護依賴 `SNAPSHOT_ENCRYPT_KEY` 的正確設定。這對未來維護者（包含自己在新機器設定時）形成誤導——可能誤以為加密是無條件開啟的。

## 根因分析

| 根因層級 | 代碼 | 分析說明 |
|---------|------|---------|
| 需求層（Requirements） | `REQ` | `adminGuard`/`initDataGuard` 被寫入架構文件但未被轉化為可驗收的開發任務，導致文件超前實作 |
| 開發層（Development） | `DEV` | `SNAPSHOT_ENCRYPT_KEY` 設計為「可選加密」，但 `envGuard` 沒有對應的條件告警，靜默失效路徑未被封閉 |

## 建議修改對象與內容

### 修改一：`envGuard.mjs` — 加入 `SNAPSHOT_ENCRYPT_KEY` 的條件警告

**目標 Agent**：`@Backend`
**目標文件**：`src/utils/envGuard.mjs`

> **設計說明**：`SNAPSHOT_ENCRYPT_KEY` 屬於「強烈建議但非硬性必填」的金鑰——沒有它系統仍可運作，但財務資料防護等級顯著下降。因此採用「warn 不 exit」策略，而非加入 `REQUIRED_VARS`。

**建議修改的程式碼**：

```javascript
/**
 * 檢查必填環境變數。
 * 缺少時列印這些變數名稱并呼叫 process.exit(1)。
 * 同時對「強烈建議設定」的變數發出警告。
 */
export function assertEnv() {
  const missing = REQUIRED_VARS.filter(
    (key) => !process.env[key] || process.env[key].trim() === "",
  );

  if (missing.length > 0) {
    console.error("\n❌ [envGuard] 程式終止：缺少必要環境變數");
    console.error(
      "請確認 GitHub Secrets 與 workflow yaml 的 env: 區塊均已設定以下變數：",
    );
    missing.forEach((key) => console.error(`  • ${key}`));
    console.error("詳情請參考 docs/env-vars.md\n");
    process.exit(1);
  }

  // ── 強烈建議設定的變數（缺少時 warn，不中斷） ──────────────────────────────
  const RECOMMENDED_VARS = [
    {
      key: "SNAPSHOT_ENCRYPT_KEY",
      reason:
        "帳戶快照將以明文儲存於 daily_report_*.json，財務資料缺乏加密保護",
    },
  ];

  for (const { key, reason } of RECOMMENDED_VARS) {
    if (!process.env[key] || process.env[key].trim() === "") {
      console.warn(
        `⚠️ [envGuard] 建議設定 ${key} 但未找到：${reason}`,
      );
    }
  }
}
```

## 預期效果

套用此提案後：

1. **`SNAPSHOT_ENCRYPT_KEY` 遺漏時不再靜默失效**：啟動時 console 明確警告，運維人員立即可見，不需等到事後審計才發現快照明文
2. **`SECURITY.md` 不再形成誤導**：「已加密」的描述附帶前提條件，未來新機器部署時不會誤判安全狀態
3. **`adminGuard`/`initDataGuard` 的落差被文件化**：架構文件清楚標注「規劃中未實作」，避免後續開發者誤以為已有防護而省略安全檢查
4. **`env-vars.md` 提供 key 產生指令**：移除操作門檻，讓設定 `SNAPSHOT_ENCRYPT_KEY` 更容易被執行
