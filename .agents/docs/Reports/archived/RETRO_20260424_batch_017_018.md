## 三、❌ 做得差的（4 項實質缺失）

### F-1：Step 6.5 雙向 bug（017 Phase C 遺留）

**現象**：`selectTechStacks()` 只實作 `installed: true → false`（drop），漏 `false → true`（keep）。User 自 017 完成到 Phase F.3 都沒發現；直到 018 設計討論才浮現。

**根因**：017 Phase C unit test 只覆蓋 `answerMatchesAvailableStacks`（純查找函式）；`selectTechStacks` 本身是 async + stateful，被「難測」勸退 → **邏輯分支 50% 未驗證**。

**改善建議**：

- 抽純函式 `applyTechStackChoices`（018 Phase B 已做 ✅）
- 為該純函式補 4 個 unit tests：keep / drop / drop-with-deps / file-missing-restore
- 規則：**任何雙向處理邏輯，單元測試必覆蓋兩方向**（可列入 RULES_DESIGN_GUIDE §九 測試準則）

---

### F-2：混淆 Phase F 與驗收缺口

**現象**：018 Phase E commit 完成後，User 問「接下來應該做什麼」，我回答「3 個驗收缺口」而**完全漏掉 Phase F**（ADR-0032 + version bump + close）。實際 Phase F 最後還是被完成（commit `79262fa`），但當下心智模型錯了。

**根因**：Todo list 追蹤 phase 進度，但我把注意力移到「驗收條件 vs 現況」比對；兩個追蹤維度打架 → 忘了 todo 還有 Phase F 未完成。

**改善建議**：

- Todo 只追蹤 phase 進度；驗收條件對齊另用獨立 checklist（例：提案 §六 驗收條件 → 每 phase commit 時逐項勾）
- 每次 User 問「接下來」時，先**朗讀 todo list 現況**再判斷（避免邊走邊忘）
- 可列入 `rules/lead.md §任務派發` 或 `skills/stateless-routing-pattern.md`

---

### F-3：Schema 變更未預警連鎖反應

**現象**：018 Phase A 加 2 個 TECH_STACK 欄位（`last_audit_date` + `audit_interval_days`），Phase B 執行 smoke test 時 success path 失敗（41 行 piped input 變得不匹配 `collectAnswers` 預期流程）。修法是讓 `collectAnswers` 明確 skip 這 2 欄位 + end 注入預設。

**根因**：`WORKSPACE_SCHEMA.yaml` 的欄位會自動進入 `collectAnswers` 互動迴圈，但某些欄位本質是系統自動填（audit date），不該問 User；schema 沒有區分「interactive / auto-populate」的屬性 → 任何新增欄位都默認互動。

**改善建議**：

- `WORKSPACE_SCHEMA.yaml` 欄位加 `interactive: boolean`（預設 true）
- `collectAnswers` 依 `interactive` 決定是否問；auto-populate 類欄位由呼叫端或 post-hook 填
- `tests/workspace-schema-validator.mjs` 檢查 schema 合法性：interactive=false 的欄位必有 default 或 autopop rule

---

### F-4：骨架建立時機過早

**現象**：017 Phase F.2 建立 `semi-avalonia/` 骨架時，vendor docs 還沒到手。後來 User 提供 SKILL.md + WORKFLOWS.md + BEST_PRACTICES.md **全部是 React 版**，不能塞進本骨架 → 最終走 WebFetch 自動擷取 irihitech 實際文件。

**根因**：提案書把 F.2 定為「建骨架」+ F.3 定為「User 提供後填 upstream」是合理 phase 劃分，但現實中 User 拿錯文件是常見情境 → 骨架模板其實過度假設 vendor 性質（元件庫 / 主題庫 / 工具）。

**改善建議**：

- 資料夾模式 tech-stack 新增流程 SOP（`skills/tech-stack-onboarding.md §4.2`）加一步「先 WebFetch 官方 repo 確認定位」再建骨架
- 或改為 **lazy skeleton**：MANIFEST entry 先建（`installed: false`），實體資料夾結構等 upstream/ 有內容才建
- 避免「空骨架 + 錯 vendor 文件」二次工作
