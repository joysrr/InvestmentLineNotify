# PROPOSAL_502_030: Prior Art Gate 改 HITL-first

## 一、背景

User 反饋（2026-05-04）：

> Prior Art Gate 目前設計是 Agent 自行去查找？為了精準度與成本考量，此部分可以改成提供需要搜索的全部資訊以及格式，讓使用者可以自行透過 Chat 取得結果再回填

### 現況問題

ADR-0014 + skills/checklists/prior-art-scan-checklist.md：

- Step 1-3 由 @Architect 執行（觸發判定 / 關鍵字抽取 / 評估矩陣準備）
- Step 4 「檢索管道」標 _User 執行；Agent 協助提示_（但設計時序不明）
- Step 5-6 評估候選 + 撰寫 report
- 之後才發 🔴 `PRIOR_ART_VERIFY_PENDING` HITL Gate

問題：

- Agent 在某些環境（Claude Code / Antigravity 內含 WebSearch tool）可能自己做 web search 推導候選 → 精準度差（LLM web search 結果不穩；訓練資料截止後新套件遺漏）
- Agent 推導 = 浪費 LLM token；User 自己 Chat / 瀏覽器 search 更快更準
- 目前 HITL Gate 在「報告產出後」；User 變成「驗證」而非「執行」

### 目標

Flip flow → **HITL-first**：

1. Agent 出「Search Package」（keywords / channels / 評估 rubric / 待填表）
2. User 執行 search（Chat / browser）→ 回填結果
3. Agent 整合 + 評估矩陣 + 最終建議
4. Final HITL Gate：User 確認 agent 評估

## 三、Functional Safety

- ✅ Bypass 機制保留（`verified_method: bypass` + reason）
- ✅ 既有 HITL Gate 不刪；只是多一層前置 gate
- ✅ Agent 仍負責 keyword 抽取 + 評估矩陣（這兩步不需 web search；agent 強項）
- ✅ Report template 向後相容（既有報告繼續用）
- ⚠️ User 額外負擔：要自己跑 search → 但這就是 user 想要的（換取準確度）

## 四、預期效果

| 維度       | 改善                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| 精準度     | User 自己 Chat / Google / 瀏覽器 search → 結果即時準確；非 LLM 訓練截止      |
| Cost       | Agent 不再做 web search → token cost -2-5K / scan                            |
| Trust      | User 親自驗證候選；信心度高                                                  |
| 速度       | User 自己 search 反而比 agent web search 慢（手動）；但 1 次到位省 follow-up |
| 流程清晰度 | 三段明確分工：agent prep → user search → agent analyze                       |
