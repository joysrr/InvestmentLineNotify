## 三、提案內容

### 3.1 `.agents/tests/` 目錄結構

```
.agents/tests/
├── README.md                              ← 使用說明 + 執行入口
├── schema-validator.mjs                   ← 驗證 frontmatter + XML section
├── lead-stateless-audit.mjs               ← 驗證 @Lead 無狀態違反
├── artifact-format-validator.mjs          ← 驗證 REVIEW/SECURITY/TEST_REPORT 格式
└── proposal-intent-consistency.mjs        ← 驗證 §🔗 意圖繼承表完整性
```

### 3.2 schema-validator.mjs（核心工具）

```javascript
// 驗證每份 rules 的 frontmatter 與 XML section 合規性
// 檢查項：
// 1. YAML frontmatter 必要欄位（依 RULES_METADATA_SCHEMA §2.1）
// 2. <section id="..." priority="..."> 屬性齊全
// 3. !ref 引用目標存在（跨檔案解析）
// 4. immutable="true" section 未被意外修改（與 git 歷史比對）
// 5. Token 預算不超標（按需 1000 / AlwaysOn 500）

執行方式：node .agents/tests/schema-validator.mjs [--strict] [--file <path>]
輸出：JSON 結構化報告 + 退出碼（0=通過 / 1=有警告 / 2=有錯誤）
```

### 3.3 lead-stateless-audit.mjs

```javascript
// 驗證 @Lead 最近 N 輪對話是否符合 §s_state_anchor 三鐵律
// 檢查項：
// 1. PENDING_ACTIONS.md [CURRENT_STAGE] 欄位存在且更新時間合理
// 2. Gate Check 輸出格式（2 行短指令）合規
// 3. 交接指令 ≤ 5 行純文字（依 §s_state_anchor 第 3 條）
// 4. 違反計數追蹤（累計 ≥ 3 次觸發全局緊急阻斷條件一）

執行方式：node .agents/tests/lead-stateless-audit.mjs [--last <N>]
```

### 3.4 artifact-format-validator.mjs

```javascript
// 驗證 @Reviewer/@Security/@QA 產出物符合 M2M 合約（PROPOSAL_20260422_003）
// 檢查項：
// 1. REVIEW_REPORT.md 第一行為 🔴/❌/🟡/✅/🟢 之一
// 2. SECURITY_REPORT.md 第一行為【@Security 資安審查報告】<符號>格式
// 3. TEST_REPORT.md 第一行為 <符號> 測試結論：...
// 4. 無前言/結語/自然語言包裝

執行方式：node .agents/tests/artifact-format-validator.mjs <file>
```

### 3.5 proposal-intent-consistency.mjs

```javascript
// 驗證 PROPOSAL_INDEX.md §🔗 提案意圖繼承關係 表完整性
// 檢查項：
// 1. 每筆意圖繼承條目對應的歷史提案 DONE 狀態存在
// 2. 繼承目標提案於 PROPOSAL_INDEX.md DONE 區塊有「意圖繼承至」標注
// 3. 新增 DONE 提案是否出現語意回退（比對 §七 備註與歷史 §一 問題描述）

執行方式：node .agents/tests/proposal-intent-consistency.mjs
輸出：與 P-14 PROPOSAL_INTENT_REGRESSION 偵測邏輯對齊
```
