# PROPOSAL_502_032: Per-Dispatch autonomy_mode

## 一、背景（User 質疑 2026-05-06）

User 問「依照目前設計 Agent 是否有可能自己一直執行每個開發階段的任務直接進行程式開發?」

### 現況分析

是。對「新增 feature」典型場景，agent 可從 Stage 1 一路自動跑到 Stage 9，**期間無 user 介入**：

- Stage 1 需求 → Stage 2 戰略審查 → Stage 3 設計 → Stage 4 TEST_SPEC → Stage 5 實作 → Stage 6 Review → Stage 7 QA 驗證 → Stage 8 收斂 → Stage 9 Retro

既有 HITL gates 對普通 feature **不會觸發**：

- Prior Art Gate（PROPOSAL_502_030）→ 只在 ≥500 LOC 或關鍵字觸發
- Security SC-01~10 → 只在金鑰 / 資料刪除等特定觸發
- force_complex 7 場景 → 只 strategyWeight / Rules edit 等
- Proposal 採納 → 只在 rules edit 流

→ **問題**：複雜功能 user 沒早期介入，可能跑歪後重做；簡單功能 user 又不希望被打擾。

### User 選擇

選項 D：per-dispatch `autonomy_mode` 欄位（4 enum）+ 智能 default per task_class + user override。

## 三、autonomy_mode Enum 設計

| 值               | 行為                                                      | Smart default 觸發 task_class |
| ---------------- | --------------------------------------------------------- | ----------------------------- |
| `auto`           | 一路跑完 Stage 1-9 不停（既有行為）                       | `doc-sync`, `config-adjust`   |
| `step-by-step`   | 每階段轉移前發 🟡 `STAGE_<N>_VERIFY_PENDING` 等 user 確認 | `hotfix`                      |
| `gate-at-design` | 只在 Stage 3 設計後卡一次（user 確認設計方向）            | `feature` (default)           |
| `gate-at-impl`   | 只在 Stage 5 實作前卡一次（user 確認 TEST_SPEC + 設計）   | `modify-existing`             |

### User Override 語法（自然語言）

| User 語句                          | autonomy_mode                           |
| ---------------------------------- | --------------------------------------- |
| "幫我跑完" / "全自動" / "一路做完" | `auto`                                  |
| "每階段跟我確認" / "step by step"  | `step-by-step`                          |
| "設計完先給我看" / "確認方向"      | `gate-at-design`（default for feature） |
| "實作前先看" / "TEST_SPEC 後確認"  | `gate-at-impl`                          |

User 未明示 → agent 依 task_class smart default。

## 四、HITL Gate 機制

`step-by-step` / `gate-at-design` / `gate-at-impl` 命中時：

1. 該 stage 完成 + DoD 自評通過後，agent **不直接 Gate Check 進下一階段**
2. 改寫 `PENDING_ACTIONS.md §🟡` 加一條 `STAGE_<N>_VERIFY_PENDING`（含 stage 編號 + artifact paths + agent 推薦下一步）
3. 等 user 回應：
   - "OK / 繼續" → agent 走原 Gate Check + 派發下一階段
   - "改 X" → agent 退回該 stage 修正
   - 24h / 5 對話無回 → P-33 升 🔴
