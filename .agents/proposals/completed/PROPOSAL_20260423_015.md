## 一、問題描述

### 1.1 現況

2026-04-22 PROPOSAL_023 建立「framework / project scope 分層」設計，**但執行層未落地**：

- 68 份歷史提案全部 `scope: framework`（正確分類）
- 0 份 project scope 提案曾立案
- 機制從未被實際驗證過

### 1.2 風險

1. **未來首個 project 提案出現時**，可能錯投 `.agents/proposals/` 而非 `workspaces/<project>/proposals/`
2. **搬運到新專案**時，沒有自動化分離 / 保留機制；需人工判斷
3. **68 份歷史提案無摘要**：新 session 或新 LLM 需讀 ~25,000 行才能掌握脈絡
4. **混合 scope 無機械防護**：設計存在但未強制

### 1.3 觸發

- User 2026-04-24 提問「PROPOSAL 依賴過深 + 搬運風險」
- Session 內連續觀察到「設計有、執行未落地」模式（ff95f38 / validator 漏用 / 本案）

---

## 二、根因分析

- **設計先行但無 enforcement**：PROPOSAL_023 定規範但未配套 validator
- **手動流程易漏**：提案立案時靠 @Retro 記住放對位置
- **歷史摘要需求未被提出**：直到本次 session 積累到 68 份才浮現
- **機制驗證缺口**：未建立 project 提案時，缺乏真實場景測試

## 三、提案內容

### 3.1 Phase A：Scope Validator

- **新建**：`.agents/tests/proposal-scope-validator.mjs`
- 掃 `.agents/proposals/{active,completed,archived}/` → 所有 frontmatter `scope` 必須為 `framework`
- 掃 `.agents/workspaces/*/proposals/{active,completed,archived}/` → 必須 `scope: project`
- 違反 → exit 1 + 明確定位
- 納入 `run-all.sh` 第 11 個 validator（`proposal_scope`）
- 納入 `git-diff-detector.sh` fast-mode 觸發

### 3.2 Phase B：gen-proposal-index 雙區掃描

擴充 `gen-proposal-index.mjs`：

- 預設掃 framework（`.agents/proposals/`）
- 新增 `--workspace <name>` 模式掃 `.agents/workspaces/<name>/proposals/`
- 自動偵測 `CURRENT_WORKSPACE` 並連動更新兩個 INDEX
- 兩個 INDEX 獨立統計；避免混合

### 3.3 Phase C：gen-proposal-summary.mjs（新）

- **輸入**：`--period <2026Q2>`（季度）或 `--range <start:end>`（提案編號區間）
- **輸出**：`proposals/summaries/SUMMARY_<period>.md`
- **內容**：
  - Frontmatter（period / generated / range / total / major_bumps）
  - 概觀分類聚合（按主題 / scope / 優先級）
  - 關鍵變更（major bumps / 架構性提案 highlight）
  - 逐份 1 行摘要表
  - 跨提案主題鏈（自動識別「繼承」/「擴充」關係）
- **首次產出**：`SUMMARY_2026Q2.md`（涵蓋 PROPOSAL_20260420_001 ~ 20260423_015）
- 新建 `proposals/summaries/README.md`（索引）

### 3.4 Phase D：FRAMEWORK_REQUIREMENTS §6 搬運流程

擴充 `.agents/FRAMEWORK_REQUIREMENTS.md` §6：

- 搬運步驟：保留 framework proposals / 清 workspaces/
- 初始化新 workspace 流程
- 三種搬運模式（完整/精簡/極簡）

### 3.5 Phase E：RULES_DESIGN_GUIDE.SCOPE §十七 強化

補「執行時強制」章節：

- Scope 判定 3 步決策樹
- 儲存位置對照表
- 違規偵測（由 proposal-scope-validator 執行）
- 混合 scope 禁止

### 3.6 Phase F：retro.md §s06/§s07 scope SOP

- §s06 提案生命週期：補 scope 判定步驟
- §s07 目錄結構規範：補對照儲存位置表

### 3.7 Phase G：歷史分類稽核

- 一次性腳本掃全 68 份 completed/ 提案
- 驗證每份 `scope: framework` 正確
- 產出稽核報告（一次性；執行後刪）

### 3.8 Phase H：派生 + 索引 + 關閉

- agents-overview §1.2 / §6 更新
- FRAMEWORK_VERSION 微 bump（v5.0 → v5.1）
- 索引全同步
