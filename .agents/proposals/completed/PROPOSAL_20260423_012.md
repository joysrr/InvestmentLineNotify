## 一、問題描述

### 1.1 直接觸發事件

2026-04-24 session 中，LLM 代理（Claude）執行 PROPOSAL_010 立案時：

1. 手動 Edit `PROPOSAL_INDEX.md` 更新「最後更新日期 / OPEN 統計 / 新增 OPEN 條目」

3. Commit `ff95f38` push 到 remote
4. User 指出缺漏；後續驗證發現 3 處 stale 統計（DONE 62→63、CANCELLED 1→0、合計 65→67）
5. 額外發現：PROPOSAL_011 缺「基本資訊」區塊 → generator 無法解析 status（又一個被 LLM 忽略的細節）

### 1.2 歷史同類事件

追溯 git log，類似現象發生過：
- PROPOSAL_007 採納後，多次後續提案立案仍手動 Edit INDEX（未落實 generator 使用習慣）
- `RULES_VERSION_INDEX.md` 在 3+ 次 rules 版本調整時被手動 Edit，應由 `gen-rules-version-index.mjs` 處理

### 1.3 系統層問題

| 層級 | 問題 | 影響 |
|------|-----|-----|
| **工具** | 4 generators 缺 `<!-- AUTO-GENERATED -->` 標記 → `--write` 模式無法落地替換 | LLM 即使想用也不方便 |
| **流程** | `rule-update-proposal-template` / `retro.md` 未列「立案後必跑 generator」SOP | LLM 無明文依據 |
| **執行** | pre-commit hook 未檢「active/ 變動 + INDEX 未同步」 | 漏改不會被攔 |
| **監控** | periodic-design-review §7 無「SCRIPT_UNDERUSE」警示維度 | 漏用長期不被發現 |
| **工具品質** | `gen-proposal-index.mjs` 對 `**CANCELLED**` 粗體標記解析失敗 | 即使跑 generator 仍有 bug |

### 1.4 根本矛盾

- **LLM 偏好直接可見的動作**（Edit 文件）勝過間接工具調用（跑 generator）
- **工具未「低摩擦化」** → LLM 即使知道工具存在也會選擇手動
- **缺軟性強制**（pre-commit 攔截）+ **缺硬性 SOP**（明文要求）→ 雙重缺位導致漏用

### 1.5 目標

透過**四道防線**徹底解決 LLM 代理漏用 scripts 的系統問題：
1. **工具低摩擦化**：INDEX 類檔案加 AUTO-GENERATED 標記；`--write` 可真正 idempotent 替換
2. **流程明文化**：template / retro.md 加 SOP
3. **執行兜底**：pre-commit 加 INDEX_DRIFT 檢查
4. **長期監控**：periodic-design-review §7 加 #8 SCRIPT_UNDERUSE 警示維度

## 二、根因分析

### 2.1 LLM 代理行為根因

- **即時可見性偏好**：Edit tool 輸出立即可見；Bash tool 呼叫 generator 多一步且需解析 stdout
- **context 內工具發現成本**：4 generators 分散 `scripts/generators/`；LLM 每次要 ls 才想起
- **驗證閉環缺失**：手動 Edit 後沒人檢查是否等同 generator 輸出
- **`--write` 機制未落地**：即使 LLM 跑了 dry-run，看到輸出仍需手動抄回檔案 → 體驗差於直接 Edit

### 2.2 工具設計根因

- **PROPOSAL_007 採納時**重點放在「生成邏輯正確」；**未設計 idempotent 替換機制**（AUTO-GENERATED 標記）
- **gen-proposal-index.mjs 的 `--write`** 現行無標記區塊可替換 → 邏輯上無法實現；實質上成為「只能看、不能寫」的工具
- 生成器的 regex 對 markdown 粗體（`**CANCELLED**`）不魯棒

### 2.3 流程治理根因

- **PROPOSAL_007 採納時**未配套更新 template / retro.md SOP；採納後文化未落地
- **PROPOSAL_008 periodic-design-review** §7 有 7 個警示維度但無「工具漏用」維度
- pre-commit hook（PROPOSAL_019）覆蓋 frontmatter / 格式，未覆蓋「一致性」（active 與 INDEX 同步）

### 2.4 組織記憶根因

- LLM 代理**無跨 session 記憶**；即使 User 上次糾正過，新 session 仍可能重犯
- 需透過**機械性強制**（pre-commit）+ **文件明文**（SOP）取代「代理需記住」

### 3.1 第 1 道：AUTO-GENERATED 標記（工具低摩擦化）

#### 3.1.1 標記規格

在 4 個自動生成索引檔案新增標準標記：

```markdown
<!-- AUTO-GENERATED:BEGIN <block_name> -->
（generator 管理的內容；手動編輯會被覆蓋）
<!-- AUTO-GENERATED:END <block_name> -->
```

#### 3.1.2 適用檔案與標記位置

| 檔案 | 標記區塊 | 範圍 |
|-----|---------|-----|
| `proposals/PROPOSAL_INDEX.md` | `stats` | 統計摘要表 |
| `proposals/PROPOSAL_INDEX.md` | `open_list` | 🟡 OPEN 表格 |
| `proposals/PROPOSAL_INDEX.md` | `in_progress_list` | 🔵 IN_PROGRESS 表格 |
| `RULES_VERSION_INDEX.md` | `rules_versions` | 當前所有 rules/ 版本表 |
| `CHANGELOG.md` | `recent_versions` | 最近 10 個版本條目 |
| `FRAMEWORK_VERSION.md` | `current` | 當前版本號 + 衍生數據 |

#### 3.1.3 generator `--write` 實作

```js
// 新增 scripts/generators/lib/auto-generated-block.mjs
export function replaceAutoGeneratedBlock(fileContent, blockName, newContent) {
  const pattern = new RegExp(
    `(<!-- AUTO-GENERATED:BEGIN ${blockName} -->)([\\s\\S]*?)(<!-- AUTO-GENERATED:END ${blockName} -->)`,
    'g'
  );
  if (!pattern.test(fileContent)) {
    throw new Error(`Block marker not found: ${blockName}`);
  }
  return fileContent.replace(pattern, `$1\n${newContent}\n$3`);
}
```

4 個 generators 分別呼叫此 lib。

#### 3.1.4 手動編輯警告

在標記區塊之間加入**第一行警告註釋**：
```markdown
<!-- AUTO-GENERATED:BEGIN stats -->
<!-- ⚠️ 此區塊由 gen-proposal-index.mjs 管理；手動編輯會在下次執行時被覆蓋 -->
| 狀態 | 數量 | 目錄位置 |
...
<!-- AUTO-GENERATED:END stats -->
```

### 3.3 第 3 道：pre-commit 執行兜底

#### 3.3.1 既有 hook 擴充

在 `scripts/hooks/pre-commit`（PROPOSAL_019）新增 `INDEX_DRIFT` 檢查：

```bash
# -------- INDEX_DRIFT 檢查 --------
# 若 active/ 有變動但 PROPOSAL_INDEX 未同步 → 跑 generator 後 diff

STAGED_ACTIVE=$(git diff --cached --name-only | grep -E "^\.agents/proposals/(active|completed|archived)/" || true)
STAGED_INDEX=$(git diff --cached --name-only | grep -E "^\.agents/proposals/PROPOSAL_INDEX\.md$" || true)

if [ -n "$STAGED_ACTIVE" ] && [ -z "$STAGED_INDEX" ]; then
  echo "❌ INDEX_DRIFT: active/completed/archived/ 變動但 PROPOSAL_INDEX 未同步"
  echo "   執行：node .agents/scripts/generators/gen-proposal-index.mjs --write"
  echo "   然後：git add .agents/proposals/PROPOSAL_INDEX.md && git commit ..."
  exit 1
fi

# 若 INDEX 有變動，驗證是否與 generator 輸出一致
if [ -n "$STAGED_INDEX" ]; then
  GENERATOR_OUTPUT=$(node .agents/scripts/generators/gen-proposal-index.mjs --check 2>&1 || true)
  if echo "$GENERATOR_OUTPUT" | grep -q "DRIFT"; then
    echo "❌ INDEX 內容與 generator 輸出不一致"
    echo "   執行：node .agents/scripts/generators/gen-proposal-index.mjs --write"
    exit 1
  fi
fi
```

#### 3.3.2 generator 新增 `--check` 模式

每個 generator 支援第 3 模式：
- `<no flag>`：dry-run 顯示
- `--write`：實寫替換 AUTO-GENERATED 區塊
- `--check`：比對當前檔案內 AUTO-GENERATED 區塊是否等同 generator 輸出；不一致 exit 1 + 輸出 `DRIFT`

#### 3.3.3 緊急豁免

允許 `git commit --no-verify` 旁路（User 已知行為；但 periodic-design-review §7 #8 會計入「豁免次數」警示）。

### 3.5 Bug 修復：gen-proposal-index `**CANCELLED**` 解析

**根因**：regex `^-\s*狀態[:：]\s*(\w+)` 遇到 markdown 粗體 `**CANCELLED**` 開頭 `*` 非 `\w` 字元 → 匹配失敗 → fallback UNKNOWN。

**修復**：

```js
export function parseProposalStatus(content) {
  // 支援 markdown 粗體 + 斜體變體
  const match = content.match(/^-\s*狀態[:：]\s*\**(\w+)\**/m);
  return match ? match[1].toUpperCase() : 'UNKNOWN';
}
```

**單元測試**：
```js
// tests/gen-proposal-index.test.mjs
test('parseProposalStatus supports bold markdown', () => {
  assert.equal(parseProposalStatus('- 狀態：**CANCELLED**'), 'CANCELLED');
  assert.equal(parseProposalStatus('- 狀態：**DONE**（2026-04-24 執行完成）'), 'OPEN');
  assert.equal(parseProposalStatus('- 狀態：_DONE_'), 'DONE');
});
```

## 四、預期效益

### 4.1 量化

| 指標 | 現況 | 目標 | 估算依據 |

### 4.2 質化

- **LLM 行為校正**：從「選擇性使用工具」變「強制使用工具」；消除跨 session 記憶斷層問題
- **工具真正落地**：PROPOSAL_007 4 generators 從「只能 dry-run」升級為「能 idempotent 寫入」
- **信任提升**：INDEX 類文件不再需要人工審閱「數字是否最新」
- **Dogfooding 閉環**：007（generators）+ 008（periodic review）+ 019（pre-commit）三個既有提案首次組合落地

### 4.3 非目標（Non-Goals / Tradeoffs）

| 情境 | 處置 | 理由 |
|-----|------|-----|
| 禁止 LLM 代理任何手動 Edit INDEX 類檔案 | ⚠️ 部分允許 | 標記區塊外仍允許手動（如 §🔗 意圖繼承表）|

| 自動產生 PR 描述 / commit message | ❌ 不做 | 屬 LLM 職責範圍；非機械性 |
| 完全移除 `--no-verify` | ❌ 不做 | 保留緊急豁免；但計入警示 |
| 擴展至非 INDEX 檔案的 drift 檢查 | ⚠️ 延後 | 本提案聚焦索引類；其他檔案由 artifact-format-validator 處理 |

### 4.4 風險緩解貢獻

| 風險 | 緩解效果 | 說明 |
|-----|---------|------|
| LLM 跨 session 忘記使用工具 | 🟢 機械性強制 | pre-commit 攔截不依賴代理記憶 |
