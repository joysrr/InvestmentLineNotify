# PROPOSAL_502_028: Antigravity / 通用 latency 優化（Lite）

## 一、背景

User 反饋（2026-05-04）：Antigravity 思考時間久。框架側分析識別 5 個阻塞點；其中 4 個容易優化。

**前 3 sprint 已優化的成本面**（PROPOSAL_502_022 + 023）：

- ✅ Token cost：每 dispatch -25-35%
- ✅ Search limit：5 → 3
- ✅ Skip @Architect for simple lane

**本提案優化 latency 面**（不變 token；改執行模式）：

- O-1 並行 cold-start tool calls（單 message batch）
- O-2 派發前 batch tool calls（讀 PENDING / grep / search 同 message）
- O-3 task_class={doc-sync, config-adjust} 跳 mempalace.search（已 simple；不需 prior context）
- O-4 mempalace.search 預設 limit=1；不足才 follow-up limit=3

## 三、Functional Safety 檢查

| 優化                        | 是否影響功能 | Mitigation                                                                                                      |
| --------------------------- | :----------: | --------------------------------------------------------------------------------------------------------------- |
| O-1 並行 cold-start         |  ❌ 不影響   | tool calls 獨立（status / 多 Read / LS）；無順序依賴                                                            |
| O-2 派發 batch              |  ❌ 不影響   | reads 獨立；grep 與 search 各自輸入                                                                             |
| O-3 simple lane skip search |   🟡 邊界    | doc-sync / config-adjust 本就「簡單改動」；ADR-0014 Prior Art Scan 觸發條件不變；agent 可手動 search 若覺得需要 |
| O-4 limit=1 default         |   🟡 邊界    | top-1 cosine ≥ 0.4 即足；< 0.4 自動 follow-up limit=3；行為等價                                                 |
