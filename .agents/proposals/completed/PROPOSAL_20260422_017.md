## 一、問題描述

**根因分類**：`REQ`（PROPOSAL_011 建立時聚焦基本 PII，GDPR 進階條款未涵蓋）

@Auditor 第二次評審：**4.3 法規隱私對齊 = 4.5/5**。缺口：

- GDPR Article 33：資料外洩通知（72 小時義務）— **未定義**
- GDPR DPA：資料處理協議（第三方如 Telegram Bot API）— **未定義**
- GDPR Article 44：跨境資料轉移許可 — **未定義**
- 當前加密實況：`AES-256 標註「未來若新增支付相關」`，暗示當前未全面加密

## 二、根因分析

- **現況**：privacy-compliance.md 五區塊聚焦「資料類別 + 刪除權 + 審計日誌」
- **缺口**：**後處理**條款（外洩後如何處理、跨域如何合規）未涵蓋
- **影響**：若專案擴展至歐盟使用者，當前政策無法滿足 GDPR 審計

## 三、提案內容

### 3.1 domains/privacy-compliance.md 新增 §六（72h 外洩通知）

```markdown
## 六、資料外洩通知流程（GDPR Article 33）

發現資料外洩後必須：

1. **0~4 小時**：`@Lead` 確認外洩範圍 + 影響使用者數量
2. **4~24 小時**：`@Security` 產出 `SECURITY_REPORT.md` 含：
   - 外洩類型（身份 / 資產 / 行為 / 配置）
   - 影響 user_id 清單（雜湊化）
   - 推測原因（內部洩漏 / 外部攻擊 / 系統故障）
3. **24~48 小時**：通知受影響使用者（Telegram Bot 推送）
4. **48~72 小時**：向主管機關備案（台灣個資法 § 12 / GDPR Art. 33）
5. **72 小時內完成**：所有上述步驟；逾期視為合規違反

### 觸發條件

- 發現 `data/audit_log.jsonl` 異常存取
- 外部情資告警（如 Telegram Bot API Key 洩漏）
- 使用者主動回報
```

### 3.2 新增 §七（DPA）

```markdown
## 七、資料處理協議（DPA）

本專案與第三方服務的資料處理責任：

| 第三方            | 處理資料類型                 | DPA 狀態                 | 處理依據     |
| ----------------- | ---------------------------- | ------------------------ | ------------ |
| Telegram Bot API  | user_id / chat_id / 訊息內容 | Telegram ToS（視為 DPA） | 服務執行必要 |
| Google Sheets API | strategyWeight 同步          | Google Cloud DPA         | User 同意    |
| Google Gemini API | 訊號分析內容                 | Google AI DPA            | User 同意    |
| Langfuse          | AI 呼叫觀測日誌              | Langfuse DPA（需確認）   | 運維必要     |

### 執行條款

- 新增第三方服務 → `@Security` SC-09 + SC-11 雙審查
- 缺 DPA 或無法確認合規時 → 禁止啟用
```

### 3.3 新增 §八（跨境轉移）

```markdown
## 八、跨境資料轉移許可

當前系統資料存儲位置：

- **熱資料**：Oracle VM（需確認 region；若在歐盟外需 SCC 標準條款）
- **溫資料**：同上
- **第三方**：Telegram（全球）、Google Cloud（依設定）

### 合規路徑

- 若 user 位於歐盟 → 需 SCC（Standard Contractual Clauses）
- 若 user 位於中國 → 需符合《個人信息保護法》跨境要求
- 若 user 位於台灣 → 預設合規（境內儲存）

### 當前狀態

⚠️ **限制**：目前本專案僅支援台灣境內用戶；跨境擴展需先完成 SCC 簽署。
```

### 3.4 新增 §九（當前加密現狀）

```markdown
## 九、當前加密現狀與升級路徑

### 當前狀態（2026-04-22）

- **靜態加密**：❌ 未啟用（所有 `data/*.json` 明文儲存；依賴 Oracle VM OS 權限）
- **傳輸加密**：✅ HTTPS 強制（Telegram Bot API / Google Cloud）
- **備份加密**：❌ 未啟用

### 升級路徑

1. **短期**（本 Sprint）：`data/users.json` + `data/strategy_user.json` 使用 `crypto.createCipheriv` AES-256-GCM 加密
2. **中期**（下 Sprint）：所有 `data/*.json` 全面加密
3. **長期**：導入 KMS（Key Management Service）集中管理金鑰

### 禁止

- **絕對禁止** 支付 / 信用卡相關資料未加密即儲存
```
