## 一、問題描述

### 1.1 現況

`rules/RULES_DESIGN_GUIDE.md` 當前 **1056 行 / 20 章節**（§一 ~ §二十），對應 ~10,000 tokens 單檔。章節內容性質高度異質：

| 性質分類                                         | 涉及章節                                 | 占比 |
| ------------------------------------------------ | ---------------------------------------- | ---- |
| 設計形式（rule/template 結構、脈絡、約束、通知） | §一、§三、§五、§六、§九                  | ~28% |
| 範圍治理（scope/版本/維護/分層）                 | §十一、§十二、§十五、§十六、§十七、§二十 | ~37% |
| 品質與量化（token/HITL/DoD/閾值/Hotfix/scan）    | §二、§四、§七、§八、§十四、§十八、§十九  | ~35% |

### 1.2 觀察到的問題

1. **定位檢索困難**：一個 1056 行單檔使得「查 Token 預算」與「查 Hotfix」混雜同一檔；LLM 讀取全量既浪費又稀釋注意力
2. **版本變動頻繁但粒度粗**：任何章節微調都動整檔 `version`，後續提案語意繼承難以判斷「影響的是哪一面向」
3. **periodic-design-review §7 警示維度 #6**：明列「單檔 rules/ ≥800 行」屬結構警示；1056 行已越界
4. **@DocsCurator 負擔沉重**：每次更新需完整 `Read` → 效率低
5. **自我應用缺失**：`PROPOSAL_20260423_004`（文件分層三原則）是 RULES_DESIGN_GUIDE 自身提出的；本文件卻未用其原則對自己
6. **預期未來增長**：PROPOSAL_20260423_010 的 §二十一「提案輕重分級」尚未納入即將再長 ~120 行；不拆檔將持續膨脹

### 1.3 目標

將 RULES_DESIGN_GUIDE 拆分為 **1 個 orchestrator + 3 個主題子檔**，分層降噪、版本獨立、檢索友善，同時 **保持既有提案引用不失效**（相容）。

## 二、根因分析

### 2.1 主觀根因

- **歷史堆疊**：20 章節自 v1.0 逐步增生；每次提案新增一章的最小衝擊選擇 → 累積成巨檔
- **缺拆檔觸發機制**：直到 2026-04-23 PROPOSAL_008 才設 800 行警示；早期無量化閾值
- **拆檔成本錯覺**：擔心「破壞 60+ 歷史提案引用」實際上透過 anchor/section 映射即可兼容

### 2.2 結構根因

- **單 `version` 線性模型**：無法表達「DESIGN 穩定但 QUALITY 微調」
- **§🔗 意圖繼承表單檔範圍**：繼承表跨 20 章，追蹤某章節的前置較模糊
- **缺子檔模式前例**：rules/ 下尚無「主檔 + 主題子檔」先例；`agents-overview.md` 為獨立檔、`SECURITY_POLICY.md` 亦獨立；未形成模式

### 2.3 動機根因

- **自我應用**：`PROPOSAL_004` 三原則（視角分層 / 依賴方向 / 粒度一致）正是本次拆檔的指導框架 → 未用於自身屬設計債
- **periodic-design-review 目標 1**：User 已要求定期審視過度設計；拆檔是首次正面響應 ≥800 行警示

### 2.4 為何此時動？

| 觸發                                           | 狀態          |
| ---------------------------------------------- | ------------- |
| 本文件 ≥800 行警示                             | 🟡 已達 1056  |
| periodic-design-review 機制就位（008 已採納）  | ✅            |
| 文件分層原則已成熟（004 已採納）               | ✅            |
| 自動化 generators 可承受索引變更（007 已採納） | ✅            |
| 010 即將再加 §二十一 ~120 行                   | 🟠 不拆將更重 |

4 信號全集結 → 時機成熟。

| 指標                                   | 現況          | 目標                          | 估算依據                         |

### 4.2 質化

- **自我應用**：首次將 PROPOSAL_004 文件分層三原則用於本文件自身 → 驗證原則普適性
- **LLM 注意力集中**：一次 Read 只載入對應 subject，降低 context 稀釋
- **章節新增決策清晰**：新章節即知落何子檔（DESIGN / SCOPE / QUALITY 三選一）
- **歷史相容**：60+ 歷史提案引用不失效（相容層 + 1 年 DEPRECATED 窗口）
- **版本語意化**：`QUALITY v1.3` 明確表達只動品質章節；不再「整檔 bump version」

### 4.3 非目標（Non-Goals / Tradeoffs）
