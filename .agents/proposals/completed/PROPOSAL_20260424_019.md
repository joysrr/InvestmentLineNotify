## 一、問題描述

本提案源自 2026-04-24 單 session 完成 017 + Phase F.3 + 018 後的 retro，收錄 4 項實質缺失（F-1 ~ F-4）對應的改善行動。

### 1.1 F-1：純函式雙向測試覆蓋不足

`selectTechStacks` 在 017 Phase C 只實作 drop 方向（`installed: true → false`），遺漏 keep 方向（`false → true`）；unit test 只覆蓋 `answerMatchesAvailableStacks` 純查找函式，未測 state mutation → bug 存活到 018 設計討論才曝光。

**暴露週期**：017 完成（4-23）→ 018 設計（4-24）≈ 1 天；若非 User 主動詢問，可能更久。

### 1.2 F-2：Phase tracking 與驗收 checklist 追蹤維度打架

018 Phase E 完成後，我（agent）在 User 問「接下來」時，心智模型從「todo phase 進度」切到「驗收條件比對」，漏掉「Phase F 仍 pending」的事實；最終 Phase F 還是被完成（commit `79262fa`），但當下交付對話錯誤地把「補齊 3 個驗收缺口」當成「批次收尾」。

**根因**：todo list 沒有明示「phase 進度」與「驗收條件」是兩個獨立維度。

### 1.3 F-3：Schema 變更未預警連鎖反應

018 Phase A 加 2 個 TECH_STACK 欄位後，Phase B 執行 smoke test 時 success path 失敗（41 行 piped input 與新欄位數不匹配）。`WORKSPACE_SCHEMA.yaml` 目前沒有欄位屬性區分「互動問答 / 系統自動填 / 衍生欄位」，新增任何欄位都默認走 `collectAnswers` 互動迴圈 → 需要 ad-hoc skip 邏輯。

### 1.4 F-4：骨架建立時機過早

017 Phase F.2 建 `semi-avalonia/` 骨架時 vendor docs 未到手。User 後續提供文件**全為 React 版**，骨架與實際 vendor 性質不符；最終走 Phase F.3 WebFetch 自行擷取 irihitech 文件補齊。

**根因**：skill `tech-stack-onboarding.md §4.2` 未要求「先 WebFetch 確認 vendor 定位」；假設 User 提供的文件一定符合 tech-stack 類型。

### 3.2 Phase B：F-1 純函式雙向單元測試（P1；~30 分）

**背景**：017 Phase C 的 `selectTechStacks` 已於 018 Phase B 抽出純函式 `applyTechStackChoices`（✅ 已做），但**未補單元測試**。

**行動**：

- `tests/scripts/unit.test.mjs` 追加 `applyTechStackChoices` 測試組（4 cases）：
  1. `keep-direction`：未安裝的 stack 選中 → MANIFEST text 翻 `installed: true`
  2. `drop-direction`：已安裝的 stack 未選 → MANIFEST text 翻 `installed: false`
  3. `drop-with-deps`：移除被依賴的 stack → 依賴方應被跳過（未來可擴充）
  4. `restore-missing-file`：stack 檔案缺失時 → `toActivate.fileStatus` 標為 `restored@<commit>` 或 `missing:no-history`
- 同時為 `updateManifestInstalledFlag` / `deriveTechStackAnswersFromStacks` 各補 1-2 cases
- 預期：unit tests 46 → ~52（6 新 cases）

**新增規則寫入 RULES_DESIGN_GUIDE**（§九 測試準則或 §十 雙向邏輯驗證）：

> 任何「狀態雙向翻轉」純函式（例：installed true↔false、status enable↔disable）**必須**補單元測試雙方向；單向測試視為覆蓋不足。

### 3.3 Phase C：F-2 Phase tracking 與驗收分離規範（P2；~20 分）

**行動**：

- `rules/lead.md §任務派發` 或 `skills/stateless-routing-pattern.md` 新增「雙維度追蹤」要求：

```markdown
### Phase 進度 vs 驗收 Checklist 雙維度

每個提案執行過程**同時追蹤**：

1. **Phase 進度**（透過 TodoWrite / 手動 checklist）：當前在哪個 phase；下一 phase 是什麼
2. **驗收條件對齊**（提案 §驗收條件 逐項）：每項是否已 done

**鐵律**：

- 當 User 問「接下來應該做什麼？」時，**必先朗讀當前 Todo 狀態 + 未完成 Phase 清單**，再判斷
- 禁止只以「驗收條件比對」推導下一步而忽略 Phase 進度
- 若兩維度打架（例：驗收 100% 但 Phase 未關閉）→ 以 Phase 進度為準（驗收條件是結果驗證，Phase 是流程控制）
```

- 可選：`skills/` 新增小型 `dual-tracking-checklist.md`（若規則內容 ≥ 20 行）

### 3.4 Phase D：F-3 Schema `interactive` 屬性（P2；~40 分）

**WORKSPACE_SCHEMA.yaml 欄位屬性擴充**：

```yaml
# v1.3 → v1.4
TECH_STACK:
  language:
    type: string
    required: true
    interactive: true # 預設；可省略
    description: "..."
  last_audit_date:
    type: string
    required: false
    interactive: false # 新屬性：不進 collectAnswers 互動迴圈
    auto_populate:
      source: system # 或 derive_from_stacks / default
      value: today # 系統值；也可寫 default: "30"
    description: "..."
  audit_interval_days:
    type: integer
    required: false
    interactive: false
    auto_populate:
      source: default
      value: 30
    description: "..."
```

**collectAnswers 修改**：

- 讀欄位時檢查 `interactive`；false → skip（不問 User）
- 迴圈結束後 → 依 `auto_populate.source` 注入：
  - `system` + `value: today` → 今日日期
  - `default` → 直接用 value
  - `derive_from_stacks` → 呼叫 `deriveTechStackAnswersFromStacks`

**workspace-schema-validator 擴充**：

- `interactive: false` 的欄位**必**有 `auto_populate` 區塊；否則 error
- `auto_populate.source` 限制在 `[system, default, derive_from_stacks]`；其他 → error

**schema_version bump**：v1.3 → v1.4
