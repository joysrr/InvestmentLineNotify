## 一、問題描述

### 1.1 User 檢視結論（2026-04-23）

> 「Hotfix 流程或許過設計：已從 3 步驟擴展到 5 步驟；真正的緊急情況下，5 步驟可能拖延處理時間；建議按事故等級分輕重（簡單 hotfix 維持 3 步；複雜 hotfix 用 5 步）」

### 1.2 現況盤點

當前（PROPOSAL_20260423_003 執行後）Hotfix Fast Lane 流程：

| Step     | 內容                                            | 時間估算       |
| -------- | ----------------------------------------------- | -------------- |
| Step 0   | @Lead 上下文注入 + SC 評估 + 診斷組評估         | ~5 min         |
| Step 1   | 診斷階段（五步 SOP；診斷組共識）                | ~20-40 min     |
| Step 2   | 修復實作 + 審查（@Reviewer + 條件式 @Security） | ~15-30 min     |
| Step 3   | @QA 核心路徑驗證                                | ~10 min        |
| Step 4   | @Lead Hotfix Gate Check 4 條件                  | ~5 min         |
| **總計** |                                                 | **~55-90 min** |

### 1.3 問題：一刀切的代價

| 事故類型                                          | 所需流程完整度 | 當前流程時間 | 時效損失            |
| ------------------------------------------------- | -------------- | ------------ | ------------------- |
| 簡單事故（單模組 + 首次 + diff < 50 LOC + 非 SC） | 3 步驟足夠     | 55-90 min    | 🔴 ~40 min 過度流程 |
| 複雜事故（D1-D4 任一 / SC 任一）                  | 5 步驟必要     | 55-90 min    | 🟢 合理             |

### 1.4 典型「過度流程」案例（User 體驗視角）

**情境**：生產環境某個 cron job 因路徑 typo 未觸發（單檔 + 1 行 diff + 首次 + 非 SC）

**當前 5 步驟流程**：

- Step 0：@Lead 讀 workspace CRITICAL_PATHS / DEPLOYMENT_CONSTRAINTS / BUSINESS_RULES / tech-stacks → 5 min
- Step 1：@Backend 五步診斷 SOP（現象 / 重現 / 二分 / 假設 ≥ 2 / 影響範圍）→ 20 min（for 1-line typo 過度）
- Step 2：@Backend 修復 + @Reviewer 快速審查 → 15 min
- Step 3：@QA 核心路徑驗證 → 10 min
- Step 4：Gate Check 4 條件 → 5 min
- **總計 ~55 min for 1-line typo**

**合理簡化流程**（PROPOSAL_20260422_026 原始 3 步驟）：

- Step 1：@Backend 定位並修復 → 10 min
- Step 2：@Reviewer 限縮範圍快速審查 → 5 min
- Step 3：@QA 核心路徑驗證 → 5 min
- **總計 ~20 min**

**差距**：~35 min / 事故（~64% 時間節省對簡單事故）

### 1.5 風險「不處理」

- User 遇到真正緊急但簡單的事故時，5 步驟流程可能被視為繁瑣 → 可能傾向 bypass 流程（損失既有資安 / 品質保證）
- 或 User 正常執行 5 步驟 → 生產停機時間延長 → 業務損失
- 同類型事故未來必會重複發生（cron typo / 路徑錯字 / API key 過期等）

```markdown
### G. Hotfix 輕重分級（依 PROPOSAL_20260423_009）

| 🟢 light | 無 D1-D4 + 無 SC + diff ≤ 50 LOC + 單檔       | 3 步驟（@Backend 修復 → @Reviewer 審 → @QA 驗）                    | typo / 路徑錯字 / 單行配置修正                    |
```

5. 全部 OK → light 啟用

