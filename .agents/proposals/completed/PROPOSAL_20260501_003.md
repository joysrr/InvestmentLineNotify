## 一、問題

### 1.1 三軸框架 vs 當前狀態

| 軸                      | 解決什麼                              | ADR                  | 狀態                                   |
| ----------------------- | ------------------------------------- | -------------------- | -------------------------------------- |
| Mutable 縮減            | rule 內容如何 slim-down（4 patterns） | ADR-0036             | ✅ 完成                                |
| Immutable 治理          | 跨切不可變鐵律 first-class            | ADR-0037             | ✅ 完成（PROPOSAL_002）                |
| **Mutable budget 量化** | **rule 該佔多少 token（tier 判定）**  | **ADR-0038（待建）** | ❌ **缺**；當前靠 11 exception flag 補 |

第 3 軸的缺位導致：

- exception flag 是補丁；無 schema-level 治理
- rules 雙標：worker（單一職能）vs orchestrator（跨 Agent 協調）密度不同，但 budget 都是 1000
- exception_reason 自由文字；無強制 schema；可被濫用

### 1.2 量化現狀（after PROPOSAL_002 + Phase H + Item 3）

13 rules tokens 落點：

- system-prompt 491（meta）
- consultant 961 / auditor 699 / reviewer 1305 / frontend 1368 / security 1367 / architect 1473 / backend 1460（worker 範疇）
- retro 1233 / planner 1373 / qa 1389 / assistant 1428 / lead 1724（orchestrator 範疇）

11 個 exception flag 散布：assistant / backend / frontend / retro / planner / security / lead / architect / reviewer / qa（10）— exception 是技術債，不是治理。

## 二、設計

### 2.1 新增 rule_category 維度

frontmatter 加新欄位（必填；ADR-0022 schema 升級）：

```yaml
rule_category:
  enum:
    - meta # 全局 always_on（system-prompt）
    - worker # 單一職能（單一 artifact 產出 / 單一審查維度）
    - orchestrator # 跨 Agent 協調 / 流程派發 / 多狀態管理
```

### 2.2 4 條判定原則（採納後寫入 ADR-0038）

判定 orchestrator 條件（任一）：

1. **Cross-Agent 派發職責**：rule 內含派發、Gate Check、收斂等多 Agent 協調動作
2. **多階段流程管理**：rule 規範 ≥ 3 個工作流階段或狀態流轉
3. **跨時序整合**：rule 跨多個工作對話 / Sprint 累積分析（如 retro 審計）
4. **Hub 性質**：成為其他 Agent 訊息流的中介點（如 PENDING_ACTIONS 集散）

不滿足任一 → worker（單一職能）。

判定 meta：file_type=always_on 自動 meta；無例外。

### 2.3 Tier-based budget table

| rule_category  | warn budget | block budget | 適用 file_type |
| -------------- | ----------- | ------------ | -------------- |
| `meta`         | 500         | 1000         | always_on      |
| `worker`       | 1500        | 2500         | agent_rule     |
| `orchestrator` | 1800        | 3000         | agent_rule     |

設計依據：

- meta=500：當前 system-prompt 494；嚴格但可達
- worker=1500：當前 worker max（architect 1474）+ 緩衝；緊但不卡
- orchestrator=1800：當前 orchestrator max（lead 1724）+ 緩衝；反映實際密度
