解 closed-list keyword paradigm 結構性 SPOF。

## 設計核心（ADR-0042 新建）

**三層判定機制（順序短路）**：

```
判定 task_class / refactor-keyword 觸發等：

層 1：結構訊號優先（最高 priority；無 LLM 成本）
  - 無 .agents/CURRENT_WORKSPACE → 強制 task_class=onboarding
  - touched_files 全為新檔（git status -u "??") + 既有 src/ 結構 → 強制 task_class=feature
  - touched_files 含 git rename detection (git diff -M50%) → 強制觸發 refactor-keyword

層 2：closed-list keyword 快車道（中 priority；零 LLM 成本）
  - §6.3.1 priority 1-7 list（v7.14 既有）
  - §C.5 4+1 觸發條件（v7.15 既有）
  - 命中 → 直接決定；不進層 3

層 3：LLM-classifier fallback（layer 1+2 全 miss 時觸發）
  - @Lead 派發前呼叫 mcp 或 inline llm（haiku 等小型 model）
  - prompt 「依下面指令推導 task_class（5 enum）+ 是否 refactor 性質」
  - 結果寫 ROUTING_TICKET frontmatter `task_class_source: llm_classifier`（audit 用）
  - 若 LLM 仍模糊 → fallback feature + 標 `intent_ambiguous: true` 提示 user 確認
```
