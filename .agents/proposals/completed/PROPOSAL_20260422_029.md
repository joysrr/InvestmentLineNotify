## 一、問題描述

當前 rules frontmatter 採用 `!ref` 標記引用 RULES_DESIGN_GUIDE / SYSTEM_THRESHOLDS.yaml 的具體欄位：

```yaml
constraints_ref:
  review_cycle_limit: !ref RULES_DESIGN_GUIDE.md#REVIEW_CYCLE_LIMIT
  audit_min_score: !ref RULES_DESIGN_GUIDE.md#AUDIT_DIMENSION_MIN_SCORE
```

無自動驗證工具會偵測：
1. `!ref` 指向的 anchor 是否實際存在於目標檔案
2. 是否有循環引用
3. 目標檔案被刪除 / 重命名後 `!ref` 指向是否失效

## 三、提案內容

### 3.1 擴充 schema-validator.mjs（或 workspace-schema-validator.mjs）

```javascript
// 解析所有 .agents/rules/*.md 與 .agents/skills/*.md 的 frontmatter
// 抽取 constraints_ref / references 等含 !ref 標記的欄位

// 對每個 !ref 進行：
// 1. 解析格式：!ref <file>#<anchor>
// 2. 檢查 file 存在
// 3. 檢查 anchor 在 file 中可定位（grep "^# <anchor>$" 或 ID 標籤）
// 4. 循環引用偵測（DFS）

// 退出碼：
// 0 = 全部 !ref 有效
// 1 = warning（anchor 模糊但可能對應）
// 2 = error（檔案不存在 / anchor 無法定位 / 循環引用）
```

### 3.2 anchor 解析規則

支援三種 anchor 格式：
1. `RULES_DESIGN_GUIDE.md#十四` → 章節「十四、系統參數配置」
2. `RULES_DESIGN_GUIDE.md#REVIEW_CYCLE_LIMIT` → §十四 內的具體參數名
3. `SYSTEM_THRESHOLDS.yaml#review_cycle_limit` → YAML 頂層 key
