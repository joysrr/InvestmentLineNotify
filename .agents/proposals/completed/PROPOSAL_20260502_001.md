# PROPOSAL_20260502_001: MemPalace 全面整合

## 四、Wings/Rooms/Drawers 對應設計（A-3 預定）

```
Framework-level (.agents/memory_palace/):
  Wings:
    framework         ← framework-wide knowledge

  Rooms (per Wing):
    architecture      ← 對應原 architecture room
    strategy_context  ← 對應原 strategy_context room
    debug_graveyard   ← 對應原 debug_graveyard room
    [ extensible: add more rooms as needed ]

  Drawers:
    [auto-mined from conversations + manual entries]


Workspace-level (.agents/workspaces/<ws>/memory_palace/):
  Wings:
    <workspace_id>    ← per-project organization

  Rooms:
    [same 3 default rooms; user may add custom rooms per workspace]

  Drawers:
    [project-specific entries]
```

## 五、初始化檢查（A-7）

`init-workspace.mjs` 啟動時執行：

1. **Python 3.9+ 驗證**: `python3 --version`
2. **MemPalace 安裝驗證**: `pip show mempalace` （≥ 3.3.4）
3. **MCP server 註冊驗證**: `.mcp.json` 含 mempalace block
4. **MemPalace init**: `mempalace init <path>`（per workspace）
5. **首次採礦**: `mempalace mine <path>`（從現有 markdown）
6. **Wake-up 測試**: 模擬 @Lead 派發查詢
7. **健康指標**: drawer count / room count / latest mine timestamp
8. **User 通知**: 「Memory Palace ready; X drawers indexed; MCP server alive」

任一步失敗 → fallback markdown filesystem mode + 警告 User。

## 七、風險

| 風險              | 緩解                                   |
| ----------------- | -------------------------------------- |
| Python 環境衝突   | 使用 venv；FRAMEWORK_REQUIREMENTS 明文 |
| ChromaDB 損毀     | 定期 dump；re-mine from markdown       |
| MCP server 不啟動 | hybrid fallback markdown               |
| 採礦結果失準      | 第一次 mine 後手動 review              |
| 版本升級 breaking | 鎖 `mempalace==3.3.4`；upgrade 走提案  |

## 八、不採納時影響

維持當前 markdown filesystem Memory Palace；強耦合風險仍在；手工維護成本累積。
