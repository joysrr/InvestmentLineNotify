# PROPOSAL_502_034: GitNexus B1+B5+B2 深度整合

User profile 確認：

- 跨檔關聯（前↔後端）= 高頻
- 單檔破千行 = 常態

→ GitNexus sweet spot 命中；月省保守 7-12 小時；值得從「外部輔助」升級為「半自動整合」。

## 三、B1 偵測場景（lead.md auto-suggest）

派發前（既有 4 探測 batch 不變）；4 探測完後加**輕量 5 探測**（純 grep；不耗 IPC）：

```
場景觸發條件（任一命中 → ROUTING_TICKET.gitnexus_hint 寫入）：
1. task_class ∈ {feature, modify-existing} + touched_files ≥ 3
2. touched_files 含跨技術棧（如 .ts + .py 混合）
3. touched_files 任一檔 LOC > 800（grep -c）
4. User 指令含 keywords：refactor / rename / impact / "找出所有使用" / 跨檔
5. task_class = feature + touched_files 含 frontend + backend 路徑
```

**寫入內容**：

```yaml
gitnexus_hint:
  triggered_by: "cross-stack" | "large-file" | "refactor-keyword" | "multi-file"
  suggested_query: "gitnexus impact <symbol>" / "gitnexus context <file>"
  fallback: "若 GitNexus disabled → 走 Prior Art Phase B（user 自跑 + 回填）"
```

## 四、B5 Reviewer Stage 6 預設提示

`reviewer.md §s06` 加 1 條 checklist：

```
4. **跨檔 / 千行檔 review**（PROPOSAL_502_034 B-5）：
   - PR diff touched_files 含千行檔 / cross-stack → 必查 caller graph
   - GitNexus available → 直呼 `mcp__gitnexus__impact(symbol=<changed_function>)`
   - GitNexus unavailable → grep + 在 REVIEW_REPORT 標 [INFO] 「caller scan 不完整」
```

## 五、B2 執行期 agent 直呼（ADR-0041 鐵律 3 amend）

### 原鐵律 3（v1）

> 派發前 batch 不加 GitNexus

### Amended 鐵律 3（v2）

| 階段                               | GitNexus 使用     | 理由                                               |
| ---------------------------------- | ----------------- | -------------------------------------------------- |
| **派發前 batch（4 探測）**         | ❌ 不加           | 維持低 latency；多數 dispatch 不需要               |
| **執行期間（agent 接到 task 後）** | ✅ 場景命中可直呼 | 千行檔 / cross-file impact 高頻；user-paste 變瓶頸 |
| **重大 refactor / 5+ 檔 rename**   | ✅ 必呼           | 風險評估必要                                       |
| **Hotfix / typo / config-adjust**  | ❌ 仍不必         | 場景不符                                           |

### B2 觸發條件（agent 自主判斷；執行期）

```
agent 在 Stage 5 / 6 / refactor 時：
  IF GitNexus MCP available AND scenario in {refactor, cross-file impact, 千行檔 navigation}:
    直呼 mcp__gitnexus__{impact, context, cypher}
  ELSE:
    退回 grep / Read 並在 ROUTING_TICKET status 標 "gitnexus_unavailable"
```

## 六、B1 + B2 共存解（避免重複）

派發前 B1 寫 hint；執行期 agent 接到 task 後：

1. 讀 ROUTING_TICKET `gitnexus_hint` → 知場景命中
2. 檢測 GitNexus MCP 可用性（`mcp__gitnexus__list_repos` 失敗 = unavailable）
3. **available** → 直呼 GitNexus tools（B2 路徑）
4. **unavailable** → 走 Prior Art Phase B（提示 user 自跑 + 回填；B1 fallback 路徑）

→ B1 是「萬一 disabled」的退路；B2 是「available 時主動」的快路。**沒有重複**。
