## 一、問題描述

### 1.1 第一問現象（skills/tasks 專案特化不一致）

User 2026-04-23 確認需求後識別以下現況：

| 目錄 | 專案特化引用機制 | 覆蓋率 |
|-----|-----------------|-------|
| `tech-stacks/` | ✅ 8/8 含 §專案特化參照 + MACHINE_READABLE anchor（PROPOSAL_022 Phase B）| 100% |
| `skills/` | ⚠️ 部分引用 workspace（如 `concurrency-guard-pattern` 引 `PATHS.source_modules.concurrency`）但格式不統一 | ~21% |
| `tasks/` | ⚠️ 部分 task 流程內含隱式 workspace 引用（如 `project-onboarding`）但無結構化聲明 | ~40% |

**問題**：
- `RULES_DESIGN_GUIDE §十六` 三分法純淨原則僅針對 tech-stacks，skills/tasks 缺對應規範
- `workspace-schema-validator.mjs` 僅驗證 tech-stacks 的 `referenced_by`，skills/tasks 無驗證
- 若 skill 有專案特化需求（如 `consultant-bypass-rules` 需引用 workspace `BUSINESS_RULES`）無統一格式

### 1.2 第二問現象（多專案並行下 .agents/ 版本同步缺機制）

User 採用**方案 B**（每個專案獨立部署 `.agents/`）情境下：
- 目前無 `.agents/` 框架整體版本識別（僅有各 rules 文件個別版本）
- 無標準化升級 SOP；User 需手動比對兩份 `.agents/` 的差異
- 無工具輔助 diff；大型變更（如 PROPOSAL_022+023 重構）易遺漏部分檔案同步

**具體案例**：
- 假設 User 同時開發 IMN + ProjectX + SaaS 三個專案，各有一份 `.agents/` 副本
- 今日 PROPOSAL_026 在 IMN 的 `.agents/` 執行完畢
- 希望同步至 ProjectX 與 SaaS 的 `.agents/` 副本
- 當前：手動 `diff -r` 比對 + 人工判斷哪些檔案屬於「框架層」（跨專案）vs「專案層」（如 `workspaces/<project>.md`）

### 1.3 量化影響

| 問題類型 | 具體風險 |
|---------|---------|
| skills/tasks 格式不一致 | @Auditor 2.1 模組化保守評估（當前 4.5）；未來新手 Agent 查詢困難 |
| workspace-schema-validator 覆蓋不全 | 只驗 tech-stacks 的 referenced_by；skills/tasks 的專案特化斷鏈無偵測 |
| 無 FRAMEWORK_VERSION | 多專案並行時版本 drift 無法察覺 |
| 無升級 SOP | 每次升級都是「從零開始」人工操作；易漏 |
| 無 diff 工具 | 框架變更（新檔 / 修改 / 刪除）手動識別成本高 |

### 3.5 Part 5：新建 `.agents/scripts/framework-diff.mjs`

#### 3.5.1 設計目標

- **純 Node.js**（無 npm 依賴；可用內建模組）
- **零網路依賴**（比對本地兩個 `.agents/` 目錄）
- **明確區分框架層 vs 專案層**
- **輸出結構化 diff 報告**供 User 人工審視決策

#### 3.5.2 框架層 vs 專案層檔案清單

```yaml
# framework_layer（跨專案資產；升級時應同步）
framework_layer:
  - rules/*.md
  - skills/*.md
  - tech-stacks/*.md
  - domains/*.md
  - tasks/*.md
  - tests/*.mjs
  - tests/*.sh
  - scripts/*.mjs
  - proposals/completed/*.md  # 歷史紀錄（唯讀）
  - proposals/archived/*.md
  - RULES_DESIGN_GUIDE.md
  - RULES_METADATA_SCHEMA.md
  - RULES_VERSION_INDEX.md
  - SYSTEM_THRESHOLDS.yaml
  - WORKSPACE_SCHEMA.yaml
  - FRAMEWORK_VERSION
  - CHANGELOG.md
  - workspaces/default_env.md  # 模板；實例排除
  - workspaces/README.md

# project_layer（專案特化；升級時不觸及）
project_layer:
  - CURRENT_WORKSPACE
  - workspaces/<name>.md  # 實例欄位值（排除 default_env）
  - workspaces/<name>/proposals/  # 專案 scope 提案（PROPOSAL_023）
  - proposals/active/*.md  # 當前進行中（升級不覆寫）
  - proposals/PROPOSAL_INDEX.md  # 專案累積狀態（升級時合併而非覆寫）
```

#### 3.5.3 用法

```bash
# 比對當前 .agents/ 與臨時目錄下的 latest .agents/
node .agents/scripts/framework-diff.mjs --target /tmp/latest-agents

# 輸出樣例
📂 Framework Layer Diff Report
📅 Local: FRAMEWORK_VERSION v3.5（2026-04-23）
📅 Target: FRAMEWORK_VERSION v4.0（2026-04-23）

✨ New Files (3)
  + scripts/framework-diff.mjs
  + FRAMEWORK_VERSION
  + CHANGELOG.md

✏️  Modified Files (2)
  ~ RULES_DESIGN_GUIDE.md（§十六 新增 F 節）
  ~ tests/workspace-schema-validator.mjs（新增 skills/tasks 掃描）

📝 Skills/Tasks with New §專案特化參照 (9)
  ~ skills/concurrency-guard-pattern.md
  ~ skills/infra-constraints.md
  ... (7 more)

🗑️  Deleted Files (0)
  (none)

🔒 Protected Layer (skipped)
  CURRENT_WORKSPACE, workspaces/<project>.md, proposals/active/*.md

📋 Recommended Merge Commands
  cp /tmp/latest-agents/scripts/framework-diff.mjs .agents/scripts/
  cp /tmp/latest-agents/FRAMEWORK_VERSION .agents/
  cp /tmp/latest-agents/CHANGELOG.md .agents/
  cp /tmp/latest-agents/RULES_DESIGN_GUIDE.md .agents/
  # ... (其餘檔案列表)

⚠️  Post-merge Checks
  1. bash .agents/tests/run-all.sh
  2. node .agents/tests/workspace-schema-validator.mjs
  3. Review CHANGELOG.md for new proposals affecting existing workspace
```

#### 3.5.4 退出碼

- `0` = 兩框架層一致（無差異）
- `1` = 有差異，User 需審視（正常升級情境）
- `2` = 結構錯誤（如其中一份目錄非 `.agents/` 結構）

#### 3.5.5 安全保證

- 工具**不自動執行 merge**；僅輸出 diff 報告 + 建議指令
- 工具**不觸及 project_layer**（即使 User 誤將其加入 target path，diff 報告中會標記 `🔒 Protected; skipped`）
- User 最終決定是否 `cp` / `rsync`；可選擇性合併部分檔案

### 3.6 Part 6：新建 `.agents/tasks/framework-upgrade-workflow.md`

升級 SOP 8 步驟（對齐 PROPOSAL_002 `project-onboarding.md` 格式）：

```markdown
# Task: Framework Upgrade Workflow (.agents 框架升級流程)

> 由 PROPOSAL_20260423_001 建立。多專案並行部署（方案 B）場景下，各專案 `.agents/` 副本的框架層升級 SOP。

## 觸發條件

任一情況觸發：
1. 上游 `.agents/` 框架發布新版本（`FRAMEWORK_VERSION` 遞增）
2. User 指令「升級 .agents 框架」
3. 新專案建立時，選擇採納最新框架版本
4. `@Auditor` 評審發現多專案間框架 drift（未來擴充 N+1 次評審項）

## 8 步驟流程

### Step 1：取得新版 `.agents/` 副本

由 User 手動執行（framework 內建工具不呼叫 git）：

```bash
# 範例：從上游 git repo clone 至臨時目錄
git clone <framework_repo_url> /tmp/latest-agents
# 或從另一專案的 .agents/ 複製
cp -r ~/other-project/.agents /tmp/latest-agents
```

### Step 2：執行框架層 diff

```bash
cd <本專案根目錄>
node .agents/scripts/framework-diff.mjs --target /tmp/latest-agents/.agents
```

### Step 3：審視 diff 報告

- 新增檔案：評估是否採納（rules/skills/tasks 通常全採納；scripts/tests 可選）
- 修改檔案：逐一檢視變更內容（特別關注 SYSTEM_THRESHOLDS.yaml / WORKSPACE_SCHEMA.yaml 欄位異動）
- 刪除檔案：確認本專案無引用（grep）

### Step 4：workspace schema 相容性檢查

若新版 `WORKSPACE_SCHEMA.yaml` 有新欄位：

```bash
node .agents/tests/workspace-schema-validator.mjs --workspace <本專案>
```

若缺新 required 欄位 → exit 2，需先補填 workspace 實值再繼續。

### Step 5：執行當前 `.agents/` 驗證（升級前基線）

```bash
bash .agents/tests/run-all.sh > /tmp/pre-upgrade-validation.log
```

記錄當前狀態（drift_score / 警告數）；升級後比對。

### Step 6：選擇性合併框架層檔案

依 Step 3 決策，逐項執行：

```bash
# 範例（依 diff 報告建議指令）
cp /tmp/latest-agents/.agents/RULES_DESIGN_GUIDE.md .agents/
cp /tmp/latest-agents/.agents/skills/concurrency-guard-pattern.md .agents/skills/
# ...
```

**禁止合併**（project_layer）：
- ❌ `CURRENT_WORKSPACE`
- ❌ `workspaces/<本專案>.md`
- ❌ `workspaces/<本專案>/proposals/`
- ❌ `proposals/active/*.md`（當前進行中提案）
- ❌ `proposals/PROPOSAL_INDEX.md`（需合併而非覆寫）

### Step 7：執行升級後驗證

```bash
bash .agents/tests/run-all.sh > /tmp/post-upgrade-validation.log

# 比對升級前後
diff /tmp/pre-upgrade-validation.log /tmp/post-upgrade-validation.log
```

預期：
- drift_score 不下降超過 0.05（對齐 `RULES_DESIGN_GUIDE §十二` Phase E.1）
- 無新增 error 類驗證失敗

### Step 8：更新本專案 `FRAMEWORK_VERSION` + 記錄

1. 複製新版 `FRAMEWORK_VERSION` 至本專案 `.agents/`
2. 於 workspace `BUSINESS_RULES` 或 `GLOBAL_STATUS_SUMMARY.md` 記錄升級事件：
   ```
   ## 框架升級記錄
   - 2026-04-23: v3.5 → v4.0（採納 PROPOSAL_20260423_001）
   ```

## 禁止行為

- **絕對禁止** 覆寫 `CURRENT_WORKSPACE` / `workspaces/<本專案>.md`
- **絕對禁止** 覆寫 `proposals/active/`（當前進行中）
- **絕對禁止** 跳過 Step 5 + Step 7 驗證（升級無驗證等同引入未測試變更）
- **絕對禁止** 合併 `PROPOSAL_INDEX.md`（需人工合併；各專案狀態不同）

## 升級失敗回滾

若 Step 7 驗證失敗：

```bash
git status  # 檢視變更清單
git restore .agents/  # 回滾至升級前
# 或針對特定檔案
git restore .agents/RULES_DESIGN_GUIDE.md
```

再次執行 run-all.sh 確認回滾成功。
```
