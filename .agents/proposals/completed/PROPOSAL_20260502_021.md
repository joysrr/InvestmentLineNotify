# PROPOSAL_20260502_021: Framework Harness-Neutral 化

## 一、背景

User 詢問現況框架對單一 agent harness（Claude Code CLI）的依賴度。經 2026-05-04 盤點：

| 等級           | 項目                                                                                        | 受影響檔案數                        |
| -------------- | ------------------------------------------------------------------------------------------- | ----------------------------------- |
| 🔴 絕對依賴    | Sub-agent dispatch（Task tool / `subagent_type`）                                           | 8 處（auditor / retro / hotfix 等） |
| 🟡 設定檔依賴  | `.mcp.json` / `.claude/settings.local.json` hooks                                           | 主檔 2 + 多處 task 引用             |
| 🟡 概念依賴    | Discussion vs Execution mode（Claude system-prompt 風）                                     | system-prompt.md + 多處 rule        |
| 🟢 命名依賴    | Read/Write/Edit/Bash/LS/Grep 工具名                                                         | 散落 74 處                          |
| ✅ 已 portable | 13 rules / 6 iron-rules / 39 ADRs / 64+ skills / 15 validators / mempalace CLI / `.export/` | —                                   |

**現有保護**：

- `docs/PLATFORM_COMPATIBILITY.md`（PROPOSAL_502_019）：4 harness × 12 capability 對照表（**只記錄；未脫鉤**）
- `tasks/harness-adapter-pattern.md`（PROPOSAL_502_019）：4 個 adapter 點設計指南（**未實作**）
- `INSTALL_ANTIGRAVITY.md`（PROPOSAL_502_019）：實機驗證紀錄（**串行 workaround 可走**）

**User 明確意圖**（2026-05-04）：

> 共用，不要依賴單一 agent 特色，盡量讓 rules 能夠自行處理即可

→ 本提案執行**真正的脫鉤**：把「派 N agent 並行」改寫為「rules 內串行 N 輪 + 結構化整合」；hooks/MCP/工具命名走中性語 + per-harness fallback。

## 二、目標 + 非目標

### 目標

1. **去 sub-agent dispatch 依賴**：5 個依賴 Task tool 的 rule/task 改寫為「rules 內串行模式」；功能等價（5x 慢但全 harness 可跑）
2. **工具命名中性化**：74 處 hardcoded 工具名（`Read tool` / `Bash tool` 等）改為「讀檔工具」「執行命令工具」中性語
3. **設定檔 per-harness fallback**：`.mcp.json` + `.claude/settings.local.json` 改為 layered（Claude 走原檔；其他 harness 走 git-native hooks + IDE settings 指南）
4. **驗證**：Hello-world test + 27 情境簡化版 在 3 種 harness 跑過（Claude CLI 全 OK 為 baseline；Antigravity ≥80% 達成；Web 視 sandbox）
5. **drift baseline 重測**：每 harness 跑 `agent-drift-simulator.mjs` 取得 per-harness drift_score baseline

### 非目標（不做）

- ❌ 真實 Qwen-Agent adapter 實作（無 Qwen 環境驗證；本提案只確保 framework 不阻擋；adapter 留 future PROPOSAL）
- ❌ Web mode 完整 fallback wiring（待 User 真實使用 web 場景再做）
- ❌ Persona 重新校準（drift baseline 取得後若 < 0.85 才另立提案處理）
- ❌ 重寫 mempalace MCP integration（PROPOSAL_502_020 v2 Plan G 已脫 git；本提案不動）
