# PROPOSAL_20260502_020: MemPalace 寫入機制升級 — Plan G（DONE）

## 一、背景

User 詢問現況框架記憶機制是否「自動化 / zip 帶走記憶 / 不雙寫」。實際分析發現：

- 現況是「寫 markdown SoT → mempalace mine」兩步；非全自動
- ChromaDB 在 `~/.mempalace/`；zip 不帶走

## 二、評估中的 4 個方案

| 方案       | 描述                     | 自動化 | zip 帶走          | 不雙寫 |
| ---------- | ------------------------ | ------ | ----------------- | ------ |
| Plan E     | data 內建專案            | ✅     | ⚠️（KG 不跟）     | ✅     |
| Plan F     | 雙寫保 markdown          | ✅     | ✅                | ❌     |
| **Plan G** | MCP-direct + 自寫 export | ✅     | ✅（透過 export） | ✅     |
| Plan H     | 接受不可完整帶走         | ✅     | ❌                | ✅     |

## 三、執行前發現的 mempalace 限制

1. **mempalace 設計是 user-global**：`~/.mempalace/` 含 KG（不跟 palace_path 走）；強行 per-project palace 會 KG 漂移
2. **mempalace 3.3.4 沒 native export**：CLI 只有 init/mine/sweep/search/compress/wake-up/migrate/status；無 export
3. **唯一 export 路徑**：透過 MCP `mempalace_list_drawers` + `mempalace_get_drawer` 自寫 script

### 限制揭露（接受並文件化）

1. **mempalace 3.3.4 user-global**：ChromaDB + KG 在 `~/.mempalace/`；強行 per-project palace 會 KG 漂移 → Plan G 接受 user-global；改用 `.export/` 解決 zip 帶走需求
2. **Cold export 非 transactional**：MCP 寫入後若未跑 export 即環境消失，drawer 不在 `.export/`；緩解：rules 強制 commit 前跑 export（lead.md/retro.md 絕對禁止「commit 前未跑 export」）
3. **Fallback `.pending/` 機制**：MCP down 期間 sub-agent 寫到 buffer；MCP 復活後 @Lead 批次 replay；@Retro 審計納入

### 後續觀察點（不入本提案）

- `git pre-commit` hook 自動跑 mempalace-export（建議；非強制）
- `.pending/` buffer 機制 e2e 測試（待 fallback 實際發生時驗證）
- `mempalace mine` 從 `.export/` 重建是否完全保留 metadata（首次 cold-start 時驗）
- export script 加 incremental mode（當 drawer 數成長後）
