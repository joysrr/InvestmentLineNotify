## 三、提案內容

### 3.1 SYSTEM_THRESHOLDS.yaml 新增 `MODEL_ROUTING` 區塊

```yaml
MODEL_ROUTING:
  # 複雜度評估三維度（任一維度達標即升等）
  complexity_thresholds:
    simple:
      max_input_tokens: 500
      max_reasoning_steps: 1
      max_artifact_paths: 2
      examples: ["格式化文字", "讀取單一檔案", "字串替換", "純查詢"]
    medium:
      max_input_tokens: 2000
      max_reasoning_steps: 3
      max_artifact_paths: 5
      examples: ["代碼審查", "API 設計", "簡易架構決策"]
    complex:
      min_input_tokens: 2000
      min_reasoning_steps: 4
      min_artifact_paths: 6
      examples: ["跨模組重構", "多 Agent 協調", "新架構提案"]

  # 模型分配（廠商中立；具體模型 ID 由各 host 平台對應）
  model_tier_map:
    simple: "haiku"      # 對應 Claude Haiku 4.5 / GPT-4o-mini 等
    medium: "sonnet"     # 對應 Claude Sonnet 4.6 / GPT-4o 等
    complex: "opus"      # 對應 Claude Opus 4.7 / GPT-5 等

  # 強制使用 complex 的場景（即使 complexity 低）
  force_complex_scenarios:
    - "strategyWeight 異動評估"
    - "資安審查（@Security 任何任務）"
    - "Hotfix 緊急通道"
    - "提案根因分析（@Retro）"
```

### 3.2 lead.md 新增 §「Task Complexity Assessment」

於 lead.md `<section id="s_state_anchor">` 之後新增 `<section id="s_complexity">`：

```markdown
## 任務複雜度評估與模型路由（依 PROPOSAL_20260422_024）

### 派發前複雜度評估三步

1. **取得 input tokens**：估算將注入子 Agent 的 prompt + workspace 欄位 + tech-stacks 引用
2. **判定推理層數**：依任務性質（單一檔案修改 = 1 / 跨檔案重構 = 3+ / 新架構設計 = 4+）
3. **計算 artifacts 數**：本次任務涉及讀寫的檔案路徑數

依 SYSTEM_THRESHOLDS.yaml `MODEL_ROUTING.complexity_thresholds` 對照分類為 `simple` / `medium` / `complex`。

### 模型注入規則

派發指令格式新增 `Model: <tier>` 欄位（對齊 `stateless-routing-pattern.md §B`）：

```
Next: @Backend
Model: medium
Tech-stacks: file-based-storage
Artifacts: src/modules/storage.mjs
```

### 強制升等場景（覆蓋 complexity 評估）

依 SYSTEM_THRESHOLDS.yaml `force_complex_scenarios` 列舉之任務 → 強制 `Model: complex`，不論評估結果。
```

### 意圖繼承
本提案不推翻任何既有提案；新增能力。

- **廠商中立**：model_tier 用語意名稱（simple/medium/complex），具體模型 ID 由 host 平台映射
- **可覆蓋**：default_model_tier 為 frontmatter 預設；@Lead 派發時可基於本次 complexity 評估覆蓋
- **強制場景優先**：安全 / 提案 / 評審等高風險領域強制 complex，不容降級
