## 一、問題描述

第五次評審顯示 **9/13 rules >3000 tokens**（1.4 Token Economy: 4.5 → 3.2）。根因兩層：

1. **流程缺口**：無「rule 檔改動前先檢查 token 預算」機制 → 新機制持續累積無阻
2. **存量膨脹**：lead.md 10.2k / retro.md 7.0k / assistant.md 6.4k 已超限

## 二、雙軌策略

本提案合併 User 2026-04-24 提出的**方法 2（auto-escalation 治本）**與**原 PROPOSAL_020（拆檔治標）**：

| 軌道       | 目標                                | Phase       | 作用時機 |
| ---------- | ----------------------------------- | ----------- | -------- |
| **治本層** | 防止未來再膨脹                      | Phase B     | 預防性   |
| **治標層** | 修復當前超限檔                      | Phase C/D/E | 存量修復 |
| **守門層** | drift_score + 新 validator 雙重保護 | Phase F     | 持續監控 |

### drift_score 守門策略（關鍵風險防護）

- `agent-drift-simulator.mjs` 依賴 `lead.md` 含 `<section id="s_state_anchor">` + `<section id="s_complexity_lane">` + 三鐵律關鍵字
- 拆檔時**必須保留**上述 section marker（stub 形式；完整內容搬至 skill）
- 每個 Phase 執行後**強制跑** drift_score；Δ < -0.05 則立即中止後續 Phase
