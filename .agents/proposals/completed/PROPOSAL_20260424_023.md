# PROPOSAL_20260424_023：ROUTING_TICKET.md 派發 artifact 機讀化

## 基本資訊

- 提案編號：**PROPOSAL_20260424_023**
- scope：**framework**
- 提案日期：2026-04-24
- 狀態：OPEN
- tier：**full**（涉及 7 子 agents rule 變更 + 1 新 skill；>50 LOC）
- 優先級：**P2**
- 預估工時：~3 小時
- 來源：User 2026-04-24 提案『CLI 無狀態路由模擬』；採方案 B 並擴大至子 agents（User 指令）

## 一、問題描述

`@Lead §s_state_anchor` 鐵律 3「短指令交接」現以**對話文本**約束子 agents 派發；存在三個風險：

1. 文本內容無 schema 強制；@Lead 可能漏欄位（Tech-stacks / Artifacts）
2. 子 agents 易參考對話歷史而非派發訊息（語意發散）
3. 缺乏 LangGraph 遷移所需的「node state」對應物

## 二、根因分析

| 層級 | 代碼   | 分析                                       |
| ---- | ------ | ------------------------------------------ |
| ARCH | `ARCH` | 派發約束停留於文本層；未檔案化             |
| DEV  | `DEV`  | 子 agents 無強制讀檔順序；可能依賴對話歷史 |

## 三、提案內容

### Phase A：立案（本檔）

### Phase B：建立 `skills/routing-ticket-protocol.md`（F1；schema + workflow）

定義 `ROUTING_TICKET.md` 規格：

```yaml
# ROUTING_TICKET.md（運行時 artifact；放專案根層；append-only history）
schema_version: v1
created_at: 2026-04-24T15:30:00Z
created_by: "@Lead"
ticket_id: TKT-20260424-001
status: dispatched | acknowledged | completed | cancelled

# 原始 User 指令（一字不漏）
original_request: |
  <User 原文，包含中文標點>

# Lane / Model 決策
assigned_lane: fast | standard | heavy
model_tier: haiku | sonnet | opus
complexity_tier: simple | medium | complex
tier_reason: <一句話評估摘要>

# 任務目標
target_agent: "@Backend"
sibling_agents: [] # 並行派發（如 @Reviewer + @Security）
touched_files: []
artifact_paths: []
tech_stacks: []

# Workspace 注入摘要
project_context_excerpt: <workspace 欄位精選>
business_rules_excerpt: <若觸發>
critical_paths_excerpt: <若觸發>
```

**與 PENDING_ACTIONS.md §🎯 邊界**：

- `PENDING_ACTIONS §🎯` = **狀態錨點**（CURRENT_STAGE；who is doing what now）
- `ROUTING_TICKET` = **派發 artifact**（this dispatch's full context）
- 兩者**並存且互補**：PENDING_ACTIONS 跨派發累積；ROUTING_TICKET 每次派發一張

### Phase C：修改 `rules/lead.md`

`§s_state_anchor` 鐵律 3 補：「派發前**必須**先寫入 `ROUTING_TICKET.md`（完整 schema 見 `skills/routing-ticket-protocol.md`）；對話訊息僅作為 ticket 創建的人讀通知」。

`§s_complexity_lane` 派發指令格式擴充欄位：補 `Ticket: ROUTING_TICKET.md`。

### Phase D：修改 7 個子 agents rules

- `rules/planner.md`
- `rules/architect.md`
- `rules/backend.md`
- `rules/frontend.md`
- `rules/qa.md`
- `rules/reviewer.md`
- `rules/security.md`

每檔 §s01 任務目標**首段**插入：

```
**派發接收鐵律**：被 `@Lead` 喚醒時，**首要動作**是讀取專案根層的 `ROUTING_TICKET.md`。
**絕對禁止** 從對話歷史推導本次任務範圍；一切以 ticket 內容為準。
```

### Phase E：Validator + Release

- 新 `tests/routing-ticket-validator.mjs`（schema 驗證 + history append-only 檢查）
- 整合 run-all.sh（第 12 validator）
- FRAMEWORK_VERSION v6.4 → v6.5（minor bump）
- CHANGELOG [v6.5]
- agents-overview §9.3 新增 ROUTING_TICKET.md 產出物
