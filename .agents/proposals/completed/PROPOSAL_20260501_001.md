## 二、為何重要

| 痛點                         | 影響                                                                |
| ---------------------------- | ------------------------------------------------------------------- |
| 規則 token 高 → context 占用 | 注入 13 rules 共 ~25K tokens；占 1M 上限 2.5%；多輪對話後無法 cache |
| 規則 token 高 → 維護成本     | 改一處要找 ~1500 行；違反 rules 為「骨架」原則                      |
| 漂移風險                     | 內容多 → LLM 容易忽略尾段；降低 boundary_adherence                  |

## 三、目標

1. **12 rules 全降至 ≤ 1000 token**（agent_rule budget）
2. **system-prompt.md ≤ 500 token**（always_on budget）
3. **不損及 drift_score**（當前 0.872；目標 ≥ 0.85）
4. **不損及 boundary_adherence**（當前 0.862）

## 四、執行策略（草案）

### A. 抽 skills（主要手段）

- Memory Palace 條目 → `memory/Strategy_Context_Room.md`

- 折疊 H3 → 表格

- 若拆完仍超 1000 → 評估是否需要新增 ADR

## 十二、Phase B 教訓固化（已寫入 playbook §三）

1. **section count 為結構不變量**：subagent 多次違反（assistant.md 17→11→9）；playbook 補強規則 + 驗證指令
2. **並行寫衝突**：subagent 在主線完成後仍可能寫入；緩解 = 立即 commit + push 鎖定
3. **atomic write 範本**：`/tmp/<rule>-slim.md` → `mv` 鎖定，避免 race
4. **「絕對禁止」鐵律敏感**：boundary_adherence 對 §s01 派發鐵律段的「絕對禁止」遺失極敏感（drift -0.02）；compress 時必逐字保留鐵律詞
