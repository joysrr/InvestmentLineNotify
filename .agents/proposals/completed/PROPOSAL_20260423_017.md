# PROPOSAL_20260423_017：Tech-Stacks Catalog 分類重構 + MANIFEST 選擇性搬運

## 基本資訊

- 提案編號：**PROPOSAL_20260423_017**
- scope：**framework**
- 提案日期：2026-04-24
- 完成日期：2026-04-24
- 狀態：**DONE** ✅
- 優先級：**P1**（為 Avalonia 專案 onboarding 鋪路 + 跨專案擴充性）
- 提案者：`@Lead`
- 前置依賴：016（ADR 架構）✅
- 實際工時：~6 小時（7 Phase 一次到位）

## 一、問題描述

### 1.1 現況

當前 `tech-stacks/` 為**扁平單層目錄**：

```
tech-stacks/
├── nodejs-esm-backend.md
├── vue3-vite.md
├── telegram-bot.md
├── telegram-miniapp.md
├── telegram-miniapp-sdk.md
├── file-based-storage.md
├── pm2-management.md
└── testing-nodejs.md
```

符合 ADR-0015 的扁平命名規則 + 6 鐵律，但**搬運時無法選擇性**：`cp -r .agents/` 會帶所有檔案，即使新專案只需 2-3 個。

### 1.2 觸發場景

User 2026-04-24 討論新 Avalonia 專案引入時發現：
- 新專案只需 `avalonia-ui` / `semi-avalonia` / `dotnet-base`
- 若搬運當前框架 → 帶入 `telegram-bot` 等 8 份無關 stacks
- LLM 讀取時增加噪音；檔案膨脹無關專案

### 1.3 預期未來增長

| 時間 | tech-stacks 預估 | 當前機制問題 |
|------|----------------|------------|
| 現在 | 8 份 | 可接受 |
| 半年 | 15-20 份 | 噪音上升 |
| 1 年 | 25-40 份 | 🔴 明顯痛點 |

ADR-0015 §十六.D 已預留「≥ 5 份同前綴強制子目錄」規則；但**沒有跨類別分類機制 + 選擇性搬運機制**。

---

## 二、根因分析

1. **扁平命名假設「幾份」** — 實際增長快於預期
2. **無 MANIFEST 概念** — 沒有「stack 目錄索引」的 SSOT
3. **init-workspace 不詢問 tech-stack** — 搬運後 workspace 需手動編 `TECH_STACK` 欄位
4. **缺記憶機制** — 刪除的 stack 後續想裝回沒有提示

---

## 三、提案內容（7 Phase）

### 3.1 Phase A：tech-stacks 分類重構

建立 **6 個類別子目錄** + `git mv` 現有 stacks：

```
tech-stacks/
├── MANIFEST.yaml                         ← Phase B 新增
├── core/                                 ← 幾乎所有專案通用
│   └── （後續加 testing-basics / git-pr-workflow 類）
├── web-backend/
│   ├── nodejs-esm-backend.md
│   ├── testing-nodejs.md
│   └── pm2-management.md
├── web-frontend/
│   └── vue3-vite.md
├── desktop/                              ← 🆕 為 Avalonia 建立
│   ├── avalonia-ui.md                    ← Phase F 新增
│   └── semi-avalonia/                    ← Phase F 新增（資料夾模式）
├── messaging/
│   ├── telegram-bot.md
│   ├── telegram-miniapp.md
│   └── telegram-miniapp-sdk.md
└── storage/
    └── file-based-storage.md
```

**路徑更新**：掃全框架更新引用（~30 處預估）：
```bash
grep -rln "tech-stacks/nodejs-esm-backend" .agents/
# 更新為 "tech-stacks/web-backend/nodejs-esm-backend"
```

### 3.2 Phase B：MANIFEST.yaml 機制

```yaml
# tech-stacks/MANIFEST.yaml
version: 1.0
schema_version: 1

categories:
  core:
    description: 幾乎所有專案通用
    priority: 1
  web-backend:
    description: 後端服務
    priority: 2
  web-frontend:
    description: Web 前端
    priority: 2
  desktop:
    description: 桌面應用 UI
    priority: 2
  messaging:
    description: 即時通訊 / Bot
    priority: 3
  storage:
    description: 資料儲存
    priority: 2

stacks:
  - name: nodejs-esm-backend
    category: web-backend
    class: F1
    file: web-backend/nodejs-esm-backend.md
    depends_on: []
    installed: true
    platforms: [windows, macos, linux]

  - name: avalonia-ui
    category: desktop
    class: F2
    file: desktop/avalonia-ui.md
    depends_on: [dotnet-base]
    installed: false             # 預設不裝；新 Avalonia 專案 opt-in
    platforms: [windows, macos, linux]
    extends_base: true           # 可被 semi-avalonia 繼承

  - name: semi-avalonia
    category: desktop
    class: F2
    folder: desktop/semi-avalonia/    # 資料夾模式（vendored content）
    depends_on: [avalonia-ui]
    installed: false
    platforms: [windows, macos, linux]
    vendor_source: https://github.com/irihitech/Semi.Avalonia
    vendor_last_vetted: <日期待填>
```

**欄位設計**：
- `installed: true/false` — 當前專案是否啟用
- `depends_on` — 自動依賴解析
- `vendor_source` + `vendor_last_vetted` — 資料夾模式專用（audit trail）
- `extends_base: true` — 聲明為可被繼承的基底 stack

### 3.3 Phase C：tech-stack-manage.mjs CLI

新腳本 `.agents/scripts/tech-stack-manage.mjs`：

```bash
# 列出所有（含狀態）
node .agents/scripts/tech-stack-manage.mjs list
# → 顯示 installed / available 分類

# 查看特定 stack
node .agents/scripts/tech-stack-manage.mjs info avalonia-ui

# 安裝（從 git history 或 upstream 取回）
node .agents/scripts/tech-stack-manage.mjs install avalonia-ui
# → 自動解析 depends_on；提示若要裝 dotnet-base

# 移除（標記未安裝；檔案 git rm）
node .agents/scripts/tech-stack-manage.mjs remove telegram-bot
# → MANIFEST 標記 installed: false；檔案刪除

# 恢復已移除的 stack
node .agents/scripts/tech-stack-manage.mjs restore telegram-bot
# → 若 git history 有則取回；否則提示去 upstream 取
```

**擴充 `init-workspace.mjs`**：
```bash
node .agents/scripts/init-workspace.mjs --name my-avalonia-app
# 互動階段新增：
# [?] 您的專案用哪些 tech-stacks?（空白鍵選擇，Enter 確認）
#   [ ] core/git-pr-workflow
#   [x] desktop/avalonia-ui         ← 自動勾 depends_on
#   [x] desktop/semi-avalonia
#   [ ] web-backend/nodejs-esm-backend
#   ...
# [?] 未選擇的 stacks 是否刪除？(yes/no/keep-as-available)
#   yes     → 刪檔 + MANIFEST 標記 removed
#   no      → 保留但 installed=false
#   keep    → 保留 + MANIFEST 不變（預設）
```

### 3.4 Phase D：tech-stack 擴充 SOP（skills/tech-stack-onboarding.md）

新 F1 類 skill 定義 tech-stack 新增流程：

```markdown
# Skill: Tech-Stack Onboarding

## 判定 checklist（新增前 5 秒問自己）
- [ ] 跨專案使用價值？
- [ ] 有實踐規範（非純 API）？
- [ ] ≥ 20 行規則？

## 建立模式決策
- 官方文件 < 200 行 → 單檔模式 `category/name.md`
- 官方文件 ≥ 200 行 → 資料夾模式 `category/name/`

## 單檔模式步驟
1. 選定分類（core / web-backend / desktop / ...）
2. 擷取 vendor 文件核心規範
3. 套用 6 鐵律檢核
4. 寫 §專案特化參照（F2 必備）+ Fallback 策略
5. 補 MACHINE_READABLE anchor
6. 註冊 MANIFEST.yaml
7. 更新相關 rules 引用（若有）

## 資料夾模式步驟
1. 同單檔 1-2
2. 建資料夾 `category/name/`
3. `upstream/` 存 vendor 原文 + SOURCE.md（URL + 日期 + 審核簽名）
4. `README.md` 寫適配規則（our rules）
5. `adapted/` 存補充 / 覆寫
6. `CHANGELOG.md` 追蹤 upstream 更新
7. 註冊 MANIFEST.yaml 含 vendor_source + vendor_last_vetted

## Vendor 內容安全準則（防 prompt injection）
- Vendor 原文只存於 upstream/，**不作為 LLM 規範來源**
- LLM 規範唯一來源：我們撰寫的 README.md / category/name.md
- SOURCE.md 明示審核人 + 日期
- 擷取內容時抽取結構而非 copy 段落
```
