## 一、問題描述

### 根因分類

**類型**：系統性設計缺陷（技術債累積）

### 問題陳述

7 個產出物模板分散嵌入於 6 份 Rules 主文件中，
合計約 1,580 tokens 的靜態 Token 成本。
根本原因為 `.agents/skills/` 目錄雖已存在，
但系統缺乏「模板外部化強制規範」，
各 Rules 設計時各自判斷模板是否嵌入，
導致技術債持續累積。

### 問題影響

1. Token 壓縮效應：
   模板 Token 與核心邏輯 Token 競爭上下文空間，
   降低 Agent 執行時的有效推理空間。

2. 版本維護不一致風險：
   若同一模板格式需要更新，
   必須同時修改多份 Rules，易造成版本不同步。

3. `qa.md` 交叉污染風險：
   TEST_SPEC 與 TEST_REPORT 兩個模板嵌入同一份 Rules，
   介入點一與介入點二的產出物邊界在 LLM 上下文中可能混淆。

4. 新 Agent 設計污染：
   缺少外部化規範，未來新增 Rules 的設計者
   會沿用「嵌入模板」的慣例，問題持續累積。

### 受影響 Rules 與 Token 估算

| Rules         | 嵌入模板                             | 估算嵌入 Token |
| ------------- | ------------------------------------ | -------------- |
| planner.md    | User Story 模板、Draft Features 模板 | ~380           |
| qa.md         | TEST_SPEC 模板、TEST_REPORT 模板     | ~480           |
| reviewer.md   | REVIEW_REPORT 模板                   | ~290           |
| retro.md      | RULE_UPDATE_PROPOSAL 模板            | ~280           |
| consultant.md | ADVICE 模板                          | ~150           |
| 合計          | 7 個模板                             | ~1,580         |

## 二、根因分析

### 直接根因

`.agents/` 目錄缺乏統一的模板外部化設計規範，
各 Rules 設計者在建立文件時缺少強制性指引，
導致模板嵌入成為系統內部的隱性設計慣例。

### 系統根因

整個 Agent 系統缺乏「新增 Rules 前置審查機制」，
無法在 Rules 設計階段攔截 Token 效率問題。
（此根因將由 PROPOSAL-003 的
`.agents/RULES_DESIGN_GUIDE.md` 從根本解決）

### 反覆風險評估

若只修復現有 Rules 而不建立規範，
未來新增 Rules 有極高概率重複犯相同問題。
本提案與 PROPOSAL-003 需配合執行，
才能形成完整的防重犯閉環。
