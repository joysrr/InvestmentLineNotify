### I-2 rule-token-budget-validator KI-001 allowlist

當前：`rule_token=1` 永久 warning（KI-001）；新 warning 出現時被掩蓋。

處置：validator 讀 `KNOWN_ISSUES.md` 解析 KI-001 對應檔案；只有 warnings 在 allowlist **之外** 才報告為 warning。

```js
// rule-token-budget-validator.mjs 新增邏輯
function loadKIAllowlist() {
  // 從 .agents/KNOWN_ISSUES.md 解析 KI-001 ~ 對應的檔案路徑
  // 簡單實作：硬編碼 KI-001 對應檔案
  return ["iron-rules/data-deletion-zero-tolerance.md"];
}

// 報告階段：
const allowlist = loadKIAllowlist();
if (allowlist.includes(relativePath)) {
  console.log(
    `ℹ️  [KI-001] ${relativePath}: ${tokens}/${warn}（已知接受；KNOWN_ISSUES 追蹤）`,
  );
} else {
  console.warn(`⚠️  [WARN] ${relativePath}: ...`);
  warnings++;
}
```

效果：

- `data-deletion-zero-tolerance.md` 696 tokens 仍報但不算 warning（顯示為 KI-001 已知）
- 任何**新出現** > tier warn 的檔案 → 仍正常 warn → 醒目可見

向後相容：`KNOWN_ISSUES.md` 不存在 / KI-001 已解除 → fallback 為原行為。
