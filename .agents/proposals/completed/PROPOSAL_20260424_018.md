# PROPOSAL_20260424_018：init-workspace UX 一鍵化 + tech-stack 定期 audit 機制

## 基本資訊

- 提案編號：**PROPOSAL_20260424_018**
- scope：**framework**
- 提案日期：2026-04-24
- 完成日期：2026-04-24
- 狀態：**DONE** ✅
- 優先級：**P1**（補 017 UX 缺口 + 新專案低摩擦進場）
- 提案者：`@Lead`
- 前置依賴：017（Catalog + MANIFEST + Step 6.5 原初實作）✅
- 實際工時：~3 小時（6 Phase 一次到位）

## 一、問題描述

### 1.1 現況 bug（017 Phase C 遺留）

`scripts/init-workspace.mjs` Step 6.5 `selectTechStacks()` 只實作單向處理：

- ✅ 將已 installed 但未選者標記 `installed: false`（drop 方向）
- ❌ 將選中但當前 `installed: false` 者翻 true（keep 方向 — 未實作）

**後果**：User 在 init 中勾選 `semi-avalonia`，MANIFEST 不會變；必須事後手動跑 `tech-stack-manage install semi-avalonia`。違反「Step 6.5 一處完成」原意。

### 1.2 UX 缺口

| 缺口                             | 影響                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| 40+ 題問答流程                   | 新專案 onboarding 摩擦高；User 易半路放棄                      |
| TECH_STACK 欄位與 stack 選擇重工 | 填 `language: csharp` 又勾 `avalonia-ui`，邏輯上重複           |
| CLI 互動式無法 agent 代跑        | Agent 無法「出一張嘴」驅動 init，User 必須坐在終端             |
| Step 6.5 預設 UX                 | 目前預設「Enter = 不變更」；新 User 想「全裝」需額外指令 `all` |

### 1.3 tech-stack 累積問題

用戶 2026-04-24 回饋：「一開始使用者可能不會篩選，選擇全面使用」。此行為合理 — 但若無回頭審視機制：

- 專案推進 3-6 個月後，多數 stack 從未被引用 → `.agents/` 噪音
- `@Lead` 派發任務時 LLM 讀無關 stack → token 浪費 + 決策干擾
- 搬運新 stack 到其他專案時帶入歷史包袱

### 1.4 現況無定期 audit

當前框架無機械化提醒：

- `ADR-0029` @Assistant 巡邏僅覆蓋既有 P-01 ~ P-22
- 無「tech-stack 閒置偵測」類型規則
- workspace schema 無 audit 時間戳

## 二、根因分析

1. **017 Step 6.5 為趕「一次到位」目標簡化實作** → keep 方向未驗證（本提案補正）
2. **init-workspace 設計時未考慮 agent 驅動** → readline 強耦合；agent 無法取代 User 輸入
3. **Catalog 擴張預期未定義生命週期下半段** → 只有「裝 / 移除」，缺「定期 audit」

## 三、提案內容（6 Phase）

### 3.1 Phase A：WORKSPACE_SCHEMA 擴充 + 立案

`WORKSPACE_SCHEMA.yaml` 新增兩欄位於 `TECH_STACK` block：

```yaml
TECH_STACK:
  last_audit_date:
    type: string # YYYY-MM-DD
    required: false
    description: "tech-stack 上次審視日期（init 自動填當天；audit 指令執行時更新）"
  audit_interval_days:
    type: integer
    required: false
    default: 30
    description: "tech-stack audit 間隔（天數）；@Assistant P-23 巡邏依此判定過期"
```

init 時自動填 `last_audit_date = today` + `audit_interval_days = 30`（若 User 未覆寫）。

### 3.2 Phase B：init-workspace UX 一鍵化

**B.1 修 Step 6.5 bug**（雙向 installed 處理）：

```js
const toActivate = stacks.filter(
  (s) => selectedSet.has(s.name) && !s.installed,
);
const toDeactivate = stacks.filter(
  (s) => !selectedSet.has(s.name) && s.installed,
);
// 對 toActivate 呼叫 updateInstalledField(text, name, true) + 檢查檔案存在（缺則從 git history restore）
// 對 toDeactivate 維持原邏輯
```

**B.2 Step 6.5 預設改為「全部保留」**：

- Enter 直接過（空輸入）→ 視為 `all`（所有 installed:true 繼續保留 + 選中所有 installed:false 者翻 true）
- 輸入 `keep` → 舊行為（不變更 MANIFEST）
- 輸入編號清單 → 精確篩選

**B.3 `--config <yaml>` 非互動旗標**：

```bash
node .agents/scripts/init-workspace.mjs --config /tmp/my-avalonia.yaml
```

config 結構：

```yaml
project_name: my_avalonia_app
answers:
  PROJECT_CONTEXT.display_name: My Avalonia App
  PROJECT_CONTEXT.business_domain: Desktop app
  TECH_STACK.language: csharp
  # ... 其他欄位
tech_stacks:
  install: [avalonia-ui, semi-avalonia]
  remove:
    [
      telegram-bot,
      telegram-miniapp,
      telegram-miniapp-sdk,
      vue3-vite,
      vue3-component-pattern,
      file-based-storage,
    ]
  mode: delete-files # or keep-files
```

**B.4 TECH_STACK 欄位自動推導**：

- 從選中的 stacks 的 `MACHINE_READABLE` block 抽取預設值
- 例：選 `avalonia-ui` → `TECH_STACK.language=csharp` / `TECH_STACK.framework=Avalonia` / `TECH_STACK.platforms=[windows, macos, linux]`
- User 透過 `--config` 可覆寫；互動模式不自動覆寫已填答案

**B.5 Post-init reminder**：

```
✅ Workspace 建立完成
📦 已安裝 N 個 tech-stacks（全部保留）
💡 建議：30 天後執行 `node .agents/scripts/tech-stack-manage.mjs audit`
   審視是否有未用到的 stack；系統會提供使用量初步篩選。
```

### 3.3 Phase C：tech-stack-manage audit 指令

新 `audit` 指令：

```bash
node .agents/scripts/tech-stack-manage.mjs audit [--deep]
```

**行為**：

1. 讀 MANIFEST 所有 `installed: true` stacks
2. 對每個 stack 計算**引用統計**：
   - `refs_in_rules`：在 `rules/*.md` / `skills/*.md` / `tasks/*.md` 中被 `tech-stacks/<category>/<name>` 路徑字串出現次數
   - `refs_in_workspace`：在當前 workspace md 被提及次數（TECH_STACK 欄位 + 其他區塊）
   - `refs_in_code`（--deep 模式；工時較久）：grep workspace `PATHS.project_root` 下原始碼中是否有關鍵字（例：`using Avalonia;` / `import { ref }` from 'vue'）
3. 分級建議：
   - `high-usage`（total refs > 3）：**保留建議**；LLM 判斷為積極使用
   - `low-usage`（1-3 refs）：**審視候選**；User 判斷是否還需要
   - `zero-usage`（0 refs）：**移除候選**；高機率未使用
4. 互動逐個確認：
   ```
   ┌─ [zero-usage] telegram-bot
   │  rules: 0 | workspace: 0 | code: 0
   │  建議：移除
   │  [k]eep / [r]emove / [s]kip ? r
   │  → git rm + MANIFEST installed: false
   └─
   ```
5. 全部處理完 → 更新 workspace `TECH_STACK.last_audit_date = today`
6. 摘要報告：
   ```
   Audit 摘要（2026-05-24）：
   - 保留：5
   - 移除：3
   - 跳過：2
   ```

**安全準則（User 2026-04-24 明確要求）**：

- Agent / 腳本**只做初步篩選**（出建議）
- **User 必須逐個確認**才執行刪除
- `--yes-all` 類旗標**不提供**（避免誤刪）

### 3.4 Phase D：agent-onboarding-flow task

新 `tasks/agent-onboarding-flow.md`（F1 task）：

定義「User 對話觸發 → agent 驅動 init」SOP：

````markdown
# Task: Agent-Driven Project Onboarding

## 觸發關鍵字

- "我要開 <平台> 專案"（例：Avalonia / Vue / React / Node.js）
- "建立新 workspace"
- "init workspace"

## Agent 流程（@Lead 或 @Assistant 擔任）

### Step 1：意圖識別

識別 User 說的平台 / 技術 → 對應 tech-stacks（查 MANIFEST）：

- "Avalonia" → avalonia-ui, semi-avalonia
- "Vue + Telegram Mini App" → vue3-vite, vue3-component-pattern, telegram-miniapp, telegram-miniapp-sdk
- "Node 後端 + Telegram Bot" → nodejs-esm-backend, testing-nodejs, telegram-bot

### Step 2：用 AskUserQuestion 確認

精簡問題清單（3-5 題）：

1. 專案名稱（snake_case）
2. 一句話描述專案
3. 部署目標（桌面 / server / serverless）
4. 是否採用推薦的 tech-stack 組合（Y / 細調）
5. 其他特殊需求

### Step 3：產出 YAML config

依 User 答案組 config；若有缺省值（如 Locale）使用 tech-stack README §七 Fallback。

### Step 4：呼叫 init-workspace --config

```bash
node .agents/scripts/init-workspace.mjs --config /tmp/onboarding-<ts>.yaml
```
````

### Step 5：後續提醒

引用 post-init reminder（§Phase B.5）；提醒 User 30 天後 audit。

````

### 3.5 Phase E：@Assistant P-23 audit overdue 巡邏

`rules/assistant.md` 新增 patrol 規則 **P-23**：

```markdown
## P-23 — Tech-Stack Audit 過期偵測

**觸發條件**：每次 session 啟動時
**檢查邏輯**：
1. 讀 `.agents/workspaces/<CURRENT_WORKSPACE>.md` 的 `TECH_STACK.last_audit_date` 與 `audit_interval_days`
2. 若不存在兩欄位 → 跳過（舊專案相容）
3. 計算 `days_since = today - last_audit_date`
4. 若 `days_since > audit_interval_days`：
   - 走 ADR-0030 通知分級；使用 `💡`（Hint 級；不阻斷）
   - 提示訊息：「距上次 tech-stack audit 已 N 天（閾值 M 天）；建議執行 `node .agents/scripts/tech-stack-manage.mjs audit`」
5. 若已過期但 User 明示「暫不 audit」 → 可請 User 更新 `last_audit_date` 推遲（或 bump `audit_interval_days`）

**狀態管理**：不主動執行；只提示。
````

`rules/lead.md` 新增觸發點（任務派發前自檢）：

- 若 workspace 存在 `last_audit_date` 且已過期 → `@Lead` 於派任務前先通知 User

## 四、預期效益

### 4.1 量化

| 指標                       | 現況                                         | 目標                              |
| -------------------------- | -------------------------------------------- | --------------------------------- |
| 新 Avalonia 專案 init 步驟 | 2 CLI（`install` + `init-workspace`）+ 40 題 | 1 次對話（agent 驅動）+ 3-5 題    |
| Step 6.5 bug               | ❌ 選中不生效                                | ✅ 雙向處理 + 自動推導 TECH_STACK |
| 非互動模式                 | 無                                           | `--config <yaml>`                 |
| tech-stack audit           | ❌ 無機械化                                  | ✅ 每 30 天提醒 + 引用統計初篩    |

### 4.2 質化

- 降低新專案 onboarding 摩擦（從「40 題問答 + 2 CLI」→「3-5 題對話」）
- Catalog 生命週期從「裝 / 移除」升級為「裝 / 審視 / 移除」
- 防止長期累積噪音（定期 audit + 引用統計建議）
- Agent 可主動發起 onboarding / audit（不必 User 記得手動跑）
- 安全前提：刪除永遠需要 User 逐個確認（符合 2026-04-24 User 明確要求）
