## 四、T-2 持久化機制（最深架構漏洞）

### 4.1 ADR-0041 v3 amend（鐵律 2 升級）

**原鐵律 2**：「結果若要持久 → 寫 mempalace drawer 摘要（agent 可提醒 user；非自動）」— **空殼**。

**v3 amend**：

```
鐵律 2（v3）：GitNexus 結果持久化規則：

A. caller list 永不寫死進 drawer body
   - drawer body 只記事件摘要（why / decision / 影響範圍粗估）
   - drawer 加 `regenerate_via: "gitnexus impact <symbol>"` 指針欄位
   - 半年後 user 可重跑 GitNexus 取最新 caller；drawer 始終 fresh

B. 「該寫」判定矩陣（替代原「若要持久」模糊詞）
   - refactor / rename 任務完成 → 強制寫
   - GitNexus impact 顯示 caller >10 + cross-stack → 強制寫
   - debug 找根因（mempalace 過期 + GitNexus 顯示新事實）→ 強制寫
   - 其他場景 → 預設不寫；user 明示才寫

C. 寫入點（單一寫入 agent 避重複）
   - 有 review 場景：@Reviewer Stage 6 完成 review 後寫入
   - debug 場景（無 review）：@Backend Stage 5.5 自評時寫入
   - onboarding：@Architect 完成 PROJECT_CONTEXT 後寫入

D. 衝突仲裁（mempalace ↔ GitNexus 結果不一致）
   - GitNexus 為「當前事實」優先（語法層；可重建）
   - mempalace drawer 觸發 update_drawer：加 `last_verified_at` + `superseded_by_drawer_id`
   - 不刪舊 drawer（保 audit trail）；新 drawer link 舊
```

### 4.2 drawer template 新增（memory-palace-schema §X）

新增 `gitnexus_summary` drawer template：

```yaml
File: <event_topic>
Type: refactor | impact_analysis | debug_root_cause | onboarding_index
Wing: <workspace_id>
Tags: <comma-separated>
Summary: <one-line takeaway; ≤ 80 chars>
---
event_type: refactor | impact | debug | onboarding
symbol: <function or module name>
decision: <what was decided / done>
regenerate_via: "gitnexus impact <symbol>" # ← 不寫死 caller list
last_verified_at: <ISO8601>
related_drawers: [<list of drawer_id>] # 同 wing 相關 drawer
superseded_by_drawer_id: null # update 時填
body: <≤ 200 chars 摘要>
```

新 room：`refactor_log`（既有 architecture / strategy / debug_graveyard 不適切 refactor 事件）。

### 4.3 P-35 patrol（持久化閉環）

```
| P-35 | ROUTING_TICKET archive `runtime_telemetry.gitnexus_used: true` 但 24h 內無對應 mempalace add_drawer | `GITNEXUS_DRAWER_PENDING` | 🟡 | ❌ |
```

→ 解 G-F4「agent 提醒 user 機制無載體」；patrol 自動偵測 + 提醒 + 升級。
