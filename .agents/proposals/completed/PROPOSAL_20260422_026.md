### 3.4 引用完整性策略（Hub-and-Spoke 保證）

- **規則**：rules/*.md → skills/ 或 tasks/（單向引用；避免 rules 之間互相摘要）
- **禁止**：rules 之間新增「跨檔 §id 引用」（如 lead.md §sX → lead-approval.md §sY）
- **現有引用保留**：既有 rules → skills 引用（如 `lead.md §s_state_anchor` → `stateless-routing-pattern.md`）視為黑板協定，繼續使用
- **drift_score 回歸**：執行後必須 `drift_score ≥ 0.90`（baseline 0.957，容許下降 ≤ 0.07；對齐 §十二 Phase E.1 閾值 -0.10 阻斷）

### 3.5 與 User 警示精神的對齊檢核

| User 警示 | 本修訂如何避免 |
|----------|--------------|
| 傳聲筒效應（Telephone Game）| rules 間零跨檔 §id 引用；@Lead 讀 rules 本體 + 直接讀 skills/tasks（黑板節點），無中間摘要 |
| 誤差級聯（Cascading Errors）| 不新增 Agent 實例；@Lead 仍為單一實例，避免多層轉譯 |
| 除錯追蹤困難（Traceability Hell）| rules/ 檔案數不變；新外部化檔案類型歸於既有 skills/tasks 體系，追蹤工具已就位 |
| 多層次發散 | 關注點分離發生於「靜態規則層」而非「Agent 實例層」；不觸發層級化 |
| 自動摘要風險 | rules 不摘要 skills/tasks 內容；@Lead 需要完整細節時直接讀黑板節點原文 |
