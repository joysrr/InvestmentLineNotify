## 一、問題描述

### 根因分類
**類型**：關鍵流程缺乏量化定義（QW-09）

### 問題陳述
`assistant.md` 定義了 @Assistant 的巡邏職責，
但巡邏週期、巡邏觸發條件、
以及巡邏範圍採用定性描述，
缺乏可量化的執行標準。

#### 具體問題條文
```
現況（定性描述）：
「@Assistant 應定時巡邏系統狀態」
「發現異常時向 @Lead 回報」
「確保 PENDING_ACTIONS.md 維持最新狀態」

問題一：「定時」未定義為幾個對話輪次
問題二：「異常」未定義判定標準
問題三：「最新狀態」未定義過期時間門檻
→ @Assistant 的巡邏行為無法被
  @Lead 或 User 客觀驗證，
  且可能出現「已巡邏但未記錄」
  或「長期未巡邏但無人知曉」的情況
```

### 問題影響層級
- 影響範圍：@Assistant 每次執行巡邏判斷
- 風險分類：系統狀態監控可靠性
  （@Assistant 是系統唯一的持續監控機制，
   巡邏週期不明確等同於監控盲區存在）
- 風險等級：🟡 中風險

## 二、根因分析

### 直接根因
`assistant.md` 設計時以「持續存在感知」
為概念描述 @Assistant 的職責，
未將巡邏行為轉化為可執行的量化規範。

### 系統根因
與 PROPOSAL-006（@Retro 週期量化）同根因：
系統缺乏「Agent 週期性任務量化規範」，
@Assistant 巡邏週期與 @Retro 審計週期
均需在本次審計中一併補強。

## 三、提案內容

### 修改項目一：巡邏週期量化

```markdown
// 修改位置：assistant.md 巡邏週期章節

// 修改前
@Assistant 應定時巡邏系統狀態。

// 修改後
## 巡邏週期定義

### 標準巡邏週期
每 3 個工作對話執行一次完整巡邏。
（工作對話定義：包含任務派發或執行的對話，
 純聊天 / 確認對話不計入）

### 即時巡邏觸發條件（任一滿足立即觸發）
條件一：@Lead 明確呼叫「@Assistant 巡邏」
條件二：任何 Agent 回報執行異常
條件三：PENDING_ACTIONS.md 新增 🔴 項目
條件四：對話開始時距上次巡邏已超過 5 個工作對話

### 巡邏跳過條件
以下情況本次對話可跳過標準巡邏：
- 純討論模式對話（無任何執行動作）
- @Lead 明確宣告「本次對話無需巡邏」

跳過時必須記錄：
「本次對話巡邏跳過，原因：{原因}，
 下次巡邏預計於第 {n} 個工作對話執行」
```

### 修改項目二：「異常」判定標準量化

```markdown
// 修改位置：assistant.md 異常判定章節

// 修改前
發現異常時向 @Lead 回報。

// 修改後
## 異常判定標準

以下任一情況判定為「異常」，
必須立即向 @Lead 回報：

### 🔴 高優先級異常（立即回報，不得延遲）
1. PENDING_ACTIONS.md 存在超過 2 個巡邏週期
   未處理的 🔴 項目
2. 任何 Agent 連續 2 次回報執行失敗
3. system-prompt.md 或任何 AlwaysOn 文件
   在非計畫性情況下發生變更
4. PENDING_ACTIONS.md 存在格式錯誤或缺失欄位

### 🟡 中優先級異常（本次巡邏結束前回報）
1. PENDING_ACTIONS.md 存在超過 1 個巡邏週期
   未處理的 🟡 項目
2. 任何 Agent 單次執行逾時（超過預估時間 2 倍）
3. Sprint Ticket 完成率低於 50%
   且距 Sprint 結束不足 1 個週期

### 🟢 低優先級觀察（記錄於巡邏日誌，不主動回報）
1. PENDING_ACTIONS.md 有新增項目但優先級為 P3
2. 任何 Rules 文件距上次修改超過 10 個工作對話
   （提示 @Retro 週期審計可能已到期）
```

### 修改項目三：PENDING_ACTIONS.md 過期定義

```markdown
// 修改位置：assistant.md 狀態維護章節

// 修改前
確保 PENDING_ACTIONS.md 維持最新狀態。

// 修改後
## PENDING_ACTIONS.md 狀態維護標準

### 過期定義
以下情況視為 PENDING_ACTIONS.md 狀態過期：

| 狀態標記 | 過期門檻 | 處理方式 |
|---------|---------|---------|
| 🟡 PENDING | 超過 3 個工作對話未更新 | 升級為 🔴 並回報 @Lead |
| 🔴 BLOCKED | 超過 2 個工作對話未處理 | 立即回報 @Lead（高優異常） |
| ✅ DONE | 超過 5 個工作對話未歸檔 | 提醒 @Lead 執行歸檔清理 |

### 巡邏後必要輸出
每次完整巡邏結束後，
@Assistant 必須輸出巡邏摘要：

```
【@Assistant 巡邏摘要】
巡邏時間：第 {n} 個工作對話
PENDING_ACTIONS 狀態：
  🔴 {n} 項 / 🟡 {n} 項 / ✅ {n} 項
異常發現：{無 / 具體描述}
下次標準巡邏：第 {n+3} 個工作對話
```

禁止：
執行完整巡邏後不輸出巡邏摘要。
巡邏摘要為 @Lead 和 User 驗證巡邏有效性的唯一依據。
```
