## 一、問題描述

### 根因分類

**類型**：負面約束語氣不足（QW-04）

### 問題陳述

`consultant.md` 的「禁止事項」章節使用
「不建議」、「應避免」等軟性語氣表達約束，
與其他 Rules 中「禁止」的強制語氣不一致。

#### 具體問題條文

```
現況（軟性語氣）：
「不建議直接修改 strategyWeight 數值」
「應避免在未通知 @Lead 的情況下自行執行」

問題：
LLM 對「不建議」的遵守強度遠低於「禁止」，
在長程任務或高壓執行情境下，
軟性約束更容易被「效率考量」覆蓋，
導致 @Consultant 跳過 @Lead 直接執行高風險操作。
```

### 問題影響層級

- 影響範圍：@Consultant 每次被呼叫時
- 風險分類：業務安全邊界（strategyWeight 直接修改
  可影響投資策略實際行為）
- 風險等級：🔴 高風險（已在 PROPOSAL-004 全局阻斷
  條件三中列為安全邊界之一）

## 二、根因分析

### 直接根因

`consultant.md` 初版撰寫時採用「建議性」語言風格，
未區分「建議」與「禁止」的語氣強度差異。

### 系統根因

`RULES_DESIGN_GUIDE.md`（PROPOSAL-003）尚未建立，
缺乏跨 Rules 的語氣規範標準，
導致各 Rules 禁止語氣強度不一致。

### 風險連結

此缺口已被 PROPOSAL-004 全局緊急阻斷條件三識別，
但全局阻斷為「最後防線」——
應在 `consultant.md` Rules 層即阻止，
而非依賴系統層兜底。

## 三、提案內容

### 修改項目：禁止語氣升級

```markdown
// 修改位置：consultant.md 禁止事項章節

// 修改前
不建議直接修改 strategyWeight 數值，
應透過 @Lead 審核後由 @Backend 執行。

應避免在未通知 @Lead 的情況下自行執行
任何涉及資料寫入的操作。

// 修改後
【禁止】直接修改 strategyWeight 數值。
strategyWeight 異動必須經由以下流程：
@Consultant 提出建議 → @Lead 審核 → @Backend 執行。
違反此規則視為安全邊界觸碰，觸發全局緊急阻斷。

【禁止】在未取得 @Lead 明確授權的情況下，
執行任何涉及資料寫入的操作。
授權確認方式：@Lead 在本次對話中明確回應「授權執行」。
```

### 修改說明

- 將「不建議」→「【禁止】」
- 將「應避免」→「【禁止】」
- 新增違反後果描述，與 PROPOSAL-004 全局阻斷對齊
- 新增授權確認方式，消除「是否已獲授權」的歧義
- Token 變化：~+30 tokens
