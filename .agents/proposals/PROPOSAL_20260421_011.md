## 一、問題描述

### 根因分類
**類型**：業務脈絡錨定系統性缺失（MT-03）

### 問題陳述
審計發現 6 份 Rules 文件均缺乏
與系統實際業務脈絡的明確錨定，
各 Agent 在執行任務時缺少系統專屬的判斷基準。

#### 缺失清單
```
lead.md：
  缺少系統技術棧描述作為協調任務的判斷依據
  缺少 Telegram Bot / Mini App 業務邊界說明

planner.md：
  Sprint 規劃缺乏系統功能域定義
  無法識別「超出系統範疇」的需求

architect.md：
  技術決策缺乏系統現有架構的錨定描述
  可能提出與現有 File-based 架構不相容的設計

backend.md：
  實作標準缺乏系統技術棧的明確描述
  （Node.js ESM / File-based 已在 PROPOSAL-007
   針對 reviewer.md 補強，backend.md 需同步）

frontend.md：
  Telegram Mini App 的技術限制未明確描述
  缺乏前端邊界定義（什麼屬於 Mini App 範疇）

qa.md：
  測試標準缺乏系統關鍵路徑的覆蓋定義
  缺少「哪些功能是必測項目」的明確清單
```

### 問題影響層級
- 影響範圍：6 份 Rules × 每次被呼叫
- 風險分類：跨 Agent 決策一致性
  （各 Agent 對系統業務的理解不一致，
   可能產生互相衝突的設計或執行決策）
- 風險等級：🟡 中風險（影響範圍廣）

## 二、根因分析

### 直接根因
系統業務脈絡集中描述於 `system-prompt.md`
（AlwaysOn 文件），但各 Agent Rules
未將業務脈絡轉化為角色專屬的執行錨點。

### 系統根因
業務脈絡錨定是「系統整體知識」
→ 「角色專屬行動基準」的轉化工作，
初版 Rules 設計時預設 Agent 能從
system-prompt.md 自動推導，
但 LLM 在多輪任務中的上下文衰減
導致這個假設不可靠。

```markdown
## 現有架構錨點

技術決策必須與以下現有架構相容：

現有架構：
- 執行環境：Node.js ESM（無 CommonJS）
- 資料層：File-based JSON / CSV

- 引入任何資料庫（SQL / NoSQL）
- 引入任何容器化技術（Docker / K8s）
- 新增 Telegram 以外的外部服務依賴
- 將 ESM 改為 CommonJS 或混用
```

### backend.md 補強

```markdown
// 修改位置：backend.md 系統脈絡章節（新增）

## 技術棧執行標準

所有實作必須符合以下技術棧標準：

語言規範：
- 使用 Node.js ESM（import/export）
- 禁止使用 require() / module.exports
- 禁止引入 TypeScript（除非 User 明確授權）

資料存取規範：
- 所有資料讀寫透過 File-based 機制
  （fs.promises、JSON.parse / stringify）
- 禁止引入任何資料庫驅動套件
- 檔案路徑使用相對路徑，禁止硬寫絕對路徑

部署環境限制：
- Oracle VM Free Tier 記憶體限制：
  單次操作避免載入超過 50MB 資料至記憶體
- 禁止使用需要 root 權限的系統呼叫
```

```markdown
// 修改位置：frontend.md 系統脈絡章節（新增）

## Telegram Mini App 技術邊界

所有前端實作必須符合 Telegram Mini App 規範：

技術限制：
- 執行環境：Telegram WebApp（內嵌瀏覽器）
- 入口：透過 Telegram Bot 指令觸發開啟
- 通訊：透過 Telegram WebApp JS SDK
  與 Bot 後端溝通
- 禁止：直接呼叫後端 API（需透過 Bot 中繼）

UI 邊界：
- 主題色彩必須遵循 Telegram 主題變數
  （var(--tg-theme-*)）
- 禁止使用需要額外安裝的原生套件
  （限 Web 標準技術）
- 視窗尺寸：適配 Telegram 內嵌視窗，
  非全螢幕應用

功能範疇（Mini App 負責）：
- strategyWeight 視覺化管理介面
- 投資訊號歷史查詢介面
- 推送設定管理介面
```
