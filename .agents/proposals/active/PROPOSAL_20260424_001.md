# Rule Evolution Proposal: PROPOSAL_20260424_001

## 1. 現狀分析 (Current State)

在本次 `strategyEngine.mjs` 重構中，我們成功將 1500+ 行的單體架構拆分為 **Orchestrator + Policies/Core** 模式。這種模式有效解決了：

- 單一檔案過大、難以維護的問題。
- 邏輯耦合嚴重、單元測試困難的問題。
- 全域變數被意外修改的風險。

## 2. 演進提案 (Proposed Changes)

我們應將此模式正式納入專案開發守則，未來所有複雜的決策或流程引擎均應遵循以下規範：

### 2.1 Orchestrator 職責

- **調度優先**：主引擎應僅包含 `import` 與 `async/await` 調度邏輯，禁止包含具體算分或狀態判定算法。
- **上下文保護**：調用外部模組前，必須對 `ctx` 進行 `Object.freeze` 或淺拷貝保護。
- **防禦性返回**：對外部模組的返回值進行 `if (result) return result;` 的優先權攔截。

### 2.2 目錄規範

- `core/`：存放無副作用、純計算或跨模組共享的狀態機（如維持率狀態機）。
- `policies/`：存放具備業務規則、可插拔的政策邏輯（如進場過濾、再平衡）。
- `index.mjs`：每個子目錄必須提供聚合匯出點。

### 2.3 測試要求

- 每個 `core/` 與 `policies/` 模組必須具備對應的單元測試。
- 引擎端必須具備「決策路徑追蹤 (Decision Trace)」驗證，確保不同輸入組合能正確路由至預期分支。

## 3. 預期效益

- 降低新進開發者的認知負擔。
- 縮短排錯時間（定位具體 Policy 即可）。
- 提升系統在極端市況下的健壯性。
