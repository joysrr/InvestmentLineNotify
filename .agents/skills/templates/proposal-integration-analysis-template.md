# Skill: Proposal Integration Analysis 標準模板

> 本模板由 PROPOSAL_20260422_007 建立，對應 `tasks/proposal-integration-analysis.md`。
> 涵蓋兩個用途：(1) 派遣子 Agent 的提示詞範本、(2) 分析報告輸出格式。

---

## 一、子 Agent 派遣提示詞範本

### 1.1 檔案衝突檢查型（針對被多提案修改的檔案）

```
你是專案的規則衝突審計員。需要深度分析一個關鍵問題：

**檔案**：{檔案路徑}
**涉及提案**：{提案編號列表}

**已知資訊**：
- 檔案當前版本：{version}
- 各提案對本檔案的修改摘要：
{逐提案列出修改點}

**請執行**：
1. 讀取 {檔案路徑} 當前完整內容
2. 讀取相關提案檔的對應變更部分
3. 判斷以下 5 個問題（直接回答 yes/no + 簡短理由）：
 - Q1：章節插入位置是否碰撞？
 - Q2：前提案的改動會被後提案無意覆蓋或破壞嗎？
 - Q3：跨提案的引用鏈是否斷裂（前提案建立的 X，後提案仍引用）？
 - Q4：Token 累積後是否超出檔案類型上限？
 - Q5：各提案的 Priority 屬性是否邏輯一致？

**輸出格式**（繁中、≤ 500 字）：
- 【衝突判定】：高 / 中 / 低，一句話摘要
- 【Q1~Q5 逐題答案】
- 【關鍵風險】：最需要 User 關注的 1~2 點
- 【建議】：若發現問題，建議如何在採納前調整提案內容
```

### 1.2 歷史意圖回退檢查型（掃描 DONE 提案）

```
你是專案的規則衝突審計員。需要快速掃描歷史 DONE 提案，判斷本次 OPEN 提案是否與歷史提案的設計意圖衝突（語意回退）。

**背景**：
{本次 OPEN 提案清單與目標}

**請執行**：
1. 讀取 PROPOSAL_INDEX.md §🔗 提案意圖繼承關係（若存在），確認既有繼承表
2. 讀取以下歷史提案檔頭摘要：
{清單}
3. 逐一判斷本次 OPEN 提案是否會「語意回退」歷史提案的設計意圖

**輸出格式**（繁中、≤ 600 字）：
- 【語意回退判定】：對每份歷史提案標注「無回退 / 部分回退 / 直接回退」
- 【關鍵警示】：1~2 點
- 【建議】：如有回退，如何明文「繼承並擴充」而非「取代」（建議新增至 PROPOSAL_INDEX.md §🔗 意圖繼承表）
```

### 1.3 跨檔案重疊檢查型（針對 design_guide / metadata schema 類變更）

```
你是專案的規則衝突審計員。需要分析多提案對同一設計文件的累積影響：

**檔案**：{設計文件路徑，例 RULES_DESIGN_GUIDE.md / RULES_METADATA_SCHEMA.md}
**涉及提案**：{提案編號列表}

**請執行**：
1. 讀取 {檔案路徑} 當前完整內容
2. 判斷以下 4 個問題：
 - Q1：多提案對同一章節的改動是否邏輯衝突？
 - Q2：新增參數 / 欄位的命名是否有重複或分類錯誤？
 - Q3：版本號遞增順序是否協調（避免跳躍或倒退）？
 - Q4：修改後的規範是否影響其他 rules 的執行依據？

**輸出格式**：同 1.1
```

## 二、分析報告輸出格式

### 2.1 報告標頭

```markdown
# 🔍 N 份 OPEN 提案組合採納 — 整合性分析報告

- **本次採納範圍**：{提案編號列表}
- **分析範圍**：{僅本次採納 / 全 OPEN 池}
- **整體風險等級**：{🔴 高 / 🟡 中 / 🟢 低}
- **分析執行者**：`@Lead` + N 個子 Agent
- **分析日期**：YYYY-MM-DD

## 一句話結論

{一句話摘要是否可直接採納；若不可，主要阻礙為何}
```

### 2.2 風險分類表

```markdown
## 📊 風險彙整

### 🔴 高優風險（阻斷型）

| #   | 風險 | 涉及提案 | 衝擊 | 處理建議 |
| --- | ---- | -------- | ---- | -------- |

### 🟡 中優風險（建議處理）

{同上表格}

### 🟢 低優風險（可接受）

{同上表格}
```

### 2.3 建議處理路徑

```markdown
## 🛠️ 建議處理路徑

### 選項 A：建立新補強提案

- 建議新提案 1：{編號} — {用途}
- 建議新提案 2：{編號} — {用途}

### 選項 B：修訂既有 OPEN 提案

- 提案 X：於 {章節} 加入 {內容}

### 選項 C：混合方案

{結合 A+B 的建議}

### 選項 D：接受風險直接採納（不建議）
```

### 2.4 天然檢查點

```markdown
## 🚦 天然檢查點（需 User 決策）

請從以下選項擇一：

1️⃣ 採取方案 A（建立 N 份新提案）
2️⃣ 採取方案 B（修訂既有提案內容）
3️⃣ 採取方案 C 混合
4️⃣ 暫緩採納，深入特定風險
5️⃣ 接受風險直接採納（不建議）
```
