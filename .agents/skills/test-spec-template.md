# Skill: TEST_SPEC 標準格式模板

> 本模板由 PROPOSAL-001 從 `qa.md` 外部化而來。
> `@QA` 在 Workflow 第 4 步（工程驗證測試階段）依本格式產出 `TEST_SPEC_<功能名稱>.md`。

---

## 標準格式

```markdown
# Test Specification

**功能名稱**：<功能簡稱>
**對應草案版本**：draft v<N>
**建立日期**：<日期>
**建立者**：`@QA`

## 測試案例清單

| # | 測試案例描述 | 前置條件 | 輸入 | 預期結果 | 執行者 | 優先級 |
|---|------------|---------|------|---------|--------|--------|
| TC-01 | <正常路徑描述> | <前置條件> | <輸入值> | <預期輸出> | `@Backend` / `@QA` | 🔴/🟡/🟢 |
| TC-02 | <邊界值描述> | <前置條件> | <極端值> | <預期處理方式> | `@QA` | 🔴 |
| TC-03 | <異常路徑描述> | <前置條件> | <異常輸入> | <錯誤處理結果> | `@QA` | 🔴 |

## 不在本次測試範圍內
- <明確說明哪些情境本次不驗證>
```

---

## 欄位說明

| 欄位 | 說明 |
|---|---|
| TC-## | 測試案例編號，`TC-` 前綴 + 兩位數序號 |
| 測試案例描述 | 一句話說明此 TC 驗證什麼 |
| 前置條件 | 執行 TC 前須建立的系統狀態或 Mock 資料 |
| 輸入 | 具體的輸入值或事件觸發條件 |
| 預期結果 | 客觀可驗證的輸出（非「應該正確」等主觀描述）|
| 執行者 | `@Backend` / `@Frontend` 自我覆蓋 或 `@QA` 負責執行 |
| 優先級 | 🔴 必測 / 🟡 重要 / 🟢 可選 |

---

## 撰寫守則

- 每個驗收標準（AC）至少轉化為一個 TC
- 執行者分工依 `qa.md` §「測試責任範圍」判斷
- 不在本次測試範圍內的項目必須明列，避免後續爭議
