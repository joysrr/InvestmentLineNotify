# Skill: @Architect 動態範疇機制（S / M / L）

`@Architect` 接收設計任務後，**開始設計前必先執行範疇評估**，依任務規模選擇對應設計深度。避免小任務過度設計、大任務設計不足。

## 任務規模分級

| 規模          | 判定條件（滿足任一）                                                                                              | 設計深度 |
| ------------- | ----------------------------------------------------------------------------------------------------------------- | -------- |
| **S（小型）** | 僅涉及單一函式或單一 API 端點修改；不新增模組或跨模組依賴；預估 `@Backend` 實作時間 ≤ 30 分鐘                     | 輕量設計 |
| **M（中型）** | 涉及單一功能模組新增或重構；新增 1~2 個 API 端點；涉及 1~2 個現有模組的介面調整                                   | 標準設計 |
| **L（大型）** | 涉及跨模組整合（≥ 3 個模組）；新增 ≥ 3 個 API 端點；引入新的系統層級資料結構；或觸發 §「HITL 升級條件」複雜度門檻 | 完整設計 |

> **HITL 門檻分層**：L 規模判定採較寬條件（API 端點 ≥ 3）；HITL 升級門檻採較嚴條件（API 端點 ≥ 5）。即 L 規模完整設計可在 `@Lead` 自主範圍內執行，再跨越 HITL 門檻時才升級。

## 各規模設計深度

### S 輕量設計

**適用**：單一函式 / 單一端點的小幅修改

**必要產出**（DoD 精簡版）：

- [ ] 修改說明（1~3 句話描述變更內容）
- [ ] 輸入 / 輸出格式定義（如有變更）
- [ ] 影響範圍確認（確認無跨模組影響）

**不需要**：完整技術規格文件、架構圖、效能評估

**回報格式**（對齊 ADR-0030 通知分級）：

```
【@Architect 輕量設計】✅ <一句話摘要>
規模評估：S
修改說明：<1~3 句話>
影響範圍：<無跨模組影響 / 具體說明>
```

### M 標準設計

**適用**：單一功能模組的新增或重構

**必要產出**：

- [ ] 功能需求摘要（來自 `@Planner` Ticket）
- [ ] 技術選型說明（為何選擇此實作方式）
- [ ] API / 函式介面定義（端點路徑 / 參數 / 回傳格式）
- [ ] 資料結構定義（如有新增或變更）
- [ ] 錯誤處理策略
- [ ] 影響模組清單

**不需要**：完整系統架構圖（非架構性變更）、效能壓測規格

**回報格式**：

```
【@Architect 標準設計】✅ <一句話摘要>
規模評估：M
功能模組：<模組名稱>
介面定義：<API / 函式清單>
資料結構：<新增 / 變更說明或「無」>
影響模組：<列表>
```

### L 完整設計

**適用**：跨模組整合或系統層級變更

**必要產出**（完整 DoD）：

- [ ] 功能需求完整描述
- [ ] 架構決策說明（含替代方案比較）
- [ ] 完整 API 規格（依 `skills/templates/api-spec-template.md`）
- [ ] 資料結構與 Schema 定義
- [ ] 模組依賴關係圖（文字描述或 ASCII 圖）
- [ ] 錯誤處理與降級策略
- [ ] 效能考量（受限環境下的可行性）
- [ ] 實作拆分建議（可拆為幾個 Sprint Ticket，交接 `@Planner`）

**回報格式**（規模大可能觸發 🟡 需 User 確認）：

```
【@Architect 完整設計】✅ / 🟡 <一句話摘要>
規模評估：L
架構決策：<核心決策摘要>
API 規格：<端點數量> 個端點（詳見規格文件）
實作拆分：建議拆為 <n> 個 Ticket
需 User 確認：<是 / 否，原因>
```

## 範疇升級機制

設計過程中發現實際規模超過初始評估時 → 必執行升級。

**觸發條件（任一）**：

1. 原評估為 S，但發現有跨模組影響
2. 原評估為 M，但發現需要架構性決策
3. 任何規模下，發現觸發 §「HITL 升級條件」門檻

**升級動作**：

1. **暫停**當前設計
2. 向 `@Lead` 輸出範疇升級通知（對齊 ADR-0030）：
   ```
   【@Architect 範疇升級通知】🟡 WARNING：範疇變更
   原評估規模：<S / M>
   實際規模：<M / L>
   升級原因：<具體描述>
   建議處理：<繼續完整設計 / 拆分任務>
   ```
3. 等待 `@Lead` 確認後繼續

## 範疇判定輸出要求

每次接收任務後，**開始設計前**向 `@Lead` 輸出範疇評估：

```
【@Architect 範疇評估】<級別符號>
任務：<任務描述>
規模判定：S / M / L
判定依據：<觸發的判定條件>
設計深度：輕量 / 標準 / 完整
預估產出：<必要產出清單>
```

## 禁止行為（保留於 rule）

- **絕對禁止** 跳過範疇評估直接輸出設計結果
- **絕對禁止** 為「簡化工作量」故意低估範疇（L 判為 M）
- **絕對禁止** 發現範疇需升級後仍沿用原設計深度
