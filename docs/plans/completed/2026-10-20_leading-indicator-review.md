### 3.2 回到原始目的

本計畫的主要目的不是建立完整量化交易系統，也不是預測每日漲跌，而是：

1. 在重大風險真正擴大前，提早發現異常。
2. 讓 0050 與 00675L 的處理不混為一談。
3. 維持 P0 定期定額，不因警報造成情緒性停扣。
4. 警報失效或資料不足時寧可靜默，不用假資料製造信號。

因此，後續範圍採「最小有效風控」原則：只有能改善提早發現、避免誤用 00675L、或避免資料不足誤報的項目，才列入近期開發。

### 3.3 建議保留、延後與不納入

#### A. 建議近期保留

- **00675L 明確凍結規則**：重大衝擊或極度恐慌時禁止新增部位；既有 Triple-Gate 保留並補齊必要輸入的資料狀態。
- **雷達 1 的滾動門檻**：保留 ShockScore + z-score + P95，因為它直接服務「隔夜提早發現」。
- **雷達 2 的資料可靠性與降級**：先確認維持率資料是否穩定；資料不可用時標示不可判讀，不以 0 或舊資料代替。
- **雷達 3 的資訊性波動警示**：若能用既有資料計算，加入簡單的高波動提示；不先擴張成複雜交易模型。
- **現有全域狀態機的明確輸出**：保留目前狀態機，先把警報文字與 P0/P1/00675L 行動說清楚，不立即拆成三套狀態機。

#### B. 建議延後，只有在實際使用證明需要時才做

- 十年歷史回測與假陽性率統計：適合用來校準門檻，但不是提早接入警報的必要前置條件；可在警報累積足夠實例後進行。
- 每個雷達獨立狀態機：目前全域狀態機已能表達主要防禦狀態，拆分會增加持久化與 UI 複雜度。
- 完整三批加碼排程：系統只提供提醒，不自動下單；在沒有明確使用需求前不增加排程與批次狀態。

#### C. 暫不納入本計畫

- 每日方向預測。
- 以回測結果自動調參或自動交易。
- 為了形式完整而加入 FGI、額外資料源或複雜模型，但沒有穩定資料鏈。
- 把 P0 固定 DCA 改成由雷達決定是否執行。

### 3.5 `L_max` 與動態槓桿研究說明

#### `L_max` 是什麼

本文件中的 `L_max` 原意是「00675L 市值占投資組合總市值的硬上限」，例如：

```text
L_current = 00675L 市值 / 投資組合總市值
禁止加碼條件：L_current >= L_max
再平衡提示：L_current >= 1.1 × L_max
```

它是**風險護欄**，不是根據市場訊號推導出的「最佳持倉比例」。例如設定 `L_max = 30%`，只代表即使市場很恐慌，也不允許 00675L 佔比超過 30%；它沒有回答「今天應該買多少」。

另外，現有 `RebalanceRule` 已使用策略設定的 `z2RatioHigh` 與 `z2TargetRatio`。這是既有再平衡規則；未來若研究 `L_max`，必須先決定它與既有規則的優先順序，不能平行產生互相矛盾的賣出建議。

#### 「依市場指標決定槓桿」的理論

這類方法通常不是預測漲跌，而是**波動率目標（volatility targeting）**或**風險平價（risk budgeting）**：

1. 估計大盤或投資組合的近期年化波動率 `σ_current`。
2. 設定可接受的目標波動率 `σ_target`。
3. 以近似公式計算總曝險：

```text
target gross exposure ≈ σ_target / σ_current
```

例如目標波動率 15%，近期估計波動率 30%，總曝險約為 `0.15 / 0.30 = 0.5x`；若近期波動率降到 10%，公式會得到 1.5x。但這只是風險估計模型，不是保證報酬的最佳槓桿。

如果使用 2 倍每日重設 ETF，還要把 ETF 的槓桿倍數與波動率耗損納入：

```text
ETF notional exposure ≈ 2 × 00675L 市值
```

因此，不能只看 00675L 市值占比。還要區分：

- **市值占比**：00675L 市值 / 投資組合市值
- **方向曝險**：00675L 市值 × 約 2 / 投資組合淨資產
- **個人資產負債維持率**：總資產 / 總負債
- **波動率與路徑風險**：近期實現波動率、跳空與震盪造成的耗損

#### 為什麼不能直接把公式接進目前系統

動態槓桿至少需要先定義：

- 使用哪個波動率：0050、加權指數、SOX，或整體投資組合。
- 估計窗口：20、60 或 120 個交易日。
- 年化方式與資料品質門檻。
- 目標波動率與最大總曝險。
- 00675L 的實際曝險倍率是否固定視為 2 倍。
- 波動率突然上升時，是立即降曝險、分段降曝險，還是只發提醒。
- 如何處理槓桿 ETF 的每日重設、交易成本、滑價與波動率耗損。

若沒有先固定這些定義，系統算出的「最適槓桿」只是對參數敏感的數字，容易製造虛假的精準感。

#### 是否適合套用在本系統

**可以研究，但目前不應直接作為自動下單或自動調整槓桿的規則。** 比較適合分三層：

- 第一層：只做資訊提示，例如「近期波動率升高，00675L 不利，禁止新增」。
- 第二層：做安全上限檢查，例如現有 00675L 方向曝險是否超過事先核定的硬上限。
- 第三層：經過歷史資料、交易成本與個人資產負債壓力測試後，才討論動態曝險建議。

因此本計畫目前採用第一層，`L_max` 與動態槓桿公式列為後續研究，不列入本階段實作。

## 四、P1 必須調整項目

### 4.1 P1-1：00675L（2 倍槓桿 ETF）的特殊處理完全缺失

#### 問題描述

這是整份計畫最大的盲點。00675L 為**每日重設**的 2 倍槓桿 ETF，具有兩個 0050 完全不具備的風險特性：

1. **波動率耗損（Volatility Decay）**：
   - 在震盪盤（大漲大跌交替）中，即使標的指數最終回到原點，2 倍槓桿 ETF 仍會虧損。
   - 耗損近似與「已實現波動率的平方」成正比，波動越大耗損越快。
   - 極端事件期間（VIX 飆升、連續跳空）正是耗損最嚴重的環境。

2. **路徑依賴（Path Dependency）**：
   - 報酬順序會改變最終結果，無法用「標的指數漲 X% 則 00675L 漲 2X%」的靜態思維決策。
   - 連續下跌後的底部反彈，00675L 的恢復速度遠慢於 0050。

#### 為何這是嚴重問題

原計畫三個雷達的輸出範例中，行動建議多為「P1 增貸加碼」「左側分批布局 0050 / 00675L」，但：

- 雷達 1（美股重挫 -3.4%）觸發時，正是波動率跳升的起點。此時加碼 00675L，等於在**耗損加速的環境中放大曝險**。
- 雷達 3（極度恐慌）觸發時，若在恐慌高峰當下布局 00675L，可能面臨「指數三個月後回本、00675L 仍虧損」的結果。
- 原計畫對 0050 與 00675L 使用同一套行動建議，等於**用最危險的工具，在最危險的時刻加碼**。

#### 建議規格

**（A）`L_max` 與動態合理槓桿：本階段不直接啟用**

PTT 討論的 Kelly／半 Kelly／估值動態槓桿模型可作為後續研究方向，但不能直接把歷史平均報酬、固定波動率與 `3.15x` 結果套入 00675L。原因是：

- Kelly 的輸入是未來可代表性的報酬、成本與波動率；歷史平均值不等於未來期望值。
- 00675L 是每日重設 ETF，需另行估計複利偏離、再平衡滑移與波動率耗損。
- `L_max` 若以市值占比表示，與實際方向曝險、借款維持率不是同一件事。
- 場外借款、期貨與 LETF 的風險來源不同，不能用同一個半 Kelly 倍數處理。

本階段只保留安全閘門：重大雷達警報時禁止新增 00675L；不產生「目前應該開幾倍槓桿」或自動減碼建議。

未來研究介面暫定為：

```text
L_current = 00675L 方向曝險 / 投資組合淨資產
L_kelly = f(預期超額報酬、融資與產品成本、波動率、估值位階、路徑耗損)
L_recommended = min(0.5 × L_kelly, 個人核定上限, 維持率安全上限)
```

其中 `0.5 × L_kelly` 只是半 Kelly 的保守縮放，不是安全保證；`L_kelly` 也必須先把 00675L 的產品層成本與路徑風險納入，不能直接套用標的指數的靜態 Kelly 值。

只有完成逐期資料回測、成本拆解、壓力測試與 Han 確認採用「提醒」或「減碼建議」後，才可把 `L_kelly` 接入系統。

**（B）雷達 1 觸發時的差異化規則**

| 標的   | 行動                                                 |
| ------ | ---------------------------------------------------- |
| 0050   | P0 定期定額照常；P1 當日暫緩進場                     |
| 00675L | **當日禁止加碼**；若已持有，不做任何動作（不加不減） |

理由：雷達 1 觸發代表波動率制度可能切換，需觀察 1~3 日確認是否進入高波動 regime。

**（C）雷達 3 觸發時的差異化規則**

00675L 加碼需通過**三道前置條件**（全部滿足才啟動第一批）：

1. `VIX_t ≤ 0.8 × max(VIX, 近 20 交易日)` —— 恐慌已從高點回落至少 20%
2. `近 5 日 VIX 移動平均 < 近 20 日 VIX 移動平均` —— 波動率趨勢向下
3. `近 20 日年化已實現波動率 < 40%` —— 避免在超高波動環境進場

若條件未滿足：**僅允許 0050 分批布局**，00675L 維持不動。

**（D）波動率耗損預警**

當 `近 20 日年化已實現波動率 > 35%` 時，於報告中顯示一行提示：

> ⚠️ 當前波動率環境對 00675L 不利（年化波動 XX%），槓桿耗損加速中。

此提示為**資訊性**，不觸發行動，但作為心理錨定。

**（E）文件層級要求**

原計畫所有雷達輸出範例，必須改寫為 0050 / 00675L 雙軌表述。禁止出現未區分標的的「加碼」字樣。

### 4.2 P1-2：固定閾值 vs 滾動分位數——門檻校準方法有缺陷

#### 問題描述

目前所有門檻均為固定絕對值：

| 雷達   | 現行門檻           | 問題                                                 |
| ------ | ------------------ | ---------------------------------------------------- |
| 雷達 1 |                    | SOX                                                  | ≥ 2.0%、 | TSM ADR | ≥ 2.5% | 2017 年 ±2% 是罕見大事；2020/2024 年幾乎每週出現，觸發頻率差 10 倍以上 |
| 雷達 2 | 融資單日減 ≥ 35 億 | 台股市值與融資餘額逐年變化，絕對金額門檻會隨時間失效 |
| 雷達 3 | VIX ≥ 28、FGI ≤ 20 | VIX 的「高位」定義隨長期波動率中樞漂移               |

**後果：**

- 低波動年代：門檻過嚴 → 該亮不亮（漏報）
- 高波動年代：門檻過鬆 → 不該亮狂亮（警報疲勞，侵蝕信任）

對 20~30 年系統而言，這是**必然會發生**的問題，不是可能。

#### 建議規格

**（A）統一改用「雙條件」：絕對下限 + 相對分位數**

單用分位數可能在高波動期觸發過頻，單用絕對值則無法適應制度切換。建議兩者並用（AND）：

**雷達 1（美股隔夜衝擊）**

```
z_SOX = (r_SOX,t - μ_60) / σ_60
觸發條件：
  |z_SOX| ≥ 2.0
  且 |r_SOX,t| ≥ P95(|r_SOX|, 近 250 交易日)
```

其中 μ_60、σ_60 為近 60 交易日報酬均值與標準差。

**雷達 2（籌碼出清）**

```
d_margin = ΔMargin_t / Margin_{t-1}
維持率條件：M_t < P10(M, 近 250 交易日)  或  M_t < 138%
觸發條件：
  d_margin ≤ -1.5%
  且 (M_t < 138% 或 M_t < P10_250)
```

以比例取代絕對金額，可自動適應融資餘額的長期變化。

**雷達 3（極度恐慌）**

```
觸發條件：
  VIX_t ≥ max(28.0, P95(VIX, 近 750 交易日))
  且 FGI_t ≤ 20
```

750 交易日約三年，涵蓋一次完整波動週期，避免用過短的 250 日低估「極端」水位。

**（B）上線前必須回測觸發頻率**

每個雷達需回測至少 10 年歷史，記錄：

| 檢核項           | 合格標準                                    |
| ---------------- | ------------------------------------------- |
| 總觸發次數       | ≥ 15 次（確保統計有效性）                   |
| 年均觸發次數     | 1~3 次（避免疲勞或沉睡）                    |
| 假陽性率         | 定義為觸發後 5 日內無明顯方向者；建議 < 50% |
| 最大連續觸發天數 | 需定義上限，超過則進入冷卻                  |

若某雷達回測年均觸發 > 5 次，視為門檻過鬆，需上調。

**（C）參數版本化**

所有門檻參數寫入設定檔並標註版本與生效日，例如：

```yaml
radar1:
  z_threshold: 2.0
  lookback_mu_sigma: 60
  lookback_percentile: 250
  percentile: 95
  version: v1.0
  effective_from: 2026-11-01
```

避免日後修改參數時無法追溯。

### 4.3 P1-3：雷達觸發後的「行動框架」過於模糊，缺乏可執行紀律

#### 問題描述

現行輸出範例多為定性描述：

- 「暫緩於開盤進場」——暫緩一天？等什麼訊號恢復？
- 「進入優先審查狀態」——審查什麼？誰審查？
- 「左側分批布局」——幾批？間隔多久？每批比例？

**對長期投資人而言，模糊建議比沒有建議更危險**，因為它留給情緒解釋的空間。當市場恐慌時，人會把「暫緩」解讀成「再等等」，把「分批」解讀成「All in 第一批」。

#### 建議規格：三狀態機

每個雷達定義獨立狀態機，狀態為：`IDLE`（靜默）、`TRIGGERED`（觸發）、`COOLDOWN`（冷卻）。

```
IDLE --(觸發條件成立)--> TRIGGERED
TRIGGERED --(連續 N 日未再觸發)--> COOLDOWN
COOLDOWN --(冷卻期滿 M 日)--> IDLE
TRIGGERED --(冷卻期內再次觸發)--> TRIGGERED（升級為連續觸發）
```

**雷達 1 狀態機（美股隔夜衝擊）**

| 狀態                     | 報告行為                   | P1 行動                        |
| ------------------------ | -------------------------- | ------------------------------ |
| IDLE                     | 不出現                     | 正常紀律                       |
| TRIGGERED（第 1 日）     | 顯示雷達卡                 | 0050 當日暫緩；00675L 禁止加碼 |
| TRIGGERED（連續第 2 日） | 顯示「連續衝擊」標記       | P1 全面暫停，直至回到 IDLE     |
| COOLDOWN（3 交易日）     | 顯示灰色小字「波動觀察中」 | 0050 可恢復，00675L 仍暫緩     |
| IDLE                     | 不出現                     | 全部恢復                       |

**恢復條件（TRIGGERED → COOLDOWN）**：

- 隔日 |SOX| < 1.0% 且 |TSM ADR| < 1.25%（門檻的一半）
- 或台指期夜盤收盤漲跌幅絕對值 < 0.8%

**雷達 2 狀態機（籌碼出清）**

| 狀態                 | 報告行為           | P1 行動                           |
| -------------------- | ------------------ | --------------------------------- |
| IDLE                 | 不出現             | 正常紀律                          |
| TRIGGERED            | 顯示雷達卡         | 進入「加碼預案審查」，不自動執行  |
| COOLDOWN（5 交易日） | 顯示「籌碼觀察中」 | 可執行第一批（若 Han 已預先授權） |

**雷達 3 狀態機（極度恐慌）**

| 狀態                  | 報告行為           | P1 行動（0050）                                      | P1 行動（00675L）                  |
| --------------------- | ------------------ | ---------------------------------------------------- | ---------------------------------- |
| IDLE                  | 不出現             | 正常                                                 | 正常                               |
| TRIGGERED             | 顯示雷達卡         | 啟動三批預案，每批間隔 5 交易日，每批 ≤ 預備現金 1/3 | 禁止，直至三道前置條件滿足         |
| COOLDOWN（10 交易日） | 顯示「恐慌觀察中」 | 第二批需 VIX 未再創高                                | 條件滿足後可啟動第一批（上限減半） |

**「三批預案」的明確參數（建議由 Han 核定）**

```
批次數：3
間隔：5 個交易日
每批金額：預備加碼現金 × 1/3
第二批前置：VIX_t < VIX_觸發日高點
第三批前置：VIX_t < 0.7 × VIX_觸發日高點
中止條件：若期間出現單日大盤跌幅 > 5%，暫停後續批次並重新評估
```

## 五、P2 建議補強項目

### 4.1 P2-1：雷達 1 的共線性問題與夜盤確認

#### 問題

台積電為費半最大權重成分股之一，SOX 與 TSM ADR 日報酬相關係數長期在 0.8 以上。使用「SOX ≥ 2% 或 TSM ADR ≥ 2.5%」會導致同一事件重複觸發，且無理論依據。

#### 建議

**（A）改用單一衝擊分數**
`ShockScore = 0.5 × z_SOX + 0.5 × z_TSM`，觸發門檻 `|ShockScore| ≥ 2.0`。

**（B）加入台指期夜盤作為最終確認**
夜盤已完整消化美股資訊：

- 夜盤漲跌幅絕對值 ≥ 1.0% → 確認訊號，標記「夜盤已反映」
- 夜盤與美股方向背離 → 標記「背離，衝擊可能鈍化」，下調強度

---

### 4.2 P2-2：缺少假陽性事後追蹤與門檻再校準機制

每次觸發記錄 JSON Lines 日誌，事後 20 日自動回填走勢分類（`effective` / `false_positive` / `ambiguous`）。季度假陽性率 > 50% 則進入門檻校準審查。

---

### 4.3 P2-3：資料源失效的降級處理未定義

核心原則：**漏報遠優於誤報**。

- 單一資料源延遲 > 1 交易日 → 該雷達靜默，顯示灰色小字提示。
- 異常值需人工確認。
- 禁止使用前日舊資料或線性外推代替當日觸發。

---

### 4.4 P2-4：雷達 2 的資料可得性需先驗證

大盤融資維持率是否有穩定每日更新的公開資料來源？上線前需確認來源穩定性與更新時效；若延遲嚴重，降級為單純融資變化率百分比。
