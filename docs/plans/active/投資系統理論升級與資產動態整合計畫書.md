## 1. 專案背景與核心原則

### 1.1 升級背景

本系統現有架構具備完善的風控閘門。為了讓系統從「被動防備極端風險」升級為「具備數學底氣的動態決策模型」，本計畫導入四大量化金融理論：**凱莉公式 (Kelly Criterion)**、**拉普拉斯肥尾效應 (Laplace Risk)**、**生命週期投資理論 (Lifecycle Investing)** 以及 **托賓分離定理 (Tobin's Separation)**。

### 1.2 三大開發原則（絕對底線）

1. **不破壞現有防護網（硬性閘門維持原樣）：**
   - 維持率狀態機：`marginCallThreshold=135%`, `frozenZone=145%`, `protectTrigger=160%`, `protectTarget=180%`
   - 曝險與配置：`z2TargetRatio=0.40`, `z2RatioHigh=45`；這是配置／再平衡參數，不是 Kelly 結果
   - 槓桿天花板：`ceiling=2.5x`, `hardCap=3.0x`, `recoveryTarget=2.0x`
2. **理論計算層 (Theoretical Layer) 獨立化：** 新增獨立計算模組，輸出結果僅用於 shadow report／唯讀 UI；不得覆蓋既有決策或作為自動交易依據。
3. **回測工具先盤點再處置：** `runMacroCompare.mjs` 仍存在，但其引用的 `src/modules/backtest/backtestMacroSentimentCompare.mjs` 在目前 checkout 找不到；先查明依賴與使用者，再決定修復、封存或移除，不直接刪除。

## 2. 實際資產與理論公式之動態綁定架構

系統在取得已驗證的行情與帳戶快照後，將持倉、帳戶淨值、借款與維持率映射至理論輸入契約。若只有持倉與借款，不得把推算值冒充券商實際維持率。

```text
[使用者真實庫存輸入]
  ├── 0050 持有股數 (qty_0050)
  ├── 00675L 持有股數 (qty_00675L)
  └── 總負債金額 (total_debt)
       │
       ▼ (結合 API 即時股價 p_0050, p_00675L)
┌────────────────────────────────────────────────────────┐
│ 基礎資產動態算式                                         │
│ 1. 0050 市值 V_0050 = qty_0050 × p_0050                 │
│ 2. 00675L 市值 V_00675L = qty_00675L × p_00675L         │
│ 3. 財務資本 FC = 優先使用帳戶／持倉快照的 accountNetAsset │
│ 4. 總方向曝險 E_gross = V_0050 + (V_00675L × 2)          │
│ 5. 當前總槓桿 L_current = E_gross / FC                  │
│ 6. 估算維持率 = collateralValue / total_debt             │
│    *註: 不得冒充券商 maintenanceMargin；無借款回傳 NO_DEBT│
└────────────────────────────────────────────────────────┘
       │
       ▼ (代入理論計算模組)
┌────────────────────────────────────────────────────────┐
│ 理論計算層 (Theoretical Layer)                          │
│ 1. 凱莉極限 (Kelly)    : 比對 L_current 與 L_max         │
│ 2. 生命週期 (Lifecycle) : 真實人生曝險 E_gross / (FC + HC)│
│ 3. 拉普拉斯 (Laplace)   : 倒推大盤容忍跌幅 1 - (160% / M%) │
└────────────────────────────────────────────────────────┘
```

## 3. 四大理論核心公式與參數設定

### 3.1 凱莉公式（槓桿幾何成長天花板）

- **參數來源：** `mu`、`sigma`、實際借款利率與產品成本必須由研究輸入契約提供；本計畫不把 12%／20% 寫死成正式預設值。
- **研究公式：** `L* = (mu - borrowRate - productCostAdjustment) / sigma²`
- **保守縮放：** `L_half = protectiveScale × L*`
- `L*` 與 `L_half` 只作 shadow research value，不是安全保證、正式上限或自動交易指令。若 `mu`／`sigma`／產品成本缺失，輸出 `UNAVAILABLE`／`UNMODELED`。

### 3.2 生命週期投資理論（以實際年齡設定為基準）

- **目前設定：** 使用者已確認實際年齡為 33 歲，因此正式設定 `currentAge = 33`；`retirementAge = 65`，距離退休 32 年。`monthlyDcaAmount = 30,000` 僅可推導年度 DCA 360,000 元。
- **年齡更新行為：** 目前正式設定沒有 `birthYear`／`birthDate`；生命週期引擎只計算 `retirementAge - currentAge`，不會依日期自動增加年齡。若未取得生日與時區／基準日規則，禁止自行推算。
- **重要限制：** DCA 金額不是薪資，也不是人力資本。若未取得稅後收入、可投入現金流、成長率與折現率，不計算 HC。
- **人力資本公式:** `HC = Σ(investableCashFlow_t / (1 + discountRate)^t)`
- **人生真實總曝險比例:** `TrueExposure = GrossExposure / (FinancialCapital + HC)`

### 3.3 拉普拉斯模型（維持率倒推崩盤容忍度）

利用當前質押維持率 ($M$)，倒推大盤暴跌多少 $\%$ 會觸發系統的保護機制：

- **防禦觸發容忍跌幅：** $\text{Crash Tolerance}_{\text{Protect}} = 1 - \left(\frac{160\%}{M}\right)$
- **斷頭危機容忍跌幅：** $\text{Crash Tolerance}_{\text{MarginCall}} = 1 - \left(\frac{135\%}{M}\right)$

### 3.4 托賓分離與 00675L 產品層風險

目前系統把 00675L 乘以 2 只作方向曝險近似；這不是長期報酬模型。不能在沒有實際追蹤差異、費用、再平衡滑移與波動耗損資料時，宣稱逆價差會抵銷產品成本。

因此本計畫只保留「核心資產與槓桿工具分層」的配置概念；產品成本先標示 `UNMODELED`，後續以資料與回放驗證。

## 6. 影子觀測模式 (Shadow Mode) 執行機制

1. **部署原則：** 理論層計算結果只寫入 shadow report／log；即使研究值低於目前曝險，也**不覆蓋既有決策**。只有現有硬性維持率、Gross Leverage 與 00675L 凍結規則可以阻擋操作。
2. **記錄格式範例：**
   ```json
   {
     "timestamp": "2026-10-23T08:30:00Z",
     "actual_decision": "ALLOW_DCA_0050_AND_00675L",
     "current_gross_leverage": 1.42,
     "shadow_mode_theory": {
       "recommended_leverage": null,
       "kelly_max": null,
       "data_status": "RESEARCH_ONLY",
       "reason": "Example only: values require verified inputs; no fixed leverage is implied."
     }
   }
   ```

## 9. 最終裁決

本計畫採以下順序：

```text
資料契約與依賴盤點
→ TDD 純理論計算層
→ 現有資料接線
→ shadow report
→ 固定壓力劇本／回放
→ 只讀 UI（可選）
→ 研究證據充分後，才討論提醒或新增限制
```

成功標準不是得到一個看似精確的固定槓桿數字，而是能回答：

- 這個數字用了哪個來源與期間？
- 缺資料時是否安全失效？
- 它與現有維持率／Gross Leverage 哪個優先？
- 它是否改變 P0 DCA？答案必須是否定的。
- 在 00675L 的每日重設與路徑風險下，這個數字是否仍只是研究值？

在上述證據完成前，Kelly、Laplace、Lifecycle 與 Tobin 分離相關內容只作為研究層與壓力測試框架，不得變成正式自動交易規則。
