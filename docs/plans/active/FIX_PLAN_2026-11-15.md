# 文檔與代碼一致性修復計劃

## 給開發者的話

這份計劃基於機器驗收工具 `scripts/verify-doc-code-sync.mjs` 的實測輸出，不是憑感覺列的。每個階段都有驗收命令，你跑完把輸出貼回給我判定。

**核心規則**：
1. 每階段獨立提交，不跳階段、不合併
2. 只改計劃列的檔案，其他不動
3. 回報必附驗收輸出全文，不接受「已完成」這種空話
4. 不確定就問，不要猜
5. 驗收工具只讀不改

**基線（2026-11-15 實測）**：

```
OpenAPI paths: 36 | operations: 40 | 代碼 routes: 28
[FAIL] OpenAPI → 代碼：18 個端點文檔有但代碼無
```
